## 1. 문제 정의 (Problem)
서비스가 성장하며 사용자의 유입 경로와 시스템 안정성을 확인해야 할 필요성이 커졌습니다. 초기에는 Google Analytics와 같은 외부 분석 툴 도입을 고려했으나, 두 가지 큰 걸림돌이 있었습니다.

1.  **개인정보 보호 및 규제 대응:** 서비스의 핵심 가치가 '보안'인 만큼, 외부 업체에 사용자의 로그 데이터를 위탁하는 과정에서 발생할 수 있는 프라이버시 리스크를 최소화해야 했습니다.
2.  **PWA 환경 최적화:** 오프라인 사용이 가능한 PWA(Progressive Web App) 환경에서 외부 스크립트 의존성을 높이는 것은 로딩 성능과 네트워크 신뢰성 측면에서 부정적인 영향을 줄 수 있었습니다.

결국 **"개인정보를 보호하면서도 가볍고, 서비스 환경에 최적화된 내부 로깅 아키텍처"**를 직접 설계하기로 결정했습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off)

### 1) 데이터 수집 방식: 미들웨어 vs 로깅 라이브러리
초기엔 비동기 로깅 라이브러리를 고민했으나, FastAPI의 미들웨어(Middleware) 체인을 활용하는 방식을 최종 선택했습니다.
*   **장점:** 요청 단계에서 즉시 메타데이터(IP, User-Agent, Path 등)를 가로챌 수 있어 구현이 일관적입니다. 또한, 정적 리소스(CSS/JS)는 제외하고 핵심 API 요청만 선별적으로 추적함으로써 DB 부하를 제어할 수 있습니다.

### 2) 개인정보 보호: IP 마스킹 (Hashing)
IP 주소를 원문 그대로 저장하는 것은 보안상 취약합니다. 이를 해결하기 위해 **단방향 해시(SHA-256 계열)**를 도입했습니다.
*   **의사결정:** IP 주소를 그대로 저장하는 대신 해시값을 저장함으로써, 특정 개인의 IP를 추적할 수는 없지만, 동일한 IP 대역에서 방문했는지 여부를 파악하는 '고유 방문자 식별(UV)' 기능을 구현했습니다.

### 3) 실시간성: 폴링 vs WebSocket
실시간 로그 모니터링 기능을 위해 WebSocket과 주기적 폴링 방식을 저울질했습니다.
*   **결정:** 현재 인프라 복잡도를 낮추기 위해 우선 Polling(또는 정기적 데이터 페칭) 방식을 채택했습니다. 어드민 페이지에서 필요한 순간에만 데이터를 가져오는 구조를 통해 서버 리소스를 효율적으로 관리하고자 했습니다.

## 3. 최종 해결 및 엔지니어링 교훈 (Takeaway)

### 시스템 구조
FastAPI의 `BaseHTTPMiddleware`를 구현하여 모든 요청을 가로채고, 파싱된 데이터를 `visitor_logs` 테이블에 적재합니다.

*   **데이터 필터링:** 관리자 IP 및 내부 테스트 요청은 로그 테이블에서 제외하여 분석의 신뢰도를 높였습니다.
*   **데이터 가공:** 단순히 로그를 쌓는 것에 그치지 않고, `User-Agent`를 기반으로 OS와 브라우저를 파싱하여 어드민 대시보드에 시각화(Chart.js 등 활용)했습니다.

### 배운 점
1.  **빌드 vs 구매(Build vs Buy):** 때로는 외부 라이브러리를 쓰는 것보다 직접 만드는 것이 서비스의 철학(프라이버시 최우선)을 지키고, 불필요한 의존성을 제거하는 데 훨씬 효율적일 수 있음을 배웠습니다.
2.  **데이터 무결성(Integrity):** 인덱스(`idx_visitor_logs_created_at`) 설계를 통해 기간별 로그 조회 성능을 보장했습니다. 모니터링은 데이터가 쌓일수록 느려지기 마련이므로, 초기부터 인덱스 전략을 세우는 것이 중요하다는 것을 체감했습니다.
3.  **옵저버빌리티(Observability):** 시스템 에러 로그와 방문자 데이터를 통합 관리함으로써, "유저가 특정 구간에서 이탈하는가?" 혹은 "특정 브라우저에서 500 에러가 발생하는가?"와 같은 **기술-비즈니스 상관관계**를 빠르게 파악할 수 있는 기반을 마련했습니다.

이 시스템을 통해 단순한 수치 확인을 넘어, 유저의 발자취를 추적하고 시스템 에러에 즉각 대응할 수 있는 강력한 무기를 갖게 되었습니다. 앞으로는 수집된 데이터를 바탕으로 이상 탐지(Anomaly Detection) 모델을 붙여볼 계획입니다.
