안녕하세요, PickSafe 백엔드 에디터입니다. 

현대 웹 서비스에서 사용자 행동 분석과 모니터링은 필수적입니다. 보통 Google Analytics(GA) 같은 외부 서드파티 솔루션을 쉽게 떠올리지만, 이번 프로젝트에서는 **프라이버시 존중, 오프라인 PWA 성격 유지, 그리고 불필요한 외부 네트워크 부하 최소화**를 이유로 **'자체 방문자 분석 및 로그 모니터링 시스템'**을 구축하기로 결정했습니다.

이번 포스팅에서는 무거운 외부 솔루션을 걷어내고, FastAPI 미들웨어와 RDB를 활용해 고성능·경량화된 자체 분석 시스템을 설계한 과정과 기술적 트레이드오프(Trade-off)를 공유합니다.

---

## 1. Problem: 왜 외부 솔루션을 쓰지 않고 자체 구축을 선택했을까?

초기 서비스 기획 단계에서 마주한 요구사항은 다음과 같았습니다.
1. **PWA(Progressive Web App) 환경 지원:** 오프라인 성격을 띠거나 네트워크 제약이 있는 환경에서도 원활히 동작해야 함.
2. **엄격한 개인정보 보호:** 민감한 사용자 정보를 수집하지 않으면서도 유의미한 통계(PV, UV, 접속 환경 등)를 추출해야 함.
3. **통합 관리:** 비즈니스 로직 에러와 사용자 트래픽 분석을 어드민 대시보드 한 곳에서 실시간으로 모니터링할 수 있어야 함.

상용 분석 툴은 서드파티 스크립트 로딩으로 인한 성능 저하 우려가 있었고, 커스텀 대시보드와의 유기적인 결합이 어려웠습니다. 이에 **FastAPI 미들웨어 기반의 트래킹 파이프라인**을 직접 설계하기로 했습니다.

---

## 2. Technical Decision & Trade-off: 어떻게 설계할 것인가?

### ① 데이터 수집: FastAPI Middleware 활용
모든 라우터에 일일이 로깅 코드를 심는 것은 휴먼 에러를 유발하고 코드 가독성을 떨어뜨립니다. 따라서 **FastAPI HTTP Middleware**를 도입했습니다.

* **필터링:** 정적 파일(`/.css`, `/.js`, `/static/` 등) 요청은 수집 대상에서 제외하여 DB I/O 낭비를 방지합니다.
* **비동기 처리 고려:** 미들웨어 내부에서 무거운 작업이 발생하면 전체 응답 속도(Latency)에 영향을 주므로, 수집된 데이터는 가볍게 파싱하여 적재하도록 설계했습니다.

### ② 보안 및 프라이버시: IP 해시화 (IP Hashing)
유저의 고유 방문자 수(UV)를 측정하려면 식별자가 필요하지만, 원본 IP를 그대로 저장하는 것은 개인정보보호 관점에서 리스크가 큽니다.
* **해결책:** IP 주소를 그대로 저장하는 대신 **단방향 해시(예: SHA-256 등)** 처리하여 `ip_hash` 컬럼에 저장했습니다. 이를 통해 개인정보 유출 위험을 원천 차단하면서도, 동일 사용자의 재방문 여부(UV)는 정확하게 파악할 수 있도록 구현했습니다.

### ③ 데이터베이스 스키마 디자인
정밀한 분석을 위해 설계한 `visitor_logs` 테이블의 핵심 구조는 다음과 같습니다.

```sql
CREATE TABLE visitor_logs (
    id VARCHAR(36) PRIMARY KEY,
    ip_hash VARCHAR(64) NOT NULL,       -- IP 단방향 해시 (개인정보 보호 & 중복 방문자 확인)
    session_id VARCHAR(100) NOT NULL,   -- 브라우저 세션 식별자
    user_id VARCHAR(36) REFERENCES users(id) ON DELETE SET NULL, -- 로그인 유저 매핑
    path VARCHAR(255) NOT NULL,         -- 요청 경로
    method VARCHAR(10) NOT NULL,        -- HTTP Method
    user_agent TEXT,                    -- User-Agent 원문
    browser VARCHAR(50),                -- 파싱된 브라우저명
    os VARCHAR(50),                     -- 파싱된 OS명
    locale VARCHAR(10),                 -- 접속 언어
    referer TEXT,                       -- 유입 경로
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 시계열 집계 쿼리 성능을 위한 인덱스
CREATE INDEX idx_visitor_logs_created_at ON visitor_logs(created_at);
```

## 3. Implementation: 어드민 모니터링 기능 구현

구축된 데이터를 기반으로 어드민 대시보드에 다음과 같은 인사이트를 제공합니다.

1. **Summary Metrics (개요):** 전체 페이지 뷰(PV), 고유 방문자(UV), 최근 30분 기준 활성 세션 수를 실시간 집계.
2. **User Environment (환경 분포):** User-Agent 파싱 데이터를 기반으로 접속 브라우저 및 OS 분포를 차트 라이브러리(Chart.js 등)와 연동.
3. **Real-time Log Monitoring:** 시스템 에러(500 에러, 외부 API 연동 실패 등)를 심각도(INFO, WARNING, ERROR)별로 필터링하고, 최근 로그를 실시간으로 스트리밍 조회할 수 있는 뷰 제공.

## 4. Takeaways & Lessons Learned

* **"가장 단순한 것이 가장 강력하다":** 무겁고 복잡한 외부 분석 툴을 도입하는 것보다, 우리 서비스의 핵심 지표만 타겟팅하여 자체 미들웨어와 RDB로 구축한 것이 유지보수성과 커스터마이징 측면에서 훨씬 큰 효용을 가져다주었습니다.
* **성능과 보안의 균형:** IP 해시화 같은 작은 디테일이 개인정보 이슈를 예방함과 동시에 서비스의 신뢰도를 높여준다는 점을 다시 한번 체감했습니다.
* **확장성 확보:** 초기에는 단일 DB 인덱스로 시작했으나, 향후 트래픽이 증가할 경우 시계열 데이터 분산이나 별도의 로그 적재소(Log aggregation)로 마이그레이션할 수 있는 확장 가능한 구조적 기틀을 마련했습니다.

앞으로도 PickSafe는 성능 저하 없이 유저 경험과 보안을 모두 잡는 견고한 아키텍처를 만들어 나갈 것입니다. 많은 기대 바랍니다!
