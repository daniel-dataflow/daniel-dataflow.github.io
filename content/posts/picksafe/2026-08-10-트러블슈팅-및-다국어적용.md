## 1. Problem: Vercel Proxy 환경에서의 소셜 로그인 500 에러

### 문제 정의
구글 등 소셜 로그인 콜백 직후 `finalize_login` 라우터로 진입하는 시점에서 뜬금없는 `ModuleNotFoundError`와 함께 500 에러가 발생했습니다. 이로 인해 사용자는 로그인 세션을 발급받지 못하고 무한 루프에 빠지는 치명적인 온보딩 이탈 현상을 겪었습니다.

### 기술적 고민과 대안 비교
- **원인 분석**: Vercel과 같은 리버스 프록시/서버리스 환경에서는 번들링되거나 실행되는 컨텍스트에 따라 특정 Python 패키지(`python-jose`) 의존성 누락 문제가 간헐적으로 발생했습니다.
- **대안 1 (패키지 추가)**: `requirements.txt`에 해당 모듈을 강제 포함시키고 빌드 버전을 고정한다. -> *단점: 서버less 환경의 콜드 스타트 최적화나 불필요한 의존성 비대화를 야기할 수 있음.*
- **대안 2 (코드베이스 내부 유틸 활용)**: 이미 프로젝트 내부 보안 모듈 내에 안전하게 구현되어 검증된 커스텀 토큰 검증 함수(`decode_access_token`)가 존재했습니다. 굳이 외부 패키지 레이어에 의존할 필요가 없었습니다.

### 최종 해결
외부 모듈 의존성을 걷어내고, 프로젝트 내부의 안정적인 토큰 디코딩 함수를 활용하도록 인증 라우터를 리팩토링했습니다. 프록시 환경의 특성에 구애받지 않고 일관된 세션 쿠키 발급이 가능해졌으며, 온보딩 및 마이페이지 진입 성공률 100%를 달성했습니다.

## 2. Troubleshooting: OCR 서비스 다중화에 따른 'Too many values to unpack' 에러

### 문제 정의
이미지 성분 스캔 요청 시, 클라이언트에는 단순한 포괄적 에러 메시지만 노출되어 디버깅이 난항을 겪었습니다. 실제 서버 내부를 들여다보니 두 가지 문제가 연쇄적으로 발생하고 있었습니다.

### 추적 및 해결 과정
1. **가시성 확보 (Fail-Fast)**: 
   먼저 에러 핸들링 부를 패치하여 프론트엔드에 상세 Python Exception String이 노출되도록 변경했습니다(`detail=f"성분 분석 오류 원인: {str(e)}"`).
2. **1차 원인 (`NameError`)**: 
   실행 시간 측정 부(`elapsed_ms`)에서 변수가 선언되기 전에 호출되는 `NameError`를 발견하여 즉각 초기화 로직을 보강했습니다.
3. **2차 원인 (`ValueError: too many values to unpack`)**: 
   이것이 핵심이었습니다. 최근 멀티 API 키 시스템을 도입하면서 OCR 수행 함수(`perform_ocr_on_image`)의 리턴값이 기존 2개에서 3개(`text, model, key_id`)로 확장되었습니다. 그러나 라우터 레이어에서는 여전히 2개의 변수로만 언패킹을 시도하고 있어 충돌이 난 것입니다.
   - **해결**: 라우터의 수신부를 3개 변수(`raw_ocr_text, used_model, used_key_id`)로 정확히 매칭하고, 테스트용 Mock 응답 분기(`ocr_service.py`)까지 동일한 3튜플 구조로 Type Hint를 통일하여 견고한 파이프라인을 구축했습니다.

## 3. Engineering Practice: 하드코딩 철폐와 완전한 i18n(다국어) 아키텍처 완성

### 문제 정의
글로벌 타겟 서비스인 PickSafe의 `result.html`, `base.html` 등 주요 뷰 템플릿 곳곳에 "성분 안내:", "배합한도:" 등의 한국어 텍스트가 하드코딩되어 있었습니다. 이는 다국어 전환 시 레이아웃 깨짐 및 로컬라이제이션 누락의 원인이 됩니다.

### 구현 내용
- 정밀 정규식 탐색(`grep_search`)을 통해 UI 전반에 남아있던 한국어 하드코딩 5곳을 모두 색출했습니다.
- 데이터베이스 시딩 스크립트(`seed_multilingual_db.py`)에 고유 번역 키들을 추가했습니다:
  - `result.restriction_label` (배합한도)
  - `result.regulation_label` (규제정보)
  - `result.unverified_prefix` / `result.unverified_reason` (성분 안내 및 사유)
  - `base.alert_default` (알림 더미 텍스트)
- 이로써 프로젝트 내 총 고유 다국어 키는 **150개**, 6개 국어 지원 기준 **총 900개의 번역 데이터셋**을 완벽하게 구축하여, 언어 장벽 없는 매끄러운 글로벌 UI/UX를 완성했습니다.

## Takeaway (엔지니어링 교훈)

1. **외부 의존성 최소화**: 서버less 및 프록시 환경에서는 외부 패키지 의존성으로 인한 빌드 에러 리스크가 큽니다. 검증된 내부 유틸리티를 최대한 활용하는 것이 아키텍처 안정성 측면에서 유리합니다.
2. **확장성 도입 시 인터페이스 동기화**: API 리턴 값의 형태(튜플, JSON 구조 등)가 변경될 때는 라우터, 서비스 레이어, 그리고 테스트 Mock까지 전파 범위를 명확히 파악하고 동기화해야 런타임 에러를 방지할 수 있습니다.
3. **글로벌 스탠다드 준수**: 비즈니스 로직 외에 UI 텍스트 같은 세부 요소도 초기 설계 단계부터 i18n 파이프라인으로 통합 관리해야 기술 부채를 예방할 수 있습니다.
