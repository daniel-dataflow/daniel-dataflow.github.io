최근 PickSafe 기술 블로그의 대량 ADR(Architecture Decision Record) 문서 관리와 정식 도메인 오픈을 앞두고, 어드민 스튜디오의 전면적인 운영 고도화 작업을 진행했습니다. 

이번 포스팅에서는 대량의 문서를 처리하는 과정에서 마주했던 **4가지 기술적 난제(Problem)**와, 이를 해결하기 위해 채택한 **아키텍처 및 구현 방식(Trade-off & Solution)**, 그리고 서비스 안정성을 높이기 위해 수립한 **출시 전 가드레일**을 공유하고자 합니다.

## 1. 마주한 문제들 (Problem Definition)

수십 편의 ADR 문서를 기술 블로그 포스트로 변환하여 배포하는 파이프라인을 구축한 직후, 실전 검증 과정에서 다음과 같은 한계점이 드러났습니다.

1. **기발행 글 대량 관리 수단 부재**: 잘못 배포된 글을 지우려면 Git CLI나 웹 리포지토리에 직접 접근해야 했고, 탭 간 선택 상태(State)가 분리되지 않아 UI 충돌이 발생했습니다.
2. **Hugo 정적 사이트의 Mermaid 렌더링 실패**: 어드민 미리보기에서는 정상 작동하던 다이어그램이 실제 배포된 Hugo 블로그에서는 Chroma 문법 하이라이터와 충돌하여 단순 텍스트로 노출되었습니다.
3. **'월별 전체선택' 카운트 불일치 버그**: 1일 1포스팅 스마트 캐스케이드 알고리즘으로 인해 *원본 문서 일자*와 *캐스케이드된 발행 일자*가 달라지면서, 날짜 문자열 필터링(`String.startsWith`) 기반의 전체선택 시 화면 표시 건수와 실제 선택 건수가 어긋나는 버그가 발생했습니다.
4. **휴먼 에러와 접근성 결함**: 카테고리가 기본 선택되어 있어 오발행 위험이 있었고, 일부 브라우저 환경에서는 셀렉트박스의 반투명 스타일 때문에 드롭다운 옵션이 읽히지 않는 문제가 있었습니다.

## 2. 기술적 고민과 해결 (Trade-off & Solutions)

### 2.1. 기발행 글 일괄 삭제와 Git 워크트리 트랜잭션
기발행 글을 안전하게 지우기 위해 FastAPI 백엔드에 일괄 삭제 엔드포인트(`DELETE /api/admin/blog/published-posts/batch`)를 구축했습니다. 
* 파일 시스템의 존재 여부를 검증한 뒤 `os.remove()`로 일괄 삭제하고, `git add -u`와 단일 커밋(`🗑️ Batch delete N published posts`)을 거쳐 원격 레포지토리에 즉시 반영되도록 트랜잭션 파이프라인을 구성했습니다. 이를 통해 수동 작업 없이 웹 어드민에서 안전한 롤백이 가능해졌습니다.

### 2.2. Hugo Goldmark 렌더 훅을 통한 Mermaid 파이프라인 구축
Hugo는 기본적으로 백틱(```mermaid) 코드 블록을 만나면 Chroma 구문 하이라이터로 감싸 `<pre class="chroma">`를 생성합니다. 이를 우회하기 위해 **Goldmark 렌더 훅**을 도입했습니다.
1. `layouts/_default/_markup/render-codeblock-mermaid.html`을 생성하여 HTML을 직접 방출하도록 수정:
   ```html
   <div class="mermaid">
     {{ .Inner | safeHTML }}
   </div>
   ```
2. `hugo.yaml`에서 `markup.goldmark.renderer.unsafe = true`를 허용하고, CDN을 통해 `mermaid.min.js`를 비동기 로드하여 정적 사이트에서도 완벽한 아키텍처 다이어그램 렌더링을 구현했습니다.

### 2.3. 데이터 필터링의 한계를 극복한 'DOM-바운드 3-상태 동기화'
데이터 기반 필터링은 캐스케이드된 날짜 변위 때문에 UI와 데이터 간 불일치를 유발했습니다. 이를 해결하기 위해 **DOM-Parity(DOM 바운드) 방식**으로 선회했습니다.
* 날짜 문자열을 필터링하는 대신, 사용자가 보고 있는 폴더 내에 실제 렌더링된 체크박스 요소(`folderEl.querySelectorAll('.doc-select-checkbox')`)를 직접 순회하고 조작했습니다.
* `checked`, `indeterminate`, `unchecked`의 3-상태(Tristate)를 지원하도록 구현하여, 화면에 표시된 폴더 내 건수와 선택 건수가 100% 일치하도록 정합성을 확보했습니다.

```javascript
// DOM 기반 직접 질의를 통한 월별 전체선택 토글 예시
function toggleSelectMonth(month, checked, event) {
    const folderEl = event.target.closest('.date-folder');
    const itemCheckboxes = folderEl.querySelectorAll('.doc-select-checkbox');
    itemCheckboxes.forEach(cb => {
        const docId = cb.dataset.docId;
        if (checked) {
            selectedDocs.add(docId);
        } else {
            selectedDocs.delete(docId);
        }
    });
    syncAllFolderCheckboxes();
    updateBatchActionBar();
}
```

### 2.4. 오발행 방지 가드레일 및 고대비 테마
* **가드레일**: 발행 카테고리의 초기값을 미선택 상태(`-- ⚠️ 발행 카테고리를 선택하세요 --`)로 강제하고, 미선택 시 발행 시도를 차단하며 브라우저 경고와 함께 붉은색 진동 애니메이션(`@keyframes batchShake`)을 트리거하여 휴먼 에러를 원천 차단했습니다.
* **크로스 브라우저 대응**: 브라우저 팝업 엔진의 투명도 이슈를 해결하기 위해 셀렉트박스와 `<option>` 태그 전체에 솔리드 다크 배경(`#0f172a`)과 화이트 텍스트(`#f8fafc`)를 명시적으로 강제하여 가독성을 높였습니다.

## 3. 정식 출시 대비 사전 점검 (Pre-Launch Audit)

도메인 연동 및 정식 배포 전, 안정성을 담보하기 위해 아래 7가지 핵심 항목을 최종 점검했습니다.

1. **OAuth 소셜 로그인**: 새 도메인 환경에 맞춰 Google/Kakao/Naver 콘솔의 `redirect_uri` 3사 동시 등록 확인.
2. **SEO & SNS 공유**: 상대 경로를 절대 URL(`https://{domain}/static/...`)로 보장하여 `og:image` 누락 방지.
3. **색인 최적화**: 정적 `sitemap.xml` 및 `robots.txt` 서빙 경로 완비.
4. **SSL 및 DNS**: DNS 전파 대기 및 HTTPS HSTS 강제 리다이렉트 확인.
5. **예외 처리**: 파이썬 스택트레이스가 노출되지 않도록 커스텀 에러 페이지 UI 적용.
6. **API 쿼터 방어**: Gemini Vision OCR 사용 시 다중 API 키 라운드로빈 및 재시도 백오프 엔진 점검.
7. **환경변수 분리**: 프로덕션 환경(`ENV=production`, `DEBUG=False`) 전환 확인.

## 4. 엔지니어링 교훈 (Takeaways)

이번 고도화 작업을 통해 얻은 가장 큰 교훈은 **"복잡한 비즈니스 로직(스마트 캐스케이드 등)이 얽혀있을 때, 데이터 상태(State)와 화면 DOM 상태가 어긋나기 쉽다"**는 점이었습니다. 

데이터를 거쳐 UI를 맞추려 하기보다, 사용자가 실제로 조작하고 인지하는 DOM 구조를 기준으로 상태를 동기화하는 접근(DOM-Parity)이 예기치 못한 버그를 줄이는 강력한 무기가 될 수 있음을 배웠습니다. 앞으로도 PickSafe는 개발자 경험(DX)과 운영 효율성을 동시에 높이는 견고한 아키텍처를 만들어 나갈 것입니다.
