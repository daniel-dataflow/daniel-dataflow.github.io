안녕하세요, PickSafe 팀의 시니어 백엔드/풀스택 에디터입니다. 

웹 서비스의 한계를 넘어 네이티브 앱과 같은 사용자 경험(UX)을 제공하기 위해 PWA(Progressive Web App)를 도입하는 팀이 많습니다. 저희 PickSafe 역시 PWA를 통해 접근성과 사용성을 극대화하고자 했습니다.

하지만 브라우저가 기본으로 제공하는 '홈 화면 추가(Add to Home Screen)' 프롬프트에만 의존하다 보니, **맥락 없는 노출, 실수로 닫았을 때의 복구 불가, DEV/PROD 환경의 아이콘 및 매니페스트 혼선** 등 여러 실무적인 벽에 부딪히게 되었습니다.

이번 글에서는 PickSafe가 이러한 PWA의 한계를 극복하기 위해 어떤 **기술적 고민**을 거쳤고, **어떤 트레이드오프(Trade-off)를 통해 문제를 해결**했는지 아키텍처 의사결정(ADR) 관점에서 공유해 드립니다.

---

## 1. Problem: 마주한 기술적 및 UX적 한계

PWA Phase 1 도입 후, 실제 사용자 데이터를 분석하면서 다음과 같은 세 가지 마찰 요소(Friction)를 발견했습니다.

1. **브라우저 기본 프롬프트의 UX 침해**: 브라우저가 알아서 띄워주는 설치 유도 배너는 사용자에게 타이밍이 맞지 않게 노출되며, 사용자가 무심코 닫았을 때 다시 띄우기 어렵습니다.
2. **앱 삭제 후 상태 동기화 누락**: 사용자가 홈 화면에서 앱을 삭제(Uninstall)한 뒤 웹 브라우저로 다시 접속했을 때, 브라우저는 '이미 설치된 상태'로 오인하여 커스텀 모달이나 안내를 제공하지 않는 버그가 발생했습니다.
3. **DEV/PROD 환경 분리의 모호성**: 정적 `manifest.json` 파일을 그대로 사용하다 보니, 개발(DEV) 환경과 운영(PROD) 환경의 PWA 앱이 홈 화면에서 구분되지 않아 QA 및 자체 테스트 시 심각한 혼란을 초래했습니다.

---

## 2. Trade-off & Solution: 어떻게 해결할 것인가?

### 2.1 커스텀 설치 모달 (`pwaInstallModal`) 및 쿨다운(Cooldown) 도입
* **대안 비교**: 
  * *안 A*: 브라우저 기본 프롬프트 그대로 사용 (구현 비용 제로, UX 제어 불가능)
  * *안 B*: 완전 자체 제작한 커스텀 모달 + `beforeinstallprompt` 이벤트 가로채기 (구현 비용 높음, 완벽한 UX 제어 가능)
* **선택 및 이유**: **안 B**를 선택했습니다. `base.html`과 `base.js`에 커스텀 모달을 구현하여 서비스의 브랜드 아이덴티티에 맞는 디자인과 안내 문구를 적용했습니다.
* **사용자 피로도 방지**: '다음에 하기(Skip)'를 선택한 경우, `localStorage('pwa_skip_until')`에 타임스탬프를 기록하여 **24시간 동안 모달을 노출하지 않는 쿨다운 로직**을 적용해 서비스 이탈률을 방어했습니다.

### 2.2 `syncPwaInstallState()`를 통한 앱 삭제 감지
* **문제 상황**: 사용자가 앱을 삭제했음에도 `localStorage`에는 'installed' 상태가 남아 있어 설치 유도 경험이 끊기는 현상.
* **해결책**: 앱 진입 시 실행되는 `syncPwaInstallState()` 함수를 설계했습니다. 현재 실행 환경이 독립형 앱 모드(`isStandalone() == false`)인지 확인하고, 만약 로컬 스토리지 상태와 실제 브라우저 환경이 불일치할 경우(즉, 앱을 삭제하고 브라우저로 들어온 경우) 강제로 상태를 초기화(Reset)하여 자연스럽게 설치 모달을 다시 유도할 수 있도록 개선했습니다.

### 2.3 FastAPI를 활용한 동적 PWA Manifest 서빙 (DEV / PROD 분리)
* **문제 상황**: 정적 파일인 `manifest.json`은 빌드 타임에 고정되므로, DEV 환경과 PROD 환경에서 앱 이름을 다르게 가져가기 번거로움.
* **해결책**: 정적 파일 서빙 방식을 포기하고, 백엔드 프레임워크인 **FastAPI의 동적 엔드포인트(`@app.get("/manifest.json")`)**를 통해 매니페스트를 생성해 내려주기로 결정했습니다.
* **구현 로직**: 백엔드 환경 변수(`settings.ENV == "dev"`)를 감지하여, 개발 환경일 경우 앱 이름을 **"dev.picksafe"**로 오버라이딩하도록 구현했습니다. 이를 통해 개발자와 테스터가 홈 화면에서 명확히 환경을 인지할 수 있게 되었습니다.

---

## 3. Takeaway: 엔지니어링 교훈

1. **UX는 프론트엔드와 백엔드의 긴밀한 협업이다**: PWA는 단순한 프론트엔드 설정(Manifest, Service Worker)을 넘어, 백엔드의 동적 라우팅 지원과 상태 동기화 로직이 결합될 때 비로소 네이티브 앱에 준하는 완성도 높은 UX를 낼 수 있습니다.
2. **개발자 경험(DX)이 곧 프로덕트 품질이다**: DEV/PROD 환경별 매니페스트 동적 분리는 사용자뿐만 아니라 우리 팀의 QA 효율성을 극적으로 높여주었습니다. 내부 사용자를 위한 작은 디테일이 배포 안정성을 지키는 키가 됩니다.

PickSafe 팀은 앞으로도 기술적 완성도와 사용자 경험 사이의 최적의 접점을 찾아내며, 더 단단한 아키텍처를 구축해 나갈 것입니다. 

읽어주셔서 감사합니다!
