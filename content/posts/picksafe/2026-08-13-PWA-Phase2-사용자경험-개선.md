안녕하세요, PickSafe 백엔드 및 웹 플랫폼 엔지니어링 팀입니다. 

PickSafe는 웹과 모바일 환경 모두에서 네이티브 앱 수준의 매끄러운 사용성을 제공하기 위해 PWA(Progressive Web App) 기술을 적극적으로 도입하고 있습니다. 이번 포스팅에서는 PWA Phase 2 고도화 과정에서 마주한 UX적 한계와 이를 해결하기 위해 내린 아키텍처적 결정(ADR)의 과정을 공유하고자 합니다.

---

## 1. Problem: PWA Phase 1의 한계와 마주한 문제들

PWA Phase 1에서는 서비스 워커(Service Worker)와 기본 manifest 설정을 통해 '홈 화면에 추가(Add to Home Screen)' 기능의 뼈대를 완성했습니다. 하지만 실제 서비스를 운영하며 다음과 같은 사용자 경험(UX) 및 운영상의 병목(Pain Points)이 수면 위로 떠올랐습니다.

1. **맥락 없는 기본 프롬프트와 이탈률**: 브라우저가 기본 제공하는 설치 프롬프트는 사용자에게 서비스의 가치를 전달하지 못한 채 불쑥 나타납니다. 사용자가 실수로 닫거나 거부했을 때, 이를 다시 유도할 수 있는 제어권이 부족했습니다.
2. **앱 삭제 후 상태 동기화 누락**: 사용자가 홈 화면에서 앱을 삭제(Uninstall)한 뒤 모바일 브라우저로 재접속했을 때, 브라우저는 이전 설치 기록을 기억하고 있어 커스텀 설치 유도 모달이 아예 뜨지 않는 버그가 발생했습니다.
3. **DEV / PROD 환경 혼동**: QA 및 개발 단계(`dev`)와 실제 운영 단계(`prod`)의 PWA 앱 아이콘과 이름이 동일하여, 테스터와 개발자들이 어떤 환경의 앱을 사용하고 있는지 혼란을 겪었습니다.
4. **모바일 웹 환경의 파편화**: 브라우저별 호환성 및 오프라인 이슈 등 PWA 특화 에러를 빠르게 수집할 수 있는 피드백 루프가 부족했습니다.

---

## 2. Trade-off & Decision: 어떻게 해결할 것인가?

이 문제를 해결하기 위해 엔지니어링 팀은 프론트엔드 UX 제어부터 백엔드 동적 라우팅까지 전방위적인 개선을 설계했습니다.

### ① 브라우저 기본 프롬프트 대체: `pwaInstallModal`과 24시간 쿨다운
* **결정**: 브라우저의 기본 `beforeinstallprompt` 이벤트를 가로채어(`preventDefault`), PickSafe의 디자인 시스템이 녹아든 **커스텀 설치 모달**을 구현했습니다.
* **Trade-off**: 사용자가 '다음에 하기(Skip)'를 선택했을 경우 무분별한 모달 노출로 인한 피로도를 높일 수 있습니다. 이를 방지하고자 `localStorage('pwa_skip_until')`에 타임스탬프를 기록하여 **24시간 동안 모달을 숨기는 쿨다운 로직**을 적용했습니다.

### ② 앱 삭제 감지 및 상태 리셋 (`syncPwaInstallState`)
* **결정**: 사용자가 앱을 삭제했음에도 시스템이 '설치됨' 상태로 오인하는 문제를 해결하기 위해, 앱 실행 환경을 검증하는 `syncPwaInstallState()` 함수를 도입했습니다.
* **구현 방식**: `pwa_skip_until == 'installed'` 상태이더라도, 현재 실행 환경이 `isStandalone()`(실제 독립 앱 모드)가 아닐 경우 **"사용자가 앱을 삭제했다"**고 판단하여 상태를 강제로 리셋(Reset)하도록 처리했습니다. 이를 통해 이탈 유저에게 자연스럽게 설치를 다시 유도할 수 있게 되었습니다.

### ③ 정적 `manifest.json`에서 FastAPI 동적 서빙으로 전환
* **결정**: 기존에 고정된 정적 파일로 서빙되던 `manifest.json`을 백엔드(`main.py`) 라우터 엔드포인트(`@app.get("/manifest.json")`)로 이관했습니다.
* **Trade-off**: 정적 파일 서빙 대비 서버 요청이 발생하지만, 성능 부하가 미미한 반면 얻는 이득이 압도적입니다. 백엔드 환경 변수(`settings.ENV == "dev"`)를 참조하여, 개발 환경일 경우 앱 이름을 **"dev.picksafe"**로 동적 오버라이딩하여 내려줌으로써 DEV/PROD 앱을 홈 화면에서 육안으로 완벽하게 구분할 수 있게 되었습니다.

### ④ 플랫폼 전용 고객 문의 카테고리 신설
* **결정**: 마이페이지 1:1 문의 폼에 **"App / PWA Issue (📱 앱 및 시스템 오류)"** 카테고리를 신설하여, 파편화된 모바일 환경에서 발생하는 이슈를 빠르게 트래킹하고 대응할 수 있는 파이프라인을 구축했습니다.

## 3. Takeaway: 무엇을 배웠고, 어떤 효과를 얻었는가?

이번 PWA Phase 2 고도화는 단순한 UI 개선을 넘어, **"웹과 앱의 경계를 허물 때 발생하는 기술적 엣지 케이스(Edge Case)를 어떻게 다룰 것인가"**에 대한 좋은 엔지니어링 경험이었습니다.

* **사용자 중심의 UX 컨트롤**: 브라우저 엔진에만 의존하던 설치 플로우를 인앱 로직으로 제어함으로써, 사용자 피로도를 낮추고 서비스 내재화율을 높일 수 있는 발판을 마련했습니다.
* **환경 분리의 중요성**: 백엔드 API뿐만 아니라 PWA 매니페스트 영역까지 환경 변수를 연동함으로써, QA 및 개발 생산성을 크게 향상시켰습니다.

PickSafe 팀은 앞으로도 기술적 완성도와 사용자 경험(UX)이라는 두 마리 토끼를 모두 잡기 위한 고도화를 지속해 나갈 것입니다. 다음 기술 블로그도 기대해 주세요!
