안녕하세요. PickSafe 백엔드 및 웹 플랫폼 팀입니다.

최근 PickSafe는 웹의 접근성과 네이티브 앱의 사용성을 동시에 잡기 위해 PWA(Progressive Web App) 도입을 적극적으로 진행하고 있습니다. 이번 포스팅에서는 **PWA Phase 2** 프로젝트를 진행하며 마주한 UX적 한계를 극복하고, 이를 해결하기 위해 어떤 기술적 의사결정을 내렸는지 공유해 드리고자 합니다.

---

## 1. 문제 정의 (Problem)

PWA Phase 1을 통해 '홈 화면에 추가(Add to Home Screen)' 기능의 기반을 다졌으나, 실제 사용자 테스트 과정에서 다음과 같은 치명적인 마찰(Friction) 요소들이 발견되었습니다.

1. **맥락 없는 브라우저 기본 프롬프트**: 브라우저가 기본 제공하는 설치 프롬프트는 타이밍과 디자인을 제어할 수 없어 사용자에게 갑작스럽게 노출되며, 사용자가 실수로 닫을 경우 다시 유도할 방법이 마땅치 않았습니다.
2. **앱 삭제 후 상태 불일치 (State Desync)**: 사용자가 홈 화면에서 PWA를 삭제했음에도 불구하고, 브라우저 스토리지에는 '설치됨' 상태가 남아있어 커스텀 설치 유도 모달이 영구적으로 노출되지 않는 버그가 발생했습니다.
3. **DEV/PROD 환경 혼선**: QA 및 개발 과정에서 운영(PROD) 앱과 개발(DEV) 앱의 `manifest.json`이 동일해 홈 화면 아이콘만으로는 어떤 환경인지 구분이 어려웠습니다.

---

## 2. 기술적 고민과 아키텍처 대안 비교 (Trade-offs)

이 문제들을 해결하기 위해 팀 내에서 검토했던 기술적 대안과 최종 선택은 다음과 같습니다.

### 대안 1: 브라우저 기본 설치 이벤트(`beforeinstallprompt`)에 전적으로 의존
* **장점**: 구현 코드가 매우 단순하며 프레임워크 독립적입니다.
* **단점**: 브라우저마다 UI가 다르고, 사용자가 '거절(Dismiss)'했을 때 브라우저 정책에 의해 프로그래밍 방식으로 다시 프롬프트를 띄우는 것이 불가능합니다.
* **결정**: **기각.** 비즈니스 성장을 위한 전환율(Conversion Rate)을 높이기 위해 UI/UX 통제권을 확보해야 했습니다.

### 대안 2: 정적 `manifest.json` 파일 분포 배포 vs 백엔드 동적 서빙
* **장점 (정적 파일)**: CDN을 통해 빠르게 서빙할 수 있고 백엔드 부하가 없습니다.
* **단점 (정적 파일)**: 빌드 타임에 환경 변수를 주입해야 하므로 배포 파이프라인이 복잡해집니다.
* **결정**: **백엔드 동적 서빙 선택.** FastAPI 백엔드 라우터를 통해 환경 변수(`settings.ENV`)를 런타임에 주입받아, 개발 환경에서는 앱 이름이 `dev.picksafe`로 즉시 오버라이딩되도록 유연성을 확보했습니다.

## 3. 최종 해결 및 엔지니어링 구현 (Solution)

### 3.1 커스텀 설치 모달과 24시간 쿨다운 정책
브라우저 기본 프롬프트를 가로채어(`beforeinstallprompt` 이벤트 방지), 서비스 디자인 시스템에 맞춘 `pwaInstallModal`을 구현했습니다. 

사용자가 '다음에 하기(Skip)'를 선택할 경우, `localStorage`에 타임스탬프 기반의 쿨다운(`pwa_skip_until`)을 기록하여 24시간 동안은 피로도를 높이는 불필요한 모달 노출을 방지했습니다.

```javascript
// 개념적 구현 예시 (Client-side)
let deferredPrompt;

window.addEventListener('beforeinstallprompt', (e) => {
  e.preventDefault();
  deferredPrompt = e;
  
  // 쿨다운 체크 후 커스텀 모달 노출
  if (!isCoolingDown()) {
    showCustomInstallModal();
  }
});
```

### 3.2 앱 삭제 상태 동기화 루프 (`syncPwaInstallState`)
가장 까다로웠던 부분은 **"사용자가 홈 화면에서 앱을 지웠을 때 브라우저는 이를 어떻게 아는가"**였습니다. 

이를 해결하기 위해 앱 진입 시 실행되는 상태 동기화 함수인 `syncPwaInstallState()`를 도입했습니다. 현재 브라우저가 독립 실행형 모드(`window.matchMedia('(display-mode: standalone)')`)가 아님에도 불구하고 내부 스토리지에는 '설치 완료' 상태로 기록되어 있다면, 사용자가 앱을 삭제한 것으로 간주하고 상태를 리셋(Reset)하도록 설계했습니다.

```javascript
function syncPwaInstallState() {
  const isStandalone = window.matchMedia('(display-mode: standalone)').matches;
  const storedState = localStorage.getItem('pwa_skip_until');

  if (storedState === 'installed' && !isStandalone) {
    // 사용자가 PWA 앱을 삭제한 것으로 판단
    localStorage.removeItem('pwa_skip_until');
  }
}
```

### 3.3 FastAPI를 활용한 동적 Manifest 서빙
정적 파일로 관리되던 `manifest.json`을 FastAPI 엔드포인트로 전환했습니다.

```python
@app.get("/manifest.json")
async def get_pwa_manifest(settings: Settings = Depends(get_settings)):
    app_name = "dev.picksafe" if settings.ENV == "dev" else "PickSafe"
    
    return {
        "name": app_name,
        "short_name": app_name,
        "start_url": "/",
        "display": "standalone",
        "background_color": "#ffffff",
        "theme_color": "#000000",
        "icons": [...]
    }
```

## 4. Takeaways (배운 점과 기대 효과)

1. **UX 컨트롤 타워 확보**: 브라우저의 기본 동작을 무조건 따르는 대신, 서비스의 맥락에 맞춰 설치 타이밍을 제어함으로써 사용자 경험(UX)과 비즈니스 지표를 동시에 챙길 수 있었습니다.
2. **엣지 케이스(Edge Case) 선제 대응**: "앱 삭제 후 재방문"이라는 흔히 놓치기 쉬운 시나리오를 상태 동기화 로직으로 방어함으로써, QA 과정에서 발생할 수 있는 휴먼 에러를 원천 차단했습니다.
3. **환경 격리의 중요성**: 백엔드 라우터를 활용한 동적 매니페스트 서빙으로 DEV/PROD 환경을 명확히 분리하여, 멀티 환경 테스트의 안정성을 대폭 끌어올렸습니다.

PickSafe 팀은 앞으로도 단순한 기능 구현을 넘어, 사용자가 체감하는 디테일한 완성도와 확장 가능한 아키텍처를 고민해 나갈 것입니다. 감사합니다.
