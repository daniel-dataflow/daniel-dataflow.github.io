안녕하세요. 서비스 완성도를 높이기 위해 프론트엔드 UI/UX와 인터랙션 구조를 전면 개편했던 경험을 공유하려 합니다.

이번 개편은 단순한 '디자인 갈아엎기'가 아니었습니다. 모바일 환경에서 사용자의 시선 흐름을 분석하고, 밋밋했던 아코디언 컴포넌트에 직관적인 인터랙션(Affordance)을 부여하며, 치명적인 프론트엔드 렌더링 버그를 해결하는 **종합적인 프론트엔드 아키텍처 개선 작업**이었습니다.

---

## 1. 마주한 문제들 (Problem Definition)

서비스 런칭을 앞두고 진행한 사용성 테스트에서 몇 가지 치명적인 UX 결함과 버그가 발견되었습니다.

1. **깨지는 모바일 레이아웃과 어긋난 시선 동선**
   - 좁은 모바일 뷰포트에서 우측 상태 뱃지(`Logged In`)가 줄바꿈되면서 레이아웃이 깨졌습니다.
   - 성분 수정 버튼이 상단에 애매하게 위치해 있어, 사용자가 기피 성분 항목들을 먼저 확인하고 하단에서 수정하려는 자연스러운 시선 흐름과 역행했습니다.
2. **단순한 텍스트 바 형태의 아코디언 (Affordance 부족)**
   - 닫혀 있는 아코디언이 평면적인 텍스트 형태로만 노출되어, 사용자가 "이 안에 정보가 숨겨져 있으니 탭해보고 싶다"라는 직관적 인지(Affordance)를 얻지 못했습니다.
3. **1:1 문의 페이징 컨트롤 미노출 버그**
   - 문의 내역이 5건을 초과했음에도 하단 페이징 컨트롤(`◀ 1 / 2 ▶`)이 렌더링되지 않아 2페이지 이후의 내역을 아예 확인할 수 없는 치명적인 결함이 있었습니다.

---

## 2. 기술적 고민과 아키텍처 설계 (Trade-off & Solution)

이 문제를 해결하기 위해 **[정돈형 기피 성분 카드 + 인터랙티브 스택 아코디언 + 견고한 페이징 바인딩]** 구조로 리팩토링을 단행했습니다.

### ① 모바일 퍼스트 4행 구조로 레이아웃 재편
* **1행 (헤더)**: 좌측 타이틀과 우측 상태 뱃지를 배치하되, CSS 속성(`white-space: nowrap; flex-shrink: 0;`)을 강제하여 좁은 화면에서도 텍스트 개행이 절대 일어나지 않도록 방어했습니다.
* **4행 (액션 버튼)**: 성분 칩 하단에 수정 버튼을 배치하고 `justify-content: center`를 적용하여, 사용자가 시선을 아래로 자연스럽게 내린 채 엄지손가락으로 쉽게 터치할 수 있는 인체공학적 동선을 구축했습니다.

### ② 입체적 스택 섀도우를 통한 인터랙션 유인 (Affordance)
단순한 둥근 박스를 넘어, 사용자가 직관적으로 '열어보고 싶다'는 충동을 느끼도록 디자인 시스템을 개선했습니다.
* **다층 스택 섀도우**: 카드가 닫혀 있을 때 아래로 2~3장의 카드가 가지런히 겹쳐져 있는 듯한 멀티 레이어 그림자 효과(`box-shadow`)를 적용했습니다.
* **마이크로 인터랙션**: 호버 시 카드가 살짝 떠오르는 피드백을 주고, 원형 셰브론 토글 버튼을 도입해 펼쳐짐 상태에 따라 부드럽게 180도 회전하도록 애니메이션을 구현했습니다.

### ③ 프론트엔드 상태 동기화 및 전역 스코프 바인딩 수정
문의 내역 페이징 미노출 버그의 원인은 CSS(`display: none`)와 자바스크립트 간의 상태 동기화 누락이었습니다.
* 데이터가 존재하여 `totalPages > 1`이 될 때 명시적으로 `style.display = "flex"`를 주입하도록 수정했습니다.
* 동적으로 생성되는 페이지네이션 내부 함수(`changeInquiryPage`)를 `window` 객체에 안전하게 바인딩하여, SPA 혹은 비동기 렌더링 환경에서도 이벤트 맵핑이 누락되지 않도록 아키텍처를 견고하게 다졌습니다.

---

## 3. 엔지니어링 교훈 (Takeaways)

1. **디자인은 '시각적 아름다움'을 넘어 '사용자의 시선 동선'이다**
   - 버튼 하나의 위치를 위에서 아래로(중앙 정렬) 바꾼 것만으로도 모바일 환경에서의 터치 전환율과 UX 만족도가 크게 개선되었습니다. 컴포넌트 배치는 언제나 인체공학적 동선을 고려해야 합니다.
2. **시각적 단서(Affordance)의 중요성**
   - 아무리 좋은 콘텐츠를 숨겨두어도 유저가 '열 수 있다'는 것을 직관적으로 알지 못하면 무용지물입니다. 스택 섀도우와 같은 미세한 입체감 부여가 인터랙션 참여율을 결정한다는 것을 배웠습니다.
3. **UI 상태 관리의 꼼꼼함**
   - 백엔드 API가 데이터를 정상 내려주더라도, 프론트엔드 레이어에서 CSS 상태 전환(`display` 토글)이나 전역 스코프 바인딩이 누락되면 사용자에게는 '기능 고장'으로 직결됩니다. 엣지 케이스에 대한 꼼꼼한 렌더링 검증 프로세스의 필요성을 다시 한번 체감했습니다.
