안녕하세요. 서비스의 완성도를 높이기 위해 끊임없이 UI/UX와 프론트엔드 아키텍처를 다듬고 있는 1인 개발자입니다. 

이번 포스팅에서는 최근 진행한 사용자 마이페이지(Mypage) 전면 개편 과정에서 마주한 프론트엔드 결함들을 해결하고, 단순한 정보 나열형 화면을 '열어보고 싶은(Affordance가 높은)' 인터랙티브 스택 아키텍처로 탈바꿈시킨 기술적 의사결정(ADR) 과정을 공유하려 합니다.

---

## 1. 문제 정의 (Problem): 사소한 UI 버그가 사용자 경험에 미치는 영향

서비스 오픈을 준비하며 마이페이지를 최종 점검하던 중, 몇 가지 치명적이지는 않지만 사용자 경험을 해치는 결함(AS-IS)들을 발견했습니다.

1. **좁은 뷰포트에서의 레이아웃 깨짐**: 
   우측 상태 뱃지(`Logged In`)가 모바일 환경의 좁은 폭에서 `Logged\nIn`으로 2줄 줄바꿈되는 현상이 발생했습니다. 또한, 사용자 시선의 흐름(기피 성분 확인 후 하단으로 이동)과 어긋난 상단 버튼 배치로 인해 인터랙션 동선이 부자연스러웠습니다.
2. **밋밋한 아코디언으로 인한 인지적 단서(Affordance) 부족**: 
   닫혀 있는 아코디언이 단순한 평면 텍스트 바 형태로 보여, "안에 숨겨진 데이터가 있으니 탭해 보세요"라는 시각적 유인 요소가 전무했습니다.
3. **페이징 컨트롤 누락 버그**: 
   1:1 고객 문의 내역이 5건을 초과하여 6건째가 등록되었음에도, 페이징 UI(`inquiryPagination`)가 화면에 노출되지 않아 사용자가 2페이지 이후의 내역을 확인할 수 없는 치명적인 버그가 숨어 있었습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off & Architecture)

모바일 퍼스트 감성과 인체공학적 시선 동선을 충족시키기 위해 **[정돈형 기피성분 카드 + 인터랙티브 스택 아코디언 3종 + 하단 설정 카드]** 체계로 전면 개편을 단행했습니다.

### 2.1. 레이아웃 안정성 확보 (`white-space`와 Flexbox 정렬)
모바일 환경에서 텍스트 줄바꿈을 방지하기 위해 CSS 제어를 도입했습니다.
* **1행 헤더**: 상태 뱃지에 `white-space: nowrap; flex-shrink: 0;`을 적용하여 뷰포트가 줄어들어도 절대 줄바꿈이 일어나지 않도록 강제했습니다.
* **4행 버튼**: 성분 칩 하단에 위치한 수정 버튼에 `justify-content: center`를 적용하여 사용자의 엄지 손가락이 닿기 가장 편한 정중앙에 배치했습니다.

### 2.2. 입체적 스택 섀도우를 통한 Affordance 극대화
단순한 2D 박스 대신, 사용자가 본능적으로 "열어보고 싶다"는 느낌을 받도록 다층 그림자(Multi-layer Box Shadow) 아키텍처를 설계했습니다.

```css
/* 닫힌 상태의 아코디언에 다층 섀도우 적용 예시 */
.mypage-accordion-card:not(.open) {
  box-shadow: 0 2px 5px rgba(0,0,0,0.05), 
              0 5px 0 -1px rgba(255,255,255,0.8), 
              0 10px 0 -3px rgba(0,0,0,0.03);
  transform: translateY(0);
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

.mypage-accordion-card:not(.open):hover {
  transform: translateY(-2px);
}
```
* **시각적 은닉 효과**: 아래로 2~3장의 카드가 가지런히 겹쳐진 듯한 `box-shadow`를 구현하여 내부에 콘텐츠가 적재되어 있음을 직관적으로 알 수 있게 했습니다.
* **마이크로 인터랙션**: 호버 시 카드가 미세하게 떠오르는(`translateY(-2px)`) 피드백을 주어 반응형 UI의 재미를 더했습니다.

### 2.3. DOM 상태 동기화 누락 트러블슈팅 (`inquiryPagination`)
1:1 문의 페이징이 노출되지 않던 원인은 **JS 렌더링 로직과 CSS 초기 상태 간의 불일치**였습니다. 
* `mypage.html`에서 최초 `#inquiryPagination`을 `display: none;`으로 선언해 두었으나, `mypage.js`의 리스트 렌더링 함수(`renderInquiryListPage()`)에서 `totalPages > 1`일 때 `style.display = "flex"`로 전환해 주는 구문이 누락되어 있었습니다.
* 이를 수정하여 데이터 조건에 따라 DOM이 동적으로 올바른 Display 속성을 갖도록 바로잡았고, 페이지 전환 함수(`changeInquiryPage`)를 `window` 스코프에 바인딩하여 템플릿 간 통신 문제를 깔끔하게 해결했습니다.

## 3. 엔지니어링 교훈 및 마무리 (Takeaways)

이번 마이페이지 개편을 통해 다음 세 가지 교훈을 다시 한번 체득했습니다.

1. **UX는 작은 디테일에서 온다**: 화려한 기능보다도 "상태 뱃지가 2줄로 깨지지 않는 것", "페이지네이션이 정상 작동하는 것" 같은 기본기가 서비스의 신뢰도를 결정합니다.
2. **시각적 어포던스(Affordance)의 중요성**: 평면적인 UI 요소를 입체적인 스택 섀도우와 인터랙티브한 원형 셰브론 버튼으로 개선한 것만으로도 사용자의 인터랙션 유도율을 눈에 띄게 높일 수 있었습니다.
3. **상태 관리와 DOM 동기화의 꼼꼼한 검수**: CSS 초기값(`display: none`)과 JS 동적 제어 로직 간의 누락은 서비스 오픈 직전 흔히 발생하는 휴먼 에러이므로, 렌더링 파이프라인 전반의 상태 변화를 코드로 확실히 추적해야 합니다.

앞으로도 사용자 피드백을 기반으로 견고하고 감각적인 프론트엔드 아키텍처를 만들어 나가겠습니다.
