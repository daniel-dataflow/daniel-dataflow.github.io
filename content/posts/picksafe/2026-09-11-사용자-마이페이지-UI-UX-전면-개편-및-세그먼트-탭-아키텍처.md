서비스의 첫인상이 '홈 화면'이라면, 서비스의 신뢰도와 완결성을 결정짓는 곳은 단연 **'마이페이지(My Page)'**입니다. 마이페이지는 사용자가 설정한 개인화 데이터가 모이고, 서비스와 직접 소통(1:1 문의 등)하는 핵심 허브이기 때문입니다.

최근 PickSafe 팀은 마이페이지의 UI/UX를 전면 개편했습니다. 단순히 "예쁘게 만드는 것"을 넘어, **사용자의 터치 동선을 최적화하고, 인지적 부하를 줄이며, 프런트엔드의 고질적인 레이아웃 깨짐과 JS 버그를 우아하게 해결한 엔지니어링 여정**을 공유합니다.

---

## 1. 문제 정의 (Problem Statement)

기존 마이페이지는 기능 위주로 빠르게 구현되다 보니, 사용성이 저하되는 몇 가지 치명적인 결함과 마주하게 되었습니다.

```
[AS-IS 문제점 요약]
1. 좁은 모바일 화면에서 상태 뱃지([Logged In])가 두 줄로 깨지는 현상 (Layout Shift)
2. 평면적인 UI로 인해 아코디언 메뉴가 "열릴 수 있다"는 인지적 단서(Affordance) 부족
3. 1:1 고객 문의 내역이 5건을 초과할 때 하단 페이징 컨트롤이 노출되지 않는 프런트엔드 버그
```

### 1.1. 불완전한 레이아웃과 깨지는 타이포그래피
모바일 뷰포트가 극도로 좁아질 때, 우측 상단의 로그인 상태 뱃지가 `Logged\nIn` 형태로 깨지며 UI 일관성을 해쳤습니다. 또한, 가장 중요한 '기피 성분 수정' 버튼이 카드 상단 구석에 애매하게 위치하여, **[성분 확인 -> 하단 버튼 클릭]**으로 이어지는 사용자의 자연스러운 시선 흐름(Eye-tracking Flow)을 방해하고 있었습니다.

### 1.2. 마이크로 인터랙션의 부재
기존 아코디언 카드는 평면적인 회색 바 형태로 디자인되어 있었습니다. 사용자 관점에서는 이 카드를 누르면 아래로 상세 내용이 펼쳐질 것이라는 기대를 하기 어려웠습니다. 즉, **누르고 싶게 만드는 '촉각적 매력'과 시각적 힌트**가 부족했습니다.

### 1.3. 고객 소통의 단절을 초래하는 페이징 버그
가장 크리티컬했던 문제는 1:1 문의 내역 페이징 처리였습니다. 사용자가 등록한 문의글이 6개 이상이 되어도 다음 페이지로 넘어가는 내비게이션 버튼(`◀ 1 / 2 ▶`)이 화면에 아예 표시되지 않았습니다. 분석 결과, 특정 마크업 요소가 숨김 상태(`display: none`)에서 동적으로 활성화되지 않는 코드 결함이 존재했습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off)

해결책을 설계하면서 엔지니어링 관점에서 몇 가지 중요한 선택지가 있었습니다.

### 고민 1. 아코디언의 입체감 표현 방식: 3D 그래픽 vs CSS 다층 셰도우 (Stack Shadow)
카드들이 겹쳐 있는 듯한 효과를 주어 "안에 내용물이 숨겨져 있다"는 단서를 주기로 했습니다.

*   **대안 A: CSS Grid 및 실제 HTML 요소를 여러 개 겹쳐 그리는 방식**
    *   *장점*: 완벽하게 구조화된 마크업.
    *   *단점*: 아코디언 하나를 그리기 위해 무의미한 빈 DOM 요소를 생성해야 하므로 렌더링 비용이 증가함.
*   **대안 B: 단일 DOM에 CSS 멀티플 `box-shadow`를 활용한 가상 스택 효과 (선택)**
    *   *장점*: DOM 구조를 매우 가볍게 유지하면서, 단 몇 줄의 스타일 시트 정의만으로 입체적인 겹침(Stacked) 효과를 극대화할 수 있음. 렌더링 성능 최적화에 유리.

### 고민 2. Vanilla JS 환경에서 페이징 함수 노출 방식: ES 모듈 스코프 vs 윈도우 스코프 (Window Scope Binding)
현재 프로젝트는 빌드 도구 없이 템플릿 엔진 위에서 Vanilla JS를 가볍고 빠르게 서빙하는 아키텍처입니다.

*   **대안 A: 완벽한 모듈화 및 이벤트 리스너 동적 바인딩**
    *   *장점*: 전역 스코프 오염 방지.
    *   *단점*: 동적으로 생성되는 페이징 HTML 버튼(문자열 템플릿) 내에 이벤트를 매핑하기 위해 과도한 보일러플레이트 코드가 필요함.
*   **대안 B: 전역 `window` 객체에 한정적으로 페이징 핸들러 노출 (선택)**
    *   *장점*: HTML 스트링 템플릿 기반 렌더러에서 즉각적으로 함수 인라인 호출이 가능하여 유지보수성 극대화. 안전한 네이밍 컨벤션을 통해 충돌 위험 제어 가능.

## 3. 최종 해결 및 엔지니어링 구현 (Engineering Solution)

완성된 마이페이지의 아키텍처는 다음과 같이 사용자의 사용 흐름에 맞춰 상단에서 하단으로 물 흐르듯 설계되었습니다.

```
┌─────────────────────────────────────────────────────────┐
│ 🛡️ 기피 성분 설정                           [Logged In] │ ◄── 1행: white-space 방어 및 플렉스 레이아웃
│ Configure allergens and custom ingredients to avoid.    │
│ ┌─────────────────────────────────────────────────────┐ │
│ │  🚫 소금    🚫 Alcohol Denat                        │ │ ◄── 2행: 중앙 정렬된 칩 컴포넌트
│ └─────────────────────────────────────────────────────┘ │
│             [ ✏️ Edit Avoided Ingredients ]            │ ◄── 3행: 인체공학적 하단 중앙 배치 버튼
├─────────────────────────────────────────────────────────┤
│ ┌─[📌] 📌 저장된 제품 (3)                            ( ∧ )─┐ │ (기본 열림)
├─────────────────────────────────────────────────────────┤
│ ┌─[🕒] 🕒 최근 스캔 기록 (12)                        ( ⌵ )─┐ │ ◄── 다층 box-shadow로 구현된
└─└─└─────────────────────────────────────────────────────┘─┘   스택(Stack) 입체 어포던스
```

### 3.1. 레이아웃 붕괴 방지 및 인체공학적 배치 (CSS)
상태 뱃지(`Logged In`)가 모바일 가로폭이 좁아질 때 아래로 떨어지는 현상을 막기 위해 CSS Flexbox 속성과 `white-space` 제어를 적용했습니다.

```css
/* 레이아웃 깨짐을 원천 차단하는 상태 뱃지 스타일 */
.mypage-status-badge {
  white-space: nowrap; /* 줄바꿈 절대 방지 */
  flex-shrink: 0;      /* 부모 너비가 줄어도 찌그러지지 않음 */
}

/* 기피 성분 수정 버튼의 직관적인 하단 중앙 배치 */
.mypage-allergen-action-container {
  display: flex;
  justify-content: center; /* 시선이 수렴하는 하단 중앙에 배치 */
  margin-top: 1.5rem;
}
```

### 3.2. 입체적인 스택 아코디언 및 마이크로 인터랙션
닫혀 있는 아코디언 카드 하단에 마치 책이 쌓여 있는 듯한 효과를 주는 CSS 섀도우 기법을 적용했습니다. 마우스를 올리거나 터치할 때 가볍게 떠오르는 인터랙션을 더해 사용자 반응성을 높였습니다.

```css
/* 닫힌 아코디언 카드에 스택 어포던스 부여 */
.mypage-accordion-card:not(.open) {
  box-shadow: 
    0 4px 6px -1px rgba(0, 0, 0, 0.1),
    0 2px 4px -1px rgba(0, 0, 0, 0.06),
    0 8px 0 -2px #f3f4f6, /* 첫 번째 겹쳐진 카드 효과 */
    0 16px 0 -4px #e5e7eb; /* 두 번째 겹쳐진 카드 효과 */
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

/* 호버 시 부드러운 플로팅 애니메이션 */
.mypage-accordion-card:not(.open):hover {
  transform: translateY(-2px);
  box-shadow: 
    0 10px 15px -3px rgba(0, 0, 0, 0.1),
    0 4px 6px -2px rgba(0, 0, 0, 0.05),
    0 10px 0 -2px #f3f4f6,
    0 18px 0 -4px #e5e7eb;
}
```

### 3.3. 1:1 고객 문의 페이징 복구 (JS 트러블슈팅)
페이징 컨트롤러(`#inquiryPagination`)가 특정 조건에서 렌더링되지 않던 버그를 분석하여, 데이터 상태 변경 시 디스플레이 모드가 `none`에서 `flex`로 정상 전환되도록 코드를 정형화했습니다. 또한, 동적 이벤트 바인딩이 유실되는 문제를 방지하기 위해 `changeInquiryPage` 스코프를 안전하게 전역에 윈도잉했습니다.

```javascript
// mypage.js 중 발췌 및 추상화
function renderInquiryListPage(currentPage, data) {
  const pagContainer = document.querySelector("#inquiryPagination");
  if (!pagContainer) return;

  const totalPages = Math.ceil(data.totalCount / data.pageSize);

  if (totalPages > 1) {
    // [Troubleshooting] 기존에 display: none 상태로 갇혀 있던 컨테이너를 정상 노출시킴
    pagContainer.style.display = "flex"; 
    pagContainer.innerHTML = generatePaginationHTML(currentPage, totalPages);
  } else {
    pagContainer.style.display = "none";
  }
}

// 동적 생성 HTML 마크업에서 즉시 호출 가능하도록 전역 바인딩 처리
window.changeInquiryPage = function(targetPage) {
  fetchInquiryData(targetPage)
    .then(response => {
      renderInquiryList(response.items);
      renderInquiryListPage(targetPage, response);
    })
    .catch(err => console.error("Failed to load inquiries:", err));
};
```

## 4. 엔지니어링 교훈 (Takeaways)

이번 마이페이지 UX 전면 개편 과정을 통해 우리 팀은 단순한 기능 구현 이상의 세 가지 값진 교훈을 얻었습니다.

1.  **시각적 어포던스(Visual Affordance)의 가치**: 디자인이 평면적일 때 사용자는 길을 잃습니다. 복잡한 3D 그래픽 라이브러리를 쓰지 않더라도, 정교한 **CSS 다층 그림자(Multi-layered Shadow)** 효과만으로 사용자에게 탭을 유도하는 힌트를 성공적으로 제공할 수 있음을 확인했습니다.
2.  **모바일 퍼스트 레이아웃의 회복 탄력성(Resilience)**: 모바일 반응형 웹을 설계할 때 텍스트 길이에 변화를 주는 다국어 환경이나 극단적인 소형 스크린 환경을 반드시 고려해야 합니다. `white-space: nowrap`과 `flex-shrink: 0` 같은 방어적 CSS 기법은 Layout Shift를 방지하는 든든한 가드레일이 됩니다.
3.  **철저한 에지 케이스 검증**: 문의 내역이 5개 이하(단일 페이지)일 때는 나타나지 않던 페이징 컨트롤이 6개(멀티 페이지)가 되는 임계점(Edge Case)에서 발견된 화면 갱신 버그는 **실제 운영 환경과 유사한 데이터 스케일로 스테이징 검증을 하는 것이 얼마나 중요한지** 다시 한번 일깨워 주었습니다.

앞으로도 PickSafe는 성능과 심미성, 그리고 견고한 아키텍처 모두를 타협하지 않는 엔지니어링 문화를 만들어 가겠습니다.
