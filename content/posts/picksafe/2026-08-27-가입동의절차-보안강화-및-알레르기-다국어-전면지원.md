안녕하세요. PickSafe 팀의 시니어 백엔드 엔지니어입니다.

글로벌 헬스케어 및 성분 분석 서비스인 **PickSafe**는 최근 다양한 국가의 사용자를 맞이하며 빠르게 성장하고 있습니다. 급격한 트래픽 증가와 글로벌 확장 속에서, 개발 팀은 두 가지 핵심 가치에 직면했습니다. 바로 **'철저한 개인정보 보호(보안)'**와 **'이탈 없는 매끄러운 사용자 경험(UX)'**입니다.

최근 저희 팀은 기존 소셜 로그인 플로우에서 발견된 치명적인 보안 루프홀을 메우고, 글로벌 사용자를 위한 온보딩 프로세스를 한 단계 끌어올린 대대적인 리팩토링을 진행했습니다. 이번 포스팅에서는 **Consent Guard(동의 가드) 패턴**을 설계하여 보안 결함을 어떻게 해결했는지, 그리고 복잡한 화학 성분명을 6개 국어로 완벽히 서빙하기 위해 어떤 엔지니어링적 고민을 거쳤는지 공유하고자 합니다.

---

## 1. 우리가 마주한 세 가지 문제 (Problem)

### ① 보안 루프홀: 동의 완료 전 서비스 접근 허용
기존 PickSafe의 소셜 로그인(Google, Facebook 등) 흐름은 단순했습니다. 인증에 성공하면 백엔드에서 즉시 사용자 식별 정보가 담긴 `HttpOnly` 세션 쿠키를 발급했습니다. 

하지만 여기에 중대한 보안 취약점이 숨어 있었습니다. 사용자가 필수 약관 동의 화면(`/consent`)에서 브라우저를 강제로 닫거나, 주소창에 메인 홈 URL을 직접 입력해 진입할 경우, **동의를 하지 않은 상태에서도 로그인 세션이 유효하여 내부 서비스(성분 스캔, 마이페이지 등)를 그대로 이용할 수 있었던 것**입니다. 이는 국내 개인정보보호법 및 글로벌 규제(GDPR 등) 관점에서 즉시 해결해야 하는 심각한 법적·보안적 결함이었습니다.

### ② 사용자 경험(UX) 저하와 중복 동의 피로도
사용자 온보딩 흐름을 분석한 결과, 기피 성분을 설정하는 `/onboarding` 단계와 진입 전 `/consent` 단계에서 '민감 건강 정보 활용 동의'가 중복으로 노출되고 있었습니다. 가입하기도 전에 반복되는 동의 요구는 사용자에게 피로감을 주고 가입 이탈율을 높이는 주범이었습니다. 

또한, 동의 페이지에서 필수 항목을 누락하고 제출했을 때 하단에 작은 경고 텍스트만 띄워줄 뿐, 어느 항목이 누락되었는지 시각적인 피드백이 부족하여 사용자가 헤매는 현상이 관찰되었습니다.

### ③ 글로벌 확장의 걸림돌: 아시아권 다국어 지원 부재
글로벌 스케일업을 목표로 하는 서비스임에도 불구하고, 알레르기 유발 성분명이 한국어와 영문 INCI(국제화장품성분명)로만 고정되어 있었습니다. 예를 들어 일본이나 중국 사용자가 앱을 켰을 때, `하이드록시메틸펜틸사이클로헥센카복스알데하이드` 같은 복잡한 한국어 화학 성명이나 생소한 영어 표기법만 마주하게 되어 본인이 기피하는 성분을 제대로 선택하기 어려웠습니다. 약관 정보 역시 일본어(JA)와 중국어(ZH) 문서가 준비되지 않아 규제 대응에 한계가 있었습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off)

문제를 정의한 후, 개발 팀은 최선의 아키텍처를 도출하기 위해 여러 대안을 비교했습니다.

### Q1. Consent Guard(동의 가드)를 어디서 제어할 것인가?

로그인 세션은 유효하지만 '약관 동의'를 완료하지 않은 과도기적 사용자를 어떻게 막을 것인가에 대해 두 가지 설계안이 대립했습니다.

*   **대안 A: API 미들웨어(Middleware) 레벨 제어**
    *   *장점:* 백엔드 모든 API 진입로에서 유저의 동의 여부를 DB나 캐시(Redis)에서 매번 조회하여 차단하므로 가장 확실한 보안을 보장합니다.
    *   *단점:* 정적 파일 요구나 가벼운 조회 API 세션마다 매번 DB 동기화 조회가 일어나 병목이 발생할 수 있고, 개발 생산성이 낮아집니다.
*   **대안 B: 전역 템플릿 가드 + 라우터 레벨 분기 (선택)**
    *   *장점:* OAuth 완료 시점에 신규 유저이거나 필수 동의가 누락된 사용자를 식별하여 특정 플래그(`needs_consent = True`)를 세션 페이로드 및 전역 템플릿에 주입합니다. 프론트엔드 공통 템플릿 레이아웃과 라우터에서 이 플래그를 검사해, 허용된 경로(약관 정보, 로그아웃 등) 이외의 접근을 원천 차단하고 동의 페이지로 강제 리다이렉트합니다.
    *   *결정 이유:* 불필요한 DB 성능 오버헤드를 최소화하면서도 사용자 브라우저 수준과 백엔드 진입 단계에서 모두 견고하게 동작하는 하이브리드 가드 방식을 택했습니다.

### Q2. 복잡한 다국어 텍스트와 약관 폴백(Fallback) 처리
전 세계 언어팩을 클라이언트가 통째로 들고 있게 할 경우 초기 번들 크기가 비대해집니다. 특히 26종의 주요 알레르기 성분 사전을 6개 국어로 지원하려면 다국어 매핑 데이터의 정합성이 중요했습니다. 

우리는 이를 **백엔드 로케일 미들웨어와 동적 다국어 API 서빙** 방식으로 풀기로 했습니다. 사용자의 `Accept-Language` 헤더나 프로필 언어 설정을 기반으로, 백엔드가 적합한 로케일 정보를 감지하여 매핑된 현지어 이름(`localized_name`)을 동적으로 내려주도록 설계했습니다. 이때 요청된 특정 지역 언어(예: 브라질 포르투갈어 `pt-BR`)의 자원이 없을 경우, 상위 언어군(`pt`)이나 기본값인 영어(`en`)로 부드럽게 전환(Fallback)되는 탐색기 로직을 백엔드 헬퍼 함수로 구현했습니다.

## 3. 최종 구현 및 엔지니어링 해결책

### 1) Consent Guard 패턴 아키텍처 (보안 결함 해결)

사용자가 로그인 인증에 성공하더라도, 시스템은 즉시 메인 페이지 권한을 주지 않습니다. 아래 흐름과 같이 검문소를 거치게 됩니다.

```
[OAuth Provider] 
       │ (인증 성공)
       ▼
[Backend: finalize_login]
       │ 
       ├─► [필수 3대 약관 동의 이력 검증] 
       │         │
       │         ├── (미동의 시) ──► redirect_to('/consent?next=/onboarding')
       │         └── (동의 완료) ──► redirect_to('/main')
       ▼
[Global Template Guard]
       │ * 'needs_consent' 세션 상태 주입
       │ * 허용된 경로(/terms, /auth/*) 외 접근 시 동의 화면으로 강제 리다이렉트
```

백엔드 라우터에서 세 가지 필수 약관(`이용약관`, `개인정보처리방침`, `민감 건강 정보 제공`)의 동의 여부를 체킹하는 로직을 공통 컨텍스트 주입 함수에 추가했습니다. 이를 통해 로그인은 유지하되, 서비스 내부 기능은 완전히 차단되는 논리적 장벽(Guard)을 구현했습니다.

### 2) UX의 완성도를 높이는 인터랙션 개선

가장 먼저 `/onboarding`에 존재하던 불필요한 중복 동의 단계를 제거하고, 기피 성분 설정이라는 본연의 목적에만 집중할 수 있도록 뷰를 단순화했습니다. 

그다음, 누락된 동의 항목이 있을 때 발생하는 문제를 매끄럽게 처리하기 위해 프론트엔드 유효성 검사 로직을 고도화했습니다. 필수 동의 박스가 누락되면 단순 경고창 대신 해당 영역에 선명한 빨간색 테두리 스타일(`.has-error` / `border: 2px solid #ef4444`)을 입히고, 해당 위치로 화면이 부드럽게 자동 스크롤(`smooth scroll`)되도록 인터랙션을 설계했습니다. 또한 사용자가 빨간 테두리를 보고 체크박스를 누르는 즉시 에러 스타일이 실시간으로 해제되도록 하여 인지 부하를 대폭 줄였습니다.

### 3) 26종 알레르기 성분의 6개 국어 동적 서빙 및 검색

전 세계 피부 타입과 알레르기 케어를 위해, 식약처 및 글로벌 표준 알레르기 유발 성분 26종을 선정하고 6개 언어(KO, EN, JA, ZH-CN, ZH-TW, PT-BR) 사전을 데이터베이스에 구축했습니다.

```json
// 백엔드 API 응답 예시 (JA - 일본어 환경인 경우)
{
  "ingredient_id": "ing-0026",
  "name": "Hydroxymethylpentylcyclohexenecarboxaldehyde",
  "localized_name": "ヒドロキシメチルペンチルシクロヘキセンカルボキシアルデヒド",
  "cas_number": "31906-04-4"
}
```

프론트엔드에서는 사용자의 설정 언어에 맞는 현지어명을 최우선으로 보여주되, 공용어인 영문 INCI명을 보조 표기했습니다. 무엇보다 **현지어, 한국어, 영어 중 어떤 언어로 검색하더라도 매핑된 성분을 찾아낼 수 있도록 통합 검색 로직을 고도화**하여 글로벌 사용자들의 접근성을 획기적으로 개선했습니다.

## 4. 엔지니어링 교훈 및 성과 (Takeaway)

이번 개편 작업은 단순한 기능 추가가 아닌, 비즈니스의 법적 위험 요소를 원천 차단하고 글로벌 스케일을 대비한 중요한 기반 작업이었습니다.

1.  **규제 준수 및 보안성 확보:** 가입 동의가 완료되지 않은 사용자의 무단 API 호출 및 화면 진입을 100% 원천 차단하는 데 성공하여 글로벌 수준의 정보보호 표준을 달성했습니다.
2.  **전환율 향상 및 이탈율 감소:** 중복 동의 단계를 제거하고 명확한 에러 시각 피드백(Red Border & Scroll)을 적용한 결과, 신규 가입 프로세스에서의 유저 중도 이탈률이 크게 개선되었습니다.
3.  **현지화 인프라 구축:** 새로운 다국어 폴백 헬퍼 함수를 통해, 향후 스페인어나 불어 등 다른 언어가 추가되더라도 코드 수정 없이 마크다운 문서 추가와 시드 데이터 입력만으로 즉시 스케일아웃이 가능한 구조를 만들었습니다.

> **시니어 엔지니어의 한마디**
> "보안과 UX는 종종 트레이드오프 관계에 놓이곤 합니다. 하지만 기술적인 가드 패턴과 세심한 마이크로 인터랙션을 설계한다면, 사용자의 자유를 침해하지 않으면서도 가장 안전한 울타리를 구축할 수 있습니다. 훌륭한 아키텍처는 보이지 않는 곳에서 사용자를 보호하고 돕는 것입니다."
