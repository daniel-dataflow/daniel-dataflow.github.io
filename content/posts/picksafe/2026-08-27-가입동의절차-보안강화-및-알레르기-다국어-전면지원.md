안녕하세요, PickSafe 백엔드 에디터입니다. 
서비스가 글로벌 시장으로 확장되고 사용자 규모가 커짐에 따라, 우리는 보안성과 사용자 경험(UX)이라는 두 마리 토끼를 모두 잡아야 하는 기술적 전환점을 마주했습니다. 

이번 포스팅에서는 최근 적용한 **'Consent Guard(가입 동의 보안 가드)'** 아키텍처 설계와 알레르기 성분·약관의 **전면 다국어화(i18n)** 과정을 통해 무엇을 고민하고 해결했는지 공유해 드립니다.

---

## 1. Problem: 우리가 마주한 보안 결함과 UX 마찰

서비스를 운영하며 제품 안정성과 법적 컴플라이언스 관점에서 치명적인 몇 가지 문제를 발견했습니다.

### ① 동의 완료 전 서비스 접근 허용 (보안 취약점)
기존 소셜 로그인(Google/Facebook) 플로우는 `finalize_login` 시점에 사용자의 약관 동의 여부와 무관하게 즉시 인증 쿠키(HttpOnly Session Cookie)를 발급했습니다. 
이로 인해 사용자가 `/consent` 화면에서 동의를 거부하거나, URL을 직접 입력해 우회하려고 해도 이미 로그인된 상태로 메인 홈이나 마이페이지 등 주요 서비스를 자유롭게 이용할 수 있었습니다. 이는 개인정보보호법 및 글로벌 프라이버시 규정 관점에서 시급히 해결해야 할 보안 결함이었습니다.

### ② 분산된 동의 절차와 UX 혼선
`/consent` 화면에 필수 약관과 건강 정보 동의가 존재함에도 불구하고, 이어지는 `/onboarding` 화면의 기피 성분 설정 단계에 건강 정보 동의가 또다시 중복 배치되어 있었습니다. 사용자는 동일한 성격의 동의를 반복해서 마주하며 피로감과 혼란을 느꼈습니다.

### ③ 미체크 항목의 시각적 피드백 부재
동의 페이지에서 필수 항목을 누락하고 제출할 경우, 하단에 텍스트 경고만 덩그러니 표시될 뿐 어떤 체크박스가 누락되었는지 시각적으로 알 수 없었습니다. 에러 원인을 찾기 위해 사용자가 직접 화면을 헤매야 하는 UX 저하가 발생했습니다.

### ④ 글로벌 사용자를 위한 다국어 지원 미흡
일본어(`JA`), 중국어(`ZH-CN`, `ZH-TW`) 등 비한국어권 사용자가 접속했을 때, 온보딩 화면의 알레르기 유발 성분명이 한국어(`하이드록시메틸펜틸사이클로헥센카복스알데하이드` 등)나 영문 INCI명으로만 고정 노출되었습니다. 현지 사용자가 자국어로 성분을 인지하기 어려웠고, 약관 문서 역시 일부 언어만 지원되어 글로벌 서비스로서의 완성도가 떨어졌습니다.

## 2. Trade-off & Architecture: 어떻게 해결할 것인가?

이러한 문제를 해결하기 위해 백엔드와 프론트엔드 전반에 걸친 아키텍처 리팩토링을 단행했습니다.

### 2.1 3대 필수 약관 Consent Guard 강제화
보안 결함을 원천 차단하기 위해 **이중 방어선(Defense in Depth)** 전략을 채택했습니다.

1. **OAuth 리다이렉트 분기 (`auth.py`)**:
   - `finalize_login` 단계에서 신규 사용자이거나 3대 필수 약관(`terms_of_service`, `privacy_policy`, `sensitive_health_data`) 동의 이력이 없는 경우, 메인 홈이 아닌 `/consent?next=/onboarding`으로 강제 리다이렉트합니다.
2. **전역 템플릿 가드 (`shared.py`, `base.html`)**:
   - 세션은 존재하나 필수 동의가 누락된 유저에게 `needs_consent = True` 플래그를 주입합니다.
   - 클라이언트 및 서버 단에서 `/consent`, `/terms`, `/privacy`, `/auth/*`를 제외한 모든 내부 경로 접근을 가로채어 동의 페이지로 리다이렉트시킵니다.

```python
# 예시: 백엔드 전역 가드 및 헬퍼 개념 구조
def check_consent_guard(user_session):
    if user_session.is_authenticated and not user_session.has_agreed_essentials:
        return RedirectResponse(url="/consent", status_code=303)
```

### 2.2 온보딩 흐름의 단순화 (Single Source of Truth)
동의 절차를 오직 `/consent` 화면으로 일원화했습니다. `/onboarding` 페이지 내의 불필요한 중복 건강정보 체크박스 블록을 완전히 제거하여, 사용자가 오롯이 기피 성분 선택에만 집중할 수 있는 깔끔한 온보딩 퍼널(Funnel)을 구축했습니다.

### 2.3 직관적인 에러 인터랙션 (.has-error & Smooth Scroll)
프론트엔드 유효성 검사(Validation) 로직을 개선했습니다. 
- 미체크 필수 항목 발견 시 `.has-error` 클래스를 동적으로 부여하여 선명한 빨간 테두리(`border: 2px solid #ef4444`)를 적용했습니다.
- 동시에 첫 번째 미체크 항목으로 부드럽게 스크롤(`smooth scroll`) 이동시킵니다.
- 사용자가 체크박스를 클릭하는 즉시 실시간으로 빨간 테두리가 해제되도록 구현하여 피드백 루프를 극적으로 단축했습니다.

### 2.4 26대 알레르기 성분 및 약관 6개 국어 전수 현지화
- **DB 시딩 및 다국어 사전 구축**: 공식 알레르기 유발 표준 성분 26종 전체에 대해 6개 국어(KO, EN, JA, ZH-CN, ZH-TW, PT-BR) 사전을 구축(`bin/seed_multilingual_db.py`)했습니다.
- **동적 서빙 API**: 백엔드 엔드포인트(`/allergens/standard-list`, `/users/me/allergens`)에서 클라이언트의 로케일을 감지하여 `localized_name`을 동적으로 서빙합니다.
- **마크다운 폴백 시스템**: `docs/consent/` 디렉토리에 일본어 및 중국어(간체/번체) 약관 파일을 완비하고, `find_consent_file` 헬퍼 함수를 통해 지역 로케일(`pt-BR` 등) 폴백 메커니즘을 안정적으로 동작하게 설계했습니다.

## 3. Takeaway: 엔지니어링 교훈

이번 작업을 통해 얻은 핵심 교훈은 다음과 같습니다.

1. **보안은 미루지 않고 레이어별로 잠그기**
   - 인증(Authentication)과 인가(Authorization)뿐만 아니라, **‘온보딩 상태(Onboarding State)’에 따른 접근 제어** 역시 백엔드 라우터 레벨과 프론트엔드 전역 템플릿 레벨에서 동시에 방어해야 한다는 점을 재확인했습니다. 우회 접근 시도가 원천 차단되는 견고한 구조를 만들었습니다.
2. **UX 디테일이 완성도를 만든다**
   - 아무리 백엔드 보안이 완벽해도 사용자가 에러 원인을 알지 못하면 이탈률이 높아집니다. 빨간 테두리 시각 피드백과 부드러운 스크롤 이동 같은 작은 UX 인터랙션이 서비스의 신뢰도를 결정짓는 핵심 요소임을 배웠습니다.
3. **확장성 있는 글로벌 아키텍처 설계**
   - 하드코딩된 문자열을 다국어 키(`translation keys`)와 로케일 기반 파일 탐색기로 전환하는 작업은 초기 공수가 들지만, 향후 새로운 국가로 진출할 때 폭발적인 생산성 향상을 가져다줍니다. 설계 단계부터 국제화(i18n)를 고려하는 습관의 중요성을 다시 한번 체감했습니다.
