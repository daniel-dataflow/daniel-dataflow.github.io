안녕하세요. **PickSafe** 팀의 백엔드 엔지니어입니다.

글로벌 서비스를 지향하는 프로덕트에서 **‘개인정보 보호법 준수(Compliance)’**와 **‘매끄러운 사용자 경험(UX)’**은 때로 트레이드오프(Trade-off) 관계에 놓이곤 합니다. 법적 규제를 지키기 위해 사용자에게 요구해야 하는 동의 절차는 복잡해지기 쉽고, 이는 곧 유저 이탈로 이어지기 때문입니다.

최근 저희 팀은 소셜 가입 과정에서 발견된 치명적인 보안 루프홀(Loophole)을 해결하는 동시에, 글로벌 사용자를 위해 까다로운 화학 성분명과 약관 데이터를 6개 국어로 유연하게 서빙할 수 있도록 아키텍처를 전면 개편했습니다. 

우리가 마주했던 문제와 이를 우아하게 해결하기 위해 고민했던 기술적 선택지, 그리고 그 과정에서 얻은 교훈을 공유합니다.

---

## 1. 문제 정의: 우리가 해결해야 했던 3가지 보틀넥

글로벌 론칭을 앞두고 보안성 검토와 UX 세션을 진행하면서, 다음과 같은 세 가지 치명적인 결함이 발견되었습니다.

### 1) 가입 동의 전 서비스 접근 허용 (보안 결함)
기존 소셜 로그인(OAuth) 플로우에서는 가입 프로세스가 완료되는 즉시 HttpOnly 세션 쿠키가 발급되었습니다. 문제는 사용자가 필수 약관 동의 화면(`/consent`)에서 브라우저를 뒤로 가거나 메인 주소를 직접 입력할 경우, **동의하지 않은 상태로 메인 홈, 마이페이지 등 로그인 전용 서비스에 접근할 수 있는 심각한 보안 취약점**이 존재했다는 점입니다. 이는 한국 개인정보보호법 및 유럽 GDPR 기준으로 즉각적인 제재 대상이 될 수 있는 중대한 결함이었습니다.

### 2) 중복된 동의 화면과 불친절한 피드백 (UX 저하)
*   **중복 동의:** 약관 동의 페이지(`/consent`)와 기피 성분을 설정하는 온보딩 페이지(`/onboarding`) 두 곳 모두에서 '건강 정보 활용 동의' 체크박스가 중복 노출되어 유저에게 혼란을 주었습니다.
*   **불친절한 UI 피드백:** 동의 페이지에서 필수 항목을 체크하지 않고 제출했을 때, 하단에 텍스트 경고만 표시될 뿐 어떤 체크박스가 누락되었는지 시각적으로 명확히 인지하기 어려웠습니다.

### 3) 글로벌 사용자를 위한 현지화(L10n) 부재
성분 분석 서비스인 PickSafe에서 가장 중요한 데이터는 '성분명'입니다. 하지만 일본, 중국 등 아시아권 유저가 접속했을 때, 알레르기 유발 성분명이 한국어와 생소한 영문 INCI명(예: `Hydroxymethylpentylcyclohexenecarboxaldehyde`)으로만 표시되었습니다. 또한 일본어(JA)와 중국어(ZH-CN, ZH-TW) 사용자를 위한 법적 약관 문서 역시 준비되지 않은 상태였습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off)

문제를 해결하기 위해 아키텍처 관점에서 크게 두 가지 영역의 엔지니어링 의사결정이 필요했습니다.

### 고민 1: 필수 동의 여부를 검증하는 'Consent Guard'를 어떻게 구현할 것인가?

로그인 세션은 유효하지만 필수 동의를 마치지 않은 유저를 차단하는 방식으로 세 가지 대안을 검토했습니다.

| 대안 | 장점 | 단점 | 선택 여부 |
| :--- | :--- | :--- | :--- |
| **A. 개별 API 엔드포인트마다 데코레이터/의존성 주입으로 검증** | 세밀한 권한 제어 가능 | 모든 신규 API 생성 시 개발자가 실수로 누락할 위험 존재, 보일러플레이트 코드 증가 | 미선택 |
| **B. 미들웨어(Middleware) 레벨에서 전역 차단** | 일괄 적용 가능, 누락 위험 없음 | 정적 파일(JS/CSS)이나 공통 번역 API 호출까지 차단하여 화면 렌더링 자체가 깨지는 부작용 발생 | 미선택 |
| **C. 이중 레이어 가드 (OAuth 분기 + 템플릿 전역 플래그 제어)** | 안전한 진입 차단 및 원활한 정적 리소스 로드 보장 | 상태 관리를 백엔드와 프론트엔드가 유기적으로 연동해야 함 | **최종 선택** |

**결정 배경 (C 선택):** 
소셜 로그인 성공 직후 백엔드 라우터에서 사용자의 필수 동의 이력을 조회하여, 미동의 시 즉시 `/consent` 경로로 강제 리다이렉트합니다. 동시에, 백엔드 공통 컨텍스트 주입부(`shared.py`)에서 `needs_consent = True` 플래그를 내려주어, 프론트엔드 최상위 레이아웃(`base.html`)에서 허용된 경로(약관, 인증 관련 API 등) 외의 모든 접근을 원천 차단하고 부드럽게 복귀시키도록 이중 방어막을 구축했습니다.

### 고민 2: 26종 알레르기 유발 성분과 마크다운 약관을 어떻게 다국어화할 것인가?

성분 데이터베이스의 영문 INCI명은 전 세계 공통이지만, 일반 소비자가 체감하는 현지어 번역명은 데이터베이스 레벨에서 동적으로 관리되어야 했습니다.

*   **해결책:** 표준 알레르기 성분 26종에 대해 **6개 국어(KO, EN, JA, ZH-CN, ZH-TW, PT-BR) 사전을 데이터베이스화**했습니다. 클라이언트가 헤더 혹은 쿼리 파라미터로 전송하는 언어셋(Locale)을 분석하여, 백엔드 헬퍼 서비스가 `localized_name`을 동적으로 서빙하는 구조를 설계했습니다.
*   **로케일 폴백(Fallback) 처리:** 사용자의 로케일 값이 세분화되어 들어올 경우(`pt-BR`, `zh-TW` 등), 이에 대응하는 마크다운 약관 파일(`.md`)이 존재하지 않으면 상위 언어군(`pt`, `zh`) 혹은 기본 영어(`en`) 파일로 부드럽게 전환(Fallback)되는 지능형 헬퍼 함수 `find_consent_file`을 구현했습니다.

## 3. 최종 해결 및 구현 디테일

### 1) Consent Guard 아키텍처 구현 (FastAPI & JS)

보안 결함을 해결하기 위해 백엔드와 프론트엔드에 적용한 핵심 로직의 개념 구조입니다. (보안을 위해 내부 코드는 추상화되었습니다.)

```python
# web/backend/app/routers/auth.py (OAuth 로그인 최종 처리 단계)

@router.get("/finalize_login")
async def finalize_login(request: Request, user_service: UserService):
    user = await user_service.get_current_user(request)
    
    # 필수 3대 약관 동의 여부 확인 (이용약관, 개인정보처리방침, 건강정보 동의)
    if not user.has_consented_to_required_terms():
        # 온보딩 흐름으로 유기적 연결을 위해 next 파라미터 지정
        return RedirectResponse(url="/consent?next=/onboarding")
        
    return RedirectResponse(url="/")
```

백엔드의 공통 컨텍스트 생성기(`shared.py`)에서는 요청 흐름을 타는 사용자에게 항상 동의 상태 플래그를 주입합니다.

```python
# web/backend/app/routers/shared.py

def inject_translation(request: Request, user: User = Depends(get_optional_user)):
    context = {}
    if user and not user.has_consented_to_required_terms():
        context["needs_consent"] = True
    else:
        context["needs_consent"] = False
    return context
```

프론트엔드 최상위 템플릿(`base.html`)에서는 이 플래그를 감지하여 허용되지 않은 경로로의 이탈을 클라이언트 사이드에서 즉시 제어합니다.

```javascript
// web/frontend/templates/base.html 내의 가드 스크립트
const needsConsent = {{ needs_consent | tojson }};
const allowedPaths = ['/consent', '/terms', '/privacy', '/auth'];

if (needsConsent && !allowedPaths.some(path => window.location.pathname.startsWith(path))) {
    // 필수 동의가 누락된 경우, 즉시 동의 페이지로 강제 리다이렉트
    window.location.href = "/consent?next=/onboarding";
}
```

### 2) UX 마이크로 인터랙션 개선: Red Border & Smooth Scroll

필수 동의 누락 시 텍스트 경고만 띄우던 기존 방식을 개선하여, 미체크 항목의 테두리를 강조하고 유저가 바로 인지할 수 있도록 스크롤 인터랙션을 적용했습니다.

```javascript
// web/frontend/static/js/consent.js

function validateConsentForm() {
    const requiredCheckboxes = document.querySelectorAll('.required-consent');
    let firstMissing = null;

    requiredCheckboxes.forEach(checkbox => {
        const wrapper = checkbox.closest('.consent-item-wrapper');
        if (!checkbox.checked) {
            // 미체크 항목에 에러 클래스 부여 (CSS에서 border: 2px solid #ef4444 적용)
            wrapper.classList.add('has-error');
            if (!firstMissing) firstMissing = wrapper;
        } else {
            wrapper.classList.remove('has-error');
        }
    });

    if (firstMissing) {
        // 첫 번째 누락된 항목으로 부드럽게 스크롤 이동
        firstMissing.scrollIntoView({ behavior: 'smooth', block: 'center' });
        return false;
    }
    return true;
}
```

### 3) 글로벌 대응: Dynamic Ingredient Localization

일본어 및 중국어 권역 사용자들을 위해 백엔드에서 26종 알레르기 표준 성분명을 언어셋에 맞추어 동적으로 변환해 반환합니다.

```json
// GET /allergens/standard-list?locale=ja 호출 시 반환 예시
{
  "allergens": [
    {
      "id": "allg_01",
      "chemical_name": "Hydroxymethylpentylcyclohexenecarboxaldehyde",
      "localized_name": "ヒドロキシメチルペンチルシクロヘキセンカルボキシアルデヒド"
    },
    {
      "id": "allg_02",
      "chemical_name": "Benzyl Alcohol",
      "localized_name": "ベンジルアルコール"
    }
  ]
}
```

이러한 다국어 맵핑 덕분에 프론트엔드에서는 1순위로 친숙한 현지어 성분을 표시하고, 보조적으로 글로벌 표준 INCI명을 함께 표기하여 글로벌 유저가 자신의 모국어로 알레르기 성분을 정확하게 인지하고 선택할 수 있도록 개선했습니다.

## 4. 엔지니어링 교훈 (Takeaway)

이번 개편을 통해 우리는 보안과 글로벌 UX 고도화라는 두 마리 토끼를 모두 잡을 수 있었습니다. 이 프로젝트를 진행하며 얻은 큰 배움은 다음과 같습니다.

1. **보안은 기본적으로 'Fail-Safe'해야 한다**
   개발자가 매번 작성하는 API 엔드포인트에서 동의 여부를 확인하는 방식은 누수(Leak)가 생기기 쉽습니다. 인프라 혹은 진입점 레이어(라우팅 & 전역 템플릿 가드)에서 세션을 통제하는 중앙 집중식 'Consent Guard' 설계가 시스템의 방어력을 극적으로 높여준다는 것을 깨달았습니다.

2. **단순 텍스트 번역을 넘어선 데이터 현지화(Localization)의 중요성**
   UI 버튼이나 라벨을 번역하는 것만큼이나, 도메인 핵심 데이터(예: 화학 성분명)의 다국어 매핑 테이블을 꼼꼼하게 관리하는 것이 글로벌 프로덕트의 완성도를 결정짓는 핵심 요소임을 배웠습니다.

3. **마이크로 인터랙션은 전환율을 높인다**
   단순히 '체크가 누락되었습니다'라는 경고창을 띄우는 것보다, 누락된 항목을 시각적(Red Border)으로 강조하고 부드러운 스크롤로 포커싱해 주는 디테일이 가입 및 온보딩 단계에서의 사용자 이탈율을 효과적으로 방어해 준다는 가치 있는 경험을 얻었습니다.

앞으로도 PickSafe는 글로벌 사용자들이 안심하고 성분을 스캔할 수 있도록, 견고하고 친절한 엔지니어링을 지향해 나갈 것입니다. 긴 글 읽어주셔서 감사합니다!
