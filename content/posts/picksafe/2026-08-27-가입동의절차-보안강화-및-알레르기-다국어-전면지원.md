안녕하세요. **PickSafe** 팀의 시니어 에디터입니다. 

서비스가 글로벌로 확장되고 유저층이 다양해짐에 따라, 우리는 비즈니스 로직의 견고함뿐만 아니라 **보안(Security)**과 **사용자 경험(UX)**의 결합이라는 큰 과제를 마주하게 됩니다. 

이번 포스팅에서는 최근 도입한 **가입 동의 절차 보안 가드(Consent Guard)**와 **알레르기·약관 전면 다국어화** 프로젝트를 통해, 백엔드 아키텍처와 프론트엔드 UX를 어떻게 유기적으로 개선했는지 공유해 드립니다.

---

## 1. Problem: 우리가 마주한 기술적·보안적 한계

프로덕트를 운영하며 발견한 핵심 문제는 크게 보안 결함, UX 혼선, 그리고 글로벌 지원 미흡이라는 세 가지 축으로 나뉩니다.

### 1.1 소셜 로그인 후 동의 우회 취약점 (Critical Security Flaw)
기존 소셜 로그인(Google/Facebook) 플로우에서는 `finalize_login` 단계에서 사용자의 약관 동의 여부와 관계없이 즉시 HttpOnly 세션 쿠키가 발급되었습니다. 
이로 인해 사용자가 `/consent` 화면에서 동의를 거부하거나, URL 직접 입력 등의 방법으로 우회를 시도할 경우, 이미 인증된 상태로 메인 서비스나 마이페이지 등을 자유롭게 이용할 수 있는 **개인정보보호법상 중대한 보안 취약점**이 존재했습니다.

### 1.2 UX 파편화와 시각적 피드백 부재
- **중복 동의:** `/consent` 화면과 `/onboarding` 화면(기피 성분 설정)에 건강 정보 동의가 중복 배치되어 유저에게 혼란을 줬습니다.
- **불친절한 유효성 검사:** 필수 동의 항목을 누락하고 제출 시 하단 텍스트 경고만 뜰 뿐, 어떤 체크박스가 누락되었는지 시각적 강조(Red Border)나 스크롤 포커싱이 없어 이탈률을 높이는 원인이 되었습니다.

### 1.3 글로벌 사용자를 위한 현지화(Localization) 공백
일본어(`JA`), 중국어(`ZH-CN`, `ZH-TW`) 등 비한국어권 유저가 접속했을 때, 알레르기 유발 성분명이 한국어와 복잡한 영문 INCI명으로만 노출되어 직관적인 인지가 불가능했습니다. 또한, 핵심 약관 문서 역시 일부 언어만 지원되어 글로벌 컴플라이언스 리스크가 있었습니다.

## 2. Architecture & Trade-off: 어떻게 해결할 것인가?

우리는 이 문제를 해결하기 위해 백엔드의 라우팅 레이어와 프론트엔드의 인터랙션을 동시에 개편했습니다.

### 2.1 3대 필수 약관 Consent Guard 강제화
단순히 클라이언트 리다이렉트에 의존하면 프론트엔드 라우팅을 우회할 위험이 있습니다. 따라서 **백엔드와 프론트엔드 양단에서 이중 방어선(Defense in Depth)**을 구축했습니다.

1. **OAuth 로그인 리다이렉트 분기 (`auth.py`):**
   - 신규 유저이거나 필수 3대 약관(`terms_of_service`, `privacy_policy`, `sensitive_health_data`) 동의 이력이 없는 경우, 세션 발급 직후 메인이 아닌 `/consent?next=/onboarding`으로 강제 리다이렉트 시킵니다.
2. **전역 템플릿 가드 (`shared.py`, `base.html`):**
   - 로그인 상태이나 필수 동의가 누락된 유저에게 `needs_consent = True` 플래그를 주입합니다.
   - 전역 템플릿 레벨에서 `/consent`, `/terms`, `/privacy`, `/auth/*` 경로 외의 접근을 원천 차단하고 동의 페이지로 리다이렉트하는 가드 스크립트를 심었습니다.

### 2.2 온보딩 플로우 단순화 (Single Source of Truth)
- `/consent` 화면에서 3대 필수 약관을 일괄 동의하도록 **동의 절차를 일원화**했습니다.
- `/onboarding` 페이지 내 중복되던 건강 정보 체크박스 블록을 완전히 제거하여, 유저가 오직 '기피 성분 선택'이라는 온보딩 본질에만 집중할 수 있도록 단순화했습니다.

### 2.3 실시간 인터랙션과 시각적 피드백
- 미체크 항목 제출 시 `.has-error` 클래스를 동적으로 부여하여 선명한 빨간 테두리(`border: 2px solid #ef4444`)를 적용했습니다.
- `smooth scroll`을 통해 첫 번째 미체크 항목으로 자동 포커싱하고, 유저가 체크박스를 클릭하는 즉시 빨간 테두리가 실시간으로 해제되도록 구현하여 UX 완성도를 높였습니다.

### 2.4 6개 국어 표준 알레르기 사전 및 로케일 폴백 구축
- 공식 알레르기 유발 성분 26종 전체에 대해 6개 국어(KO, EN, JA, ZH-CN, ZH-TW, PT-BR) 사전을 DB에 시딩(`bin/seed_multilingual_db.py`)했습니다.
- 백엔드 API 레이어에서 클라이언트의 로케일을 감지하여 `localized_name`을 동적으로 서빙하고, 프론트엔드에서는 현지어 성분명을 1순위로 노출하되 영문 INCI명을 보조 표기하며 통합 검색을 지원하도록 설계했습니다.
- 아울러 `find_consent_file` 헬퍼 함수를 도입하여 `pt-BR -> pt`, `zh-CN`, `zh-TW` 등 세부 지역 로케일(Locale Fallback)까지 완벽히 지원하는 마크다운 문서 서빙 파이프라인을 구축했습니다.

## 3. Takeaway: 엔지니어링 교훈

1. **보안은 프론트엔드와 백엔드의 협공이다:** 클라이언트 라우팅 가드만 믿고 백엔드 API를 열어두면 보안 취약점으로 직결됩니다. 인증/인가 단계에서 세션과 동의 상태(Consent Status)를 엄격히 결합하는 백엔드 레이어의 가드가 필수적입니다.
2. **글로벌 서비스의 현지화는 데이터 설계부터 시작된다:** 단순히 UI 텍스트 몇 개를 번역하는 것을 넘어, 성분명과 같은 도메인 특화 데이터(`INCI Name` 등)와 마크다운 문서까지 다국어 아키텍처를 초기 단계부터 고려해야 확장성 있는 글로벌 서비스를 만들 수 있습니다.
3. **작은 UX 디테일이 전환율을 바꾼다:** 에러 메시지 텍스트 하나보다, 빨간 테두리와 스무스 스크롤 같은 직관적인 시각 피드백이 유저의 인지 부하를 줄이고 올바른 행동을 유도하는 데 훨씬 강력하다는 것을 다시 한번 확인했습니다.

---

이번 개선을 통해 PickSafe는 법적 규제 준수(Compliance)를 공고히 함 동시에, 글로벌 유저들에게 매끄럽고 신뢰성 있는 온보딩 경험을 제공할 수 있게 되었습니다. 

앞으로도 견고한 아키텍처와 뛰어난 유저 경험을 동시에 추구하는 기술적 도전기를 공유해 드리겠습니다. 감사합니다!
