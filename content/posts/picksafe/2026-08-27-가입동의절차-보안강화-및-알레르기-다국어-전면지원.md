글로벌 서비스를 지향하는 프로덕트에서 **‘사용자 개인정보 보호’**와 **‘매끄러운 온보딩 경험(UX)’**은 종종 트레이드오프(Trade-off) 관계에 놓이곤 합니다. 법적 규제(GDPR, 국내 개인정보보호법 등)를 철저히 준수하기 위해 동의 절차를 강화하면 가입 전환율이 떨어지고, 반대로 가입 단계를 너무 단순화하면 보안 결함이나 법적 리스크가 발생합니다.

최근 우리 개발 팀은 소셜 로그인 이후 필수 약관 동의를 우회할 수 있었던 **보안 취약점**을 해결하고, 동시에 일본, 중국 등 글로벌 사용자를 위한 **알레르기 성분 및 약관 다국어화(L10n)** 작업을 진행했습니다. 

이 과정에서 우리가 마주한 기술적 페인 포인트와 이를 해결하기 위해 설계한 **'Consent Guard(동의 가드) 패턴'**, 그리고 **확장 가능한 다국어 사전 아키텍처**를 소개합니다.

---

## 1. 우리가 마주한 세 가지 문제 (Problem Statement)

### 1.1 소셜 로그인 세션 발급과 동의 우회 취약점 (Security Gap)
기존의 소셜 로그인(OAuth) 흐름에서는 사용자가 로그인에 성공하면 약관 동의 여부와 관계없이 즉시 인증 세션(HttpOnly Cookie)이 발급되었습니다. 
이로 인해 사용자가 `/consent` (동의 페이지)에서 브라우저를 이탈하거나, URL 주소창에 메인 홈 주소를 직접 입력할 경우, **필수 개인정보 및 건강정보 수집에 동의하지 않은 상태로 서비스를 자유롭게 이용할 수 있는 심각한 법적/보안적 홀(Hole)**이 존재했습니다.

### 1.2 동의 요구의 중복과 UX 피드백 부재
*   **중복 노출**: 가입 동의 화면(`consent`)과 회원 맞춤형 기피 성분을 설정하는 온보딩 화면(`onboarding`) 양쪽 모두에서 '건강 정보 활용 동의' 체크박스가 중복 노출되어 유저에게 피로감을 주었습니다.
*   **불친절한 오류 피드백**: 필수 체크박스를 누락한 채 제출했을 때, 화면 하단에 텍스트 경고만 띄워줄 뿐 어떤 항목이 누락되었는지 시각적으로 강조되지 않아 가입 이탈률을 높이는 원인이 되었습니다.

### 1.3 글로벌 유저를 위한 다국어(L10n) 지원 미흡
한국어와 영어(INCI 표준명)로만 고정되어 있던 알레르기 유발 성분명(예: `하이드록시메틸펜틸사이클로헥센카복스알데하이드`)은 일본어나 중국어권 사용자들에게 심각한 인지 장벽이 되었습니다. 또한, 국가별 약관 문서 관리 방식이 파편화되어 있어 새로운 언어 추가 시 대응이 어려운 구조였습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off)

### 2.1 Consent Guard: 미동의 세션 제어 방식 결정

로그인은 되었으나 약관 동의를 완료하지 않은 '불완전한 세션 상태'를 어떻게 제어할 것인가에 대해 두 가지 대안을 고민했습니다.

*   **대안 A: 임시 토큰(Temporary Token) 발행 방식**
    *   소셜 로그인 완료 시 정식 세션 쿠키 대신 짧은 만료 시간을 가진 `temp_token`을 발급하고, 약관 동의가 완료되면 비로소 정식 세션 쿠키를 발급하는 방식입니다.
    *   *장점*: 정식 세션이 없으므로 내부 API가 원천 차단되어 완벽하게 안전합니다.
    *   *단점*: 토큰 전환을 위한 별도의 Redis 상태 관리나 토큰 교환 엔드포인트가 필요하여 아키텍처 복잡도가 증가합니다.
*   **대안 B: 전역 템플릿 가드 + 세션 필터링 방식 (선택)**
    *   정식 세션은 발급하되, 사용자 세션 정보에 `needs_consent` 플래그를 주입하고, 글로벌 라우터 레벨에서 이 플래그가 `True`인 경우 예외 경로(로그아웃, 약관 보기 등)를 제외한 모든 접근을 `/consent`로 강제 리다이렉트하는 가드(Guard)를 세우는 방식입니다.
    *   *장점*: 기존 세션 관리 메커니즘을 그대로 활용하면서, 백엔드와 프론트엔드 양쪽에서 촘촘한 가드를 구현할 수 있어 안전하고 단순합니다.
    *   *선택 이유*: 아키텍처 복잡성을 최소화하면서도, 백엔드 라우터 분기 처리를 통해 우회 접근을 원천 차단할 수 있다고 판단하여 **대안 B**를 선택했습니다.

## 3. 해결 방식 및 구현 디테일 (Engineering Solution)

### 3.1 3대 필수 약관 'Consent Guard' 강제화

문제를 근본적으로 해결하기 위해 OAuth 로그인 리다이렉트 분기점(`auth.py`)과 전역 템플릿 처리부(`shared.py`)에 **Consent Guard**를 장착했습니다.

```python
# [개념 검증용 수도코드 - FastAPI 기반 구조 예시]

@router.get("/auth/callback")
async def finalize_login(request: Request, user_service: UserService):
    user = await user_service.authenticate_oauth_user(request)
    
    # 3대 필수 약관 동의 여부 검증 (이용약관, 개인정보처리방침, 건강정보동의)
    if not user.has_consented_to_required_terms():
        # 동의 미완료 시 온보딩을 'next' 파라미터로 넘기며 가이드 화면으로 강제 리다이렉트
        return RedirectResponse(url="/consent?next=/onboarding")
        
    return RedirectResponse(url="/home")
```

백엔드에서 템플릿을 렌더링할 때 사용되는 공통 컨텍스트 주입부(`shared.py`)에 `needs_consent` 플래그를 추가하고, 프론트엔드 공통 레이아웃(`base.html`)에서 클라이언트 측 리다이렉트 가드를 이중으로 구축했습니다. 이로써 URL 직접 입력을 통한 우회 시도를 완전히 차단했습니다.

### 3.2 중복 동의 제거 및 UX 마이크로 인터랙션 개선
*   **UX 단순화**: `/onboarding` 페이지 내 불필요했던 중복 건강정보 체크박스 블록을 완전히 제거하고 기피 성분 설정에만 집중하게 만들었습니다. 대신, 가입 직전 `/consent` 화면에서 3대 필수 약관을 일괄 동의받도록 정리했습니다.
*   **시각 피드백 기능**: 사용자가 동의 체크를 빠뜨리고 제출하면, 브라우저가 해당 컴포넌트에 `.has-error` 클래스를 즉시 부여하여 선명한 빨간 테두리(`border: 2px solid #ef4444`)를 노출합니다. 또한, `window.scrollTo`를 활용해 첫 번째 미체크 항목으로 부드럽게 스크롤링(`smooth scroll`)되어 유저가 막힘없이 문제를 인지하고 해결할 수 있도록 돕습니다.

### 3.3 6개 국어 표준 알레르기 성분 딕셔너리 구축
글로벌 스케일업을 위해 백엔드에 표준 알레르기 유발 성분 26종에 대한 **6개 국어(KO, EN, JA, ZH-CN, ZH-TW, PT-BR) 번역 데이터베이스**를 시딩(Seeding)했습니다.

사용자의 Accept-Language 헤더나 프로필 설정에 맞춰, `/allergens/standard-list` 엔드포인트는 동적으로 번역된 `localized_name`을 응답합니다.

```json
/* GET /api/v1/allergens/standard-list?lang=ja 응답 예시 */
[
  {
    "id": "allergen_01",
    "standard_name": "Benzyl Alcohol",
    "localized_name": "ベンジルアルコール"
  }
]
```

프론트엔드에서는 이 데이터를 기반으로 사용자의 모국어로 성분명을 표시하되, 국제 표준 규격인 영문 INCI명을 서브 텍스트로 보조 표기하여 신뢰성을 높였습니다. 통합 검색창에서도 `현지어 / 한국어 / 영어` 중 어떤 것으로 검색해도 매칭되도록 검색 로직을 고도화했습니다.

### 3.4 다국어 약관 마크다운 엔진 설계
각 국가별 법적 약관 문서를 깔끔하게 관리하기 위해, 파일 디렉토리 기반의 다국어 약관 마크다운 로더(`find_consent_file`)를 구현했습니다.

```python
# 국가별 로케일 매칭 및 폴백(Fallback) 헬퍼 함수 예시
def find_consent_file(locale: str, doc_name: str) -> Path:
    # 예: pt-BR -> pt, zh-CN -> zh-CN, zh-TW -> zh-TW 매핑 처리
    normalized_locale = normalize_locale(locale) 
    target_path = Path(f"docs/consent/{normalized_locale}/{doc_name}.md")
    
    if target_path.exists():
        return target_path
    return Path(f"docs/consent/en/{doc_name}.md") # 기본 언어(EN) 폴백
```

이 구조 덕분에 새로운 국가(예: 프랑스어 `FR`)의 약관 문서를 추가할 때 백엔드 코드 수정 없이, `docs/consent/fr/` 폴더 하위에 마크다운 문서를 드롭하는 것만으로 신규 언어 약관 배포가 가능해졌습니다.

## 4. 엔지니어링 교훈 (Takeaways)

1.  **보안은 사후 처리가 아니라 설계 단계부터 (Security by Design)**
    세션 쿠키 발급 시점을 고민하지 않고 '로그인 완료 = 권한 획득'으로 안일하게 설계했던 과거의 기술 부채를 해결하며, 세션 상태 세분화(State Segmentation)의 중요성을 다시 한번 깨달았습니다.
2.  **규제 준수와 훌륭한 UX는 공존할 수 있다**
    복잡한 법적 동의 절차라도 적절한 시각적 피드백(Red Border & Smooth Scroll)과 중복 동의 제거를 통해 가입 프로세스의 마찰을 최소화할 수 있었습니다.
3.  **글로벌 스케일링을 위한 사전 준비의 가치**
    처음부터 다국어 사전(Translation Dictionary) 구조와 마크다운 기반 헬퍼를 체계화해 둔 덕분에, 향후 진출 국가가 늘어나더라도 단 몇 분 만에 완벽한 현지화(Localization) 대응을 할 수 있는 확장성 높은 아키텍처를 얻게 되었습니다.
