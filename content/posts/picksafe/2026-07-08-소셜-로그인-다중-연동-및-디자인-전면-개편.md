안녕하세요, PickSafe 팀의 백엔드 엔지니어입니다.

스타트업의 초기 프로토타입 단계에서는 '빠른 시장 검증'을 위해 많은 것들이 단순하게 설계되곤 합니다. 하지만 서비스가 성장하고 유저 피드백이 쌓이면서, 초기 디자인 부채와 단순했던 아키텍처는 비즈니스 확장과 보안을 위협하는 요소가 되기 마련입니다.

최근 PickSafe 팀은 유저 가치와 보안성, 그리고 개발 생산성이라는 세 마리 토끼를 모두 잡기 위해 **1:N 다중 소셜 계정 연동 시스템을 구축**하고, **브랜드 아이덴티티에 맞춘 전체 UI/UX 리뉴얼**을 단행했습니다. 

단순한 기능 추가를 넘어, 어떠한 기술적 고민을 통해 아키텍처를 안전하게 고도화했는지 그 과정을 공유합니다.

---

## 1. [Problem] 기존 소셜 로그인 구조의 한계와 비즈니스 요구사항

기존 PickSafe의 사용자 테이블은 한 명의 사용자가 단 하나의 소셜 계정(1:1 관계)만 연동할 수 있도록 설계되어 있었습니다. 

이 구조는 다음과 같은 두 가지 치명적인 문제를 야기했습니다.
1. **데이터 유실 및 계정 충돌:** 구글로 가입한 사용자가 며칠 후 동일한 이메일 주소를 사용하는 페이스북으로 로그인을 시도할 때, 기존 계정 정보가 덮어씌워져 유실되거나 연동 정보가 꼬이는 오류가 빈번히 발생했습니다.
2. **브랜드 미스매치:** 성분 체크 및 큐트한 로고 컨셉을 가진 서비스임에도 불구하고, 초기 화면이 다크 네이비 톤의 투박한 디자인으로 구현되어 타겟 고객층(여성 및 꼼꼼한 성분 분석 소비자)의 첫인상 만족도가 낮았습니다.

또한, 로컬 개발 환경에서 이메일 인증 기반 회원가입 흐름을 검증할 때 외부 이메일 API의 샌드박스 제한(등록된 메일 외 수신 불가)으로 인해 개발 속도가 지체되는 병목 현상도 존재했습니다.

---

## 2. [Trade-off & Decision] 기술적 고민과 대안 비교

### 고민 1: 소셜 로그인 정보, 'User'에 둘 것인가 외래키로 분리할 것인가?

*   **대안 A: 기존 `users` 테이블에 소셜 ID 컬럼들을 계속 추가 (1:1 유지)**
    *   *장점:* 구현이 단순하고 쿼리가 가볍습니다.
    *   *단점:* 추후 새로운 소셜 로그인(네이버, 카카오 등)이 추가될 때마다 테이블 스키마를 변경해야 하며, 한 사용자가 동일 플랫폼의 여러 계정을 연동하는 시나리오 대응이 불가능합니다.
*   **대안 B: `user_social_accounts` 매핑 테이블 신설 (1:N 관계 분리) [선택]**
    *   *장점:* 사용자는 한 계정에 구글, 페이스북 등 다양한 소셜 계정을 안전하게 다중 연동할 수 있습니다. 스키마 확장성이 뛰어납니다.
    *   *단점:* 로그인 시 매핑 테이블을 거쳐야 하므로 JOIN 쿼리가 추가됩니다.

**선택의 이유:** 
서비스의 지속 가능성과 유저 경험을 최우선으로 고려하여 **대안 B**를 선택했습니다. 인덱스 최적화를 통해 JOIN으로 인한 미미한 성능 손실은 충분히 커버할 수 있다고 판단했습니다.

### 고민 2: 이메일 기반 자동 연동 시 발생할 수 있는 '계정 하이재킹(Hijacking)' 차단하기

동일한 이메일을 가진 소셜 요청이 올 때, 기존 계정과 자동으로 매핑해 주면 유저 사용성이 극대화됩니다. 그러나 여기에 숨겨진 **보안 취약점**이 있습니다. 

만약 공격자가 특정 이메일로 소셜 인증이 검증되지 않은 가짜 소셜 계정을 만들어 로그인을 시도할 때, 시스템이 이를 기존 유저의 계정과 무조건 연동해 버린다면 타인의 계정을 무단 점유(Hijacking)할 위험이 생깁니다.

```
[보안 위협 시나리오]
공격자가 임의의 이메일(victim@email.com)로 인증되지 않은 소셜 계정 생성 
-> PickSafe에 해당 소셜로 로그인 시도 
-> 시스템이 이메일만 보고 victim의 실제 계정과 연동 처리 (취약점 발생!)
```

**해결책:**
우리는 OAuth 제공자(Provider)로부터 전달받은 페이로드 중 `email_verified` 속성을 필수로 검증하도록 로직을 설계했습니다. 

*   `email_verified == True` (신뢰 가능한 소셜 계정) $\rightarrow$ **다중 연동 및 자동 로그인 허용**
*   `email_verified == False` (신뢰 불가능한 소셜 계정) $\rightarrow$ **연동 거부 및 추가 이메일 인증 요구**

## 3. [Resolution] 최종 구현 및 엔지니어링 아키텍처

### 3.1. DB 스키마 고도화 및 자가 진단(Self-Healing) 마이그레이션
신규 테이블 `user_social_accounts`를 생성하여 외래키(FK) 관계를 맺어 주었습니다. 

또한, 배포 환경에서의 유연성을 위해 애플리케이션 시작 시 `users` 테이블에 특정 관리자 권한 관련 필드(`role`)가 유실되어 에러가 발생하는 경우, 백엔드가 직접 이를 감지하여 DDL(`ALTER TABLE users ADD COLUMN IF NOT EXISTS...`)을 안전하게 실행하는 자가 진단 마이그레이션 코드를 가동하여 서버 안정성을 한 단계 끌어올렸습니다.

### 3.2. 이메일 발송 개발용 폴백(Fallback) 모드 도입
로컬 개발 환경에서 이메일 인증 테스트 시 외부 메일 발송 제한으로 병목이 걸리던 문제를 해결하기 위해, 개발용 폴백 패턴을 적용했습니다.

```python
# email_service.py (개념적 구현 예시)
async def send_verification_email(email: str, token: str):
    if settings.ENV == "dev":
        # 외부 API 호출 실패에 대비한 폴백 처리
        logger.info(f"[이메일 발송 개발용 폴백] 수신처: {email}")
        logger.info(f"인증 링크: /verify?token={token}")
        return True
    
    try:
        await external_email_api.send(email, token)
    except ExternalAPIError as e:
        logger.error(f"Email API Error: {e}")
        raise
```
이로 인해 로컬 개발 및 QA 환경에서 API 호출 에러에 구애받지 않고, 터미널에 콘솔 출력된 링크를 통해 즉각적인 인증 흐름 테스트가 가능해져 **개발 생산성이 200% 이상 훌륭하게 개선**되었습니다.

### 3.3. 브랜드 언어(Identity) 기반 UI/UX 전면 리뉴얼
PickSafe의 시그니처 룩앤필을 구축하기 위해 로고 이미지의 색상 팔레트인 **민트 그린, 파스텔 핑크, 크림색**을 기본 테마 컬러로 지정했습니다.

*   **CSS Custom Variables 적용:** 다크 네이비 테마에서 파스텔 톤 테마로의 매끄러운 전환을 위해 CSS 전반을 커스텀 변수 구조로 개편하여 유지보수성을 극대화했습니다.
*   **인터랙티브 로고 적용:** 기본 로고 이미지에 마우스 오버 시 위트 있게 반응하는 윙크 그래픽으로 상호 전환되는 CSS/JS 효과를 가미하여, 사용자가 서비스를 이용할 때 느끼는 감성적인 디테일을 높였습니다.

## 4. [Takeaway] 이번 프로젝트를 통해 얻은 엔지니어링 교훈

1.  **아키텍처 설계와 보안은 늘 동전의 양면과 같다:** Convenience(편의성)를 높이려 할 때(자동 이메일 매핑) 필연적으로 Security(보안) 허점이 생길 수 있음을 인지하고, `email_verified`와 같은 엄격한 검증 장치를 촘촘히 덧대어 비즈니스적 리스크를 선제적으로 방지해야 합니다.
2.  **개발 환경의 DX(Developer Experience) 투자는 곧 속도로 환원된다:** 이메일 샌드박스 제한 같은 사소한 병목을 방치하지 않고 개발용 폴백(Fallback) 처리를 견고히 함으로써, 팀의 전반적인 QA 속도와 개발 스프린트 주기를 대폭 단축할 수 있었습니다.
3.  **코드의 품질은 사용자 경험(UX)과 일치해야 한다:** 견고하게 설계된 백엔드 비즈니스 로직은 결국 프론트엔드의 부드럽고 친근한 사용자 인터페이스와 시너지를 낼 때 비로소 진정한 비즈니스 가치로 완성됩니다.

앞으로도 PickSafe는 탄탄한 아키텍처 위에서 사용자의 목소리를 기민하게 반영하는 안전하고 가치 있는 서비스를 만들어 가겠습니다. 긴 글 읽어주셔서 감사합니다!
