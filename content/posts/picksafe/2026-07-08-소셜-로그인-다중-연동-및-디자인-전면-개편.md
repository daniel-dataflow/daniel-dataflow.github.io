안녕하세요, PickSafe 개발팀입니다. 

이번 포스팅에서는 최근 진행한 **1:N 소셜 계정 다중 연동 아키텍처 개편**과 **로컬 개발 환경(DX) 최적화**, 그리고 브랜드 아이덴티티를 살린 **UI/UX 전면 리뉴얼** 과정을 공유하고자 합니다. 

스타트업이나 프로덕트를 빠르게 성장시키는 과정에서 마주치는 구조적 한계를 어떻게 해결했는지, 기술적 고민과 트레이드오프(Trade-off)를 중심으로 풀어보겠습니다.

---

## 1. Problem: 무엇을 해결해야 했는가?

프로덕트가 고도화됨에 따라 기존 인증 및 아키텍처 구조에서 다음과 같은 명확한 한계점(Pain Points)이 드러났습니다.

1. **소셜 계정 연동의 1:1 제약과 데이터 유실 위험**
   * 기존 구조는 `users` 테이블에 소셜 정보가 종속되어 있어, 사용자가 구글과 페이스북 등 여러 소셜 계정을 하나의 서비스 계정에 매핑할 수 없었습니다. 
   * 동일한 이메일 주소를 사용하는 서로 다른 소셜 로그인을 시도할 경우, 기존 계정 정보가 덮어씌워지거나 데이터가 유실되는 치명적인 오류가 발생했습니다.
2. **로컬 개발 환경(DX)에서의 외부 API 병목**
   * 회원가입 및 인증 과정에서 외부 이메일 발송 API(Resend 등)를 사용하고 있으나, 샌드박스 환경의 수신자 제한 정책(등록된 이메일만 수신 가능)으로 인해 로컬 개발 및 테스트 시 불필요한 병목이 발생했습니다.
3. **브랜드 아이덴티티와 룩앤필(Look & Feel)의 괴리**
   * 기존의 무거운 다크모드 위주 디자인은 PickSafe의 친근하고 아기자기한 로고 및 성분 분석 서비스 컨셉과 일치하지 않았습니다. 사용자 경험(UX) 관점에서 일관성 있는 비주얼 언어로의 전환이 시급했습니다.

---

## 2. Technical Solution & Trade-off: 어떻게 해결했는가?

### ① Database Architecture: 1:1 관계에서 1:N 관계로의 정규화
기존의 강결합 구조를 해소하기 위해 데이터베이스 스키마를 리팩토링했습니다.

* **엔티티 분리 (`UserSocialAccount` 도입):** 
  `users` 테이블과 소셜 인증 정보를 분리하여, 하나의 계정에 여러 개의 소셜 프로바이더(구글, 페이스북 등)를 안전하게 연결할 수 있는 `user_social_accounts` 매핑 테이블을 신설했습니다.
* **자가 진단형 마이그레이션 적용:**
  서버 부팅 시점(`main.py` 기동 단계)에 필수 스키마 및 컬럼(예: 권한 관리를 위한 `role` 컬럼 등)의 유무를 체크하고, 누락 시 안전하게 DDL을 실행(`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`)하는 방어적 초기화 로직을 도입하여 배포 안정성을 높였습니다.

### ② 보안 필터 및 동일 이메일 매핑 로직 강화
계정 통합 과정에서 발생할 수 있는 보안 취약점(타인 계정 무단 점유 등)을 방어하기 위해 인증 로직을 정교화했습니다.

* **`email_verified` 검증 필수화:** 
  OAuth 프로바이더로부터 수신한 이메일이 실제 소유자의 것인지 검증하기 위해 `email_verified: True` 상태인 경우에만 다중 연동(1:N) 및 자동 로그인을 허용하도록 제한했습니다.
* **무단 점유 방지:** 
  이메일 검증이 완료되지 않은 요청은 기존 계정과 연결을 거부하여 보안성을 확보했습니다.

### ③ DX(Developer Experience)를 위한 스마트 폴백(Fallback) 모드
* 외부 API 의존성을 낮추기 위해 개발 환경(`ENV=dev`)에서는 이메일 발송 실패(403 에러 등) 시 예외를 스킵하고, **인증 링크를 터미널 콘솔 로그에 직접 출력(`[이메일 발송 개발용 폴백]`)**하도록 구현했습니다.
* 이를 통해 외부 네트워크 환경이나 샌드박스 제약에 구애받지 않고 원활한 가입 및 인증 플로우 테스트가 가능해졌습니다.

### ④ 디자인 시스템 전면 개편 및 마이크로 인터랙션
* **파스텔 톤 디자인 언어 정립:** 
  로고 이미지에 사용된 민트 그린(`5ABFAD`), 파스텔 핑크(`F4A5B0`), 크림색(`FFF8F0`)을 CSS 커스텀 변수로 정의하고, 가독성과 친근감을 높이는 `Nunito` 폰트를 전면 적용했습니다.
* **반응형 인터랙션:** 
  헤더 로고에 마우스 오버 시 윙크하는 이미지(`picksafe_log_on.png`)로 전환되는 디테일을 추가하여 브랜드의 생동감을 더했습니다.

## 3. Takeaway: 엔지니어링 교훈

이번 아키텍처 개편을 통해 다음의 인사이트를 얻을 수 있었습니다.

1. **확장성을 고려한 초기 설계의 중요성**
   * 인증 시스템과 같은 코어 도메인은 처음부터 다중 연동(1:N) 가능성을 열어두거나 쉽게 확장할 수 있는 구조로 분리하는 것이 기술 부채를 줄이는 지름길임을 재확인했습니다.
2. **개발자 경험(DX)이 곧 생산성**
   * 로컬 폴백 모드 도입처럼 사소해 보이는 디테일이 개발 속도를 크게 높이고, 불필요한 환경적 제약을 제거해 준다는 것을 배웠습니다.
3. **기술과 비즈니스/UX의 일치**
   * 백엔드 안정성과 보안을 탄탄하게 다지는 동시에, 브랜드 아이덴티티에 맞는 UI/UX를 일관되게 적용하는 것이 프로덕트의 완성도를 결정짓는 핵심 요소입니다.

앞으로도 PickSafe는 안정적인 아키텍처와 뛰어난 사용자 경험을 동시에 달성하기 위한 기술적 도전을 지속해 나갈 것입니다. 

읽어주셔서 감사합니다.
