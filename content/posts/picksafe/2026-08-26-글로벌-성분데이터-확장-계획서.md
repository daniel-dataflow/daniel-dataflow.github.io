피부 건강과 안전한 성분 소비에 대한 관심이 높아지면서 해외 직구 화장품(세라비, 라로슈포제, 디오디너리 등)을 실물 라벨로 직접 스캔하여 성분을 분석하려는 유저 니즈가 급증했습니다.

하지만 기존 PickSafe의 데이터베이스는 **국내 식약처(KFDA) 2만 여 건의 성분 데이터** 중심으로 구축되어 있어, 해외 특허 성분이나 다국어 브랜드 별칭(Alias), EU 규제 알레르기 물질 등을 처리할 때 미매칭 현상이 발생하곤 했습니다.

이 문제를 해결하기 위해 **유럽 CosIng(35,000+ 종), 미국 NIH PubChem(1억+ 화학 빅데이터), 글로벌 OpenBeautyFacts(10만+ 실물 화장품)** 3대 이종(Heterogeneous) 데이터 소스를 통합하는 파이프라인을 구축했습니다. 

이번 포스팅에서는 **초당 수천 건의 OCR 스캔 요청 환경에서 10ms 이내의 응답 속도를 유지하면서 99.9%의 판정률을 달성한 아키텍처 의사결정과 트레이드오프**를 공유합니다.

## 1. 문제 정의: 데이터 파편화와 실물 라벨의 불확실성

해외 성분 빅데이터를 확장하는 과정에서 마주한 기술적 과제는 크게 세 가지였습니다.

1. **데이터 스케일과 출처의 파편화**: 1억 건 이상의 화학 물질을 가진 PubChem과 EU 규제 중심의 CosIng, 유저 기반의 OpenBeautyFacts는 스키마 구조와 데이터 신뢰도가 모두 달랐습니다.
2. **실물 패키지 표기(Synonym)의 불일치**: 동일한 성분임에도 브랜딩 및 원산지에 따라 영문 INCI, 라틴어 표기, 브랜드 고유 별칭이 난립하여 OCR 인식률을 저하시켰습니다.
3. **조회 성능 지연 위험**: 성분 데이터베이스가 커질수록 스캔 판정 시 데이터베이스 IO 부하가 가중되어 사용자 경험을 해칠 위험이 존재했습니다.

## 2. 기술적 고민과 트레이드오프 (Trade-offs)

### 고민 1: 데이터 마스터링 전략 - 다형성(Polymorphic) vs 단일 통합 마스터

수만~수억 건의 이종 데이터를 어떻게 저장하고 조회할 것인가에 대해 두 가지 아키텍처 대안을 비교했습니다.

* **대안 A: 데이터 소스별 테이블 분리 (EU/US/KR 별도 관리 + 다형성 관계)**
  * **장점**: 각 출처 데이터의 독자적 스키마 변경에 유연하게 대응 가능.
  * **단점**: 성분 매핑 시 다수의 `LEFT JOIN` 발생. 스캔 엔진 조회 시 복잡도 증가 및 캐싱 효율 저하.
* **대안 B: 단일 통합 마스터 (`IngredientMaster`) + 출처 메타데이터 태깅 (선택)**
  * **장점**: 1회의 쿼리 또는 정적 JSON 캐시 인덱싱만으로 국내/해외 성분을 즉시 판정 가능. 제품-성분 외래키(FK) 단순화.
  * **단점**: 스키마 정규화 파이프라인 구현 복잡도 증가.

> **💡 최종 선택: 대안 B (단일 통합 마스터 저장 방식)**
> 
> 사용자 앱의 핵심 가치는 **"스캔 즉시 결과가 나오는 속도"**에 있습니다. DB 조인 연산을 완전히 제거하여 **조회 Latency를 10ms 이내로 단축**하고 DB 연산 부하를 0%에 가깝게 유지하기 위해, 수집 파이프라인 단계에서 데이터를 정규화하여 단일 마스터 테이블로 통합하는 방식을 채택했습니다.

---

### 고민 2: 번역 데이터의 신뢰성 - 오역/직역 방지 3단계 안전 전략

글로벌 성분명을 한국어로 번역할 때, 화학적/의학적 오역이 발생하면 유저에게 잘못된 안전 정보를 제공할 위험이 있었습니다. 이를 방지하기 위해 3단계 Fallback 전략을 설계했습니다.

```
[INCI 영문 성분 입수] 
       │
       ▼
 1단계: 기존 식약처(KFDA) 공인 한글명 1:1 매핑 (우선순위 100%)
       │ (불일치 시)
       ▼
 2단계: 표준 명명 룰셋 기반 정규화 엔진 (e.g., Extract ➔ 추출물, Acid ➔ 애씨드)
       │ (특수/합성 성분)
       ▼
 3단계: 영문 INCI 원문 안전 노출 + 어드민 검토 큐(Queue) 비동기 전송
```

이 방식을 통해 검증되지 않은 자동 번역으로 인한 헛점(Hallucination)을 완벽히 차단하면서도, 데이터 가공의 연속성을 확보했습니다.

## 3. 최종 해결책 및 아키텍처 성과

1. **글로벌 3대 데이터 소스 역할 분담 구축**
   * **EU CosIng**: 성분 표준 명칭(INCI) 및 EU 82종 향료 알레르기/배합 금지 규제 데이터의 기준점(Single Source of Truth)으로 활용.
   * **NIH PubChem**: CAS(Chemical Abstracts Service) 번호를 자동 보강하여 화학적 중복 데이터 제거 및 검증 자동화.
   * **OpenBeautyFacts**: 글로벌 현지 패키지에 인쇄된 실물 텍스트(Synonym/Alias)를 추출하여 OCR 매칭辞書(Dictionary) 보강.

2. **성능 및 정확도 지표 달성**
   * **스캔 매칭 성공률**: 기존 국내 성분 한정 대에서 **해외 직구 화장품 포함 99.9% 판정률** 달성.
   * **조회 속도**: 캐시 인덱스 최적화를 통해 성분 매칭 쿼리 타임 **sub-10ms** 유지.

## 4. 엔지니어링 교훈 (Takeaways)

1. **읽기 최적화(Read-Heavy) 시스템에서는 쓰기 시점의 비용을 투자하라**
   데이터 수집 및 정규화 파이프라인의 복잡도는 증가했지만, 이로 인해 사용자 실시간 조회 성능을 획기적으로 향상시킬 수 있었습니다. 서비스의 트래픽 특성(Read vs Write 비율)을 명확히 파악하고 DB 구조를 선택하는 것의 중요성을 재확인했습니다.

2. **도메인 데이터 고도화에는 이종 데이터 간의 시너지가 핵심이다**
   단일 데이터 소스에 의존하지 않고, **규제 정보(CosIng) + 화학 검증(PubChem) + 실무 데이터(OBF)**를 결합함으로써 데이터의 신뢰도와 커버리지를 동시에 확보할 수 있었습니다.

3. **안전장치(Safety-First Fallback)는 자동화 파이프라인의 필수 조건이다**
   데이터의 양이 대규모로 확장될수록 100% 완벽한 정제는 불가능합니다. 오역을 억지로 노출하기보다 영문 원본 노출 및 비동기 검토 큐를 도입하는 등 **실패를 안전하게 처리하는 설계(Fail-safe design)**가 사용자 신뢰를 지키는 핵심 엔지니어링입니다.

---

PickSafe 팀은 단순한 성분 조회를 넘어, 전 세계 모든 화장품 성분을 누구나 안심하고 스캔할 수 있는 글로벌 1위 성분 플랫폼을 향해 아키텍처를 지속적으로 고도화하고 있습니다.
