안녕하세요. 화장품 성분 분석 서비스 **PickSafe**의 백엔드 에디터입니다.

국내 화장품 성분 데이터 기반(2만여 종)을 성공적으로 구축한 PickSafe는 이제 시야를 넓혀 **글로벌 직구 화장품 시장**으로 향합니다. 
이번 포스팅에서는 **EU CosIng(35,000+), 미국 NIH PubChem(1억+), OpenBeautyFacts(10만+)**의 이질적인 3대 글로벌 데이터 소스를 어떻게 단 하나의 파이프라인으로 통합하고, **스캔 속도 10ms 이내, 매칭률 99.9%**를 달성했는지 그 기술적 의사결정 과정을 공유합니다.

---

## 1. Problem: 글로벌 직구 화장품 스캔의 기술적 한계

국내 유통 제품 중심의 기존 시스템은 해외 직구 화장품(라로슈포제, 세라비, 디오디너리 등)을 마주했을 때 두 가지 치명적인 병목에 부딪혔습니다.

1. **독자적 해외 성분 및 시노님(Alias) 누락**:
   - 국내 식약처 데이터베이스에 등록되지 않은 최신 펩타이드, 특허 바이오 추출물 등이 존재합니다.
   - 특히 실물 라벨에 인쇄된 브랜드별 영문/다국어 표기 방식(이명)이 다양하여 OCR 인식 후 매칭 실패율이 높아졌습니다.
2. **이질적인 데이터 소스의 파편화**:
   - 규제 기준을 제공하는 유럽 CosIng, 화학적 CAS 번호가 방대한 미국 PubChem, 실제 제품 패키지 정보를 가진 OpenBeautyFacts의 데이터 구조가 모두 달랐습니다. 이를 무작정 수집하면 데이터 정합성이 깨지고 쿼리 성능이 급격히 저하될 위험이 있었습니다.

---

## 2. Trade-off: 아키텍처 설계 고민과 대안 비교

이질적인 대규모 데이터를 어떻게 구조화할 것인가에 대해 팀 내에서 치열한 논의가 오갔습니다.

### 대안 A: 데이터 소스별 독립 테이블 분리 (Polymorphic / Multi-Table)
- **구조**: `KfdaIngredient`, `CosingIngredient`, `PubChemIngredient` 등 소스별로 테이블을 나누고 통합 뷰(View)나 애플리케이션 레벨에서 조인.
- **장점**: 각 소스 고유의 스키마 변경에 유연하게 대응 가능.
- **단점**: 사용자가 제품을 스캔할 때 여러 테이블을 조인하거나 순차 조회해야 하므로 **스캔 응답 속도가 느려짐 (LATENCY 증가)**. 제품-성분 외래키(`ProductIngredient`) 설계가 매우 복잡해짐.

### 대안 B: 단일 통합 마스터 테이블 + 출처 태그 (`IngredientMaster` + `data_source`) — *[최종 채택]*
- **구조**: 기존 `IngredientMaster` 테이블을 유지하되, `data_source` (`kfda` | `cosing` | `openbeauty` | `manual`) 컬럼을 추가하여 하나의 테이블에 통합 수용.
- **장점**: 
  - **초고속 스캔 (10ms 이내)**: 단 1회의 인덱스 쿼리 또는 정적 JSON 캐시 조회로 판정 가능 (DB 부하 최소화).
  - **관계 단순화**: 제품과 성분 간의 외래키 관계가 깔끔하게 유지됨.
  - **어드민 확장성**: `data_source` 필터링 및 뱃지 UI 구현 용이.
- **단점**: 소스별로 상이한 속성(Columns)을 모두 수용할 수 있도록 스키마를 유연하게(JSONB 활용 등) 설계해야 함.

## 3. Engineering Challenge: 오역 방지와 데이터 정규화 파이프라인

글로벌 데이터를 통합할 때 가장 경계해야 할 것은 **기계 번역으로 인한 성분명 오역**입니다. 잘못된 성분 정보는 사용자 안전에 직접적인 영향을 주기 때문에, 3단계 안전 대처 전략(Safety Strategy)을 파이프라인에 녹였습니다.

```
[원천 데이터 수집] ➔ [1단계: 식약처 공인명 100% 승계] ➔ [2단계: 표준 명명 룰셋 적용] ➔ [3단계: 원문 노출 및 어드민 큐]
```

1. **1단계 (기존 식약처 공인 한글명 우선 승계)**: 
   - 국내 식약처에 이미 등록된 INCI는 기존 공인 한글명을 1:1 매핑하여 오역 가능성을 원천 차단합니다.
2. **2단계 (표준 명명 룰셋 기반 정규화)**: 
   - `Extract` ➔ `추출물`, `Oil` ➔ `오일`, `Acid` ➔ `애씨드` 등 대한화장품협회 표준 어미 룰셋을 적용하여 일관성을 확보합니다.
3. **3단계 (영문 원본 안전 노출 & 어드민 검토 큐)**: 
   - 정규화가 모호한 특수 합성 성분은 영문 INCI 원문을 기본 안전 노출하고, 내부 어드민 검토 큐로 라우팅하여 전문가가 검증할 수 있도록 설계했습니다.

## 4. Takeaway & Conclusion

이번 글로벌 성분 DB 확장 프로젝트를 통해 다음과 같은 엔지니어링 교훈을 얻었습니다.

* **"성능과 단순성의 균형"**: 대규모 데이터를 다룰 때 마이크로서비스나 분산 스토리지만큼이나 중요한 것은 **실제 서비스의 읽기 패턴(Read Pattern)**에 맞춘 단순한 단일 테이블 전략입니다. 10ms 이내의 응답 속도를 지켜낸 덕분에 글로벌 데이터가 추가되어도 사용자 경험은 쾌적하게 유지됩니다.
* **"도메인 특화 안전 장치"**: 단순 데이터 파이프라인 구축을 넘어, 화장품 도메인 특유의 규제(EU 82종 알레르기 기준 등)와 오역 리스크를 방어하는 3단계 검증 프로세스를 코드가 아닌 아키텍처 레벨에서 정의한 것이 성공의 핵심이었습니다.

PickSafe는 이제 국내를 넘어 전 세계 모든 화장품을 99.9% 정확도로 스캔할 수 있는 강력한 기술적 기반을 갖추었습니다. 앞으로도 더 빠르고 신뢰할 수 있는 성분 분석 인프라를 만들어 나가겠습니다.

감사합니다.
