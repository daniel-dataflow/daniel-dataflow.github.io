안녕하세요. PickSafe 개발팀입니다. 

서비스를 정식으로 오픈한 뒤, 우리는 데이터와 사용자 경험(UX) 측면에서 동시에 두 가지 흥미로운(?) 과제를 마주했습니다. 하나는 대시보드에 찍히는 방문자 수의 신뢰성 문제였고, 다른 하나는 모바일 화면에서 간헐적으로 무너지는 UI 레이아웃이었습니다.

이번 포스팅에서는 **서버 단에서의 봇 트래픽 정제 과정(Backend)**과 **다양한 모바일 디바이스를 대응하기 위한 뷰포트 최적화 과정(Frontend)**에서 우리가 어떤 고민을 했고, 왜 그런 방식을 선택했는지 공유해 드리고자 합니다.

---

## 1. 문제 정의 (Problem)

### ① 봇(Bot) 트래픽으로 인한 통계 왜곡
서비스 오픈 초기, 방문자 분석(Analytics) 대시보드를 확인하던 중 이상 기류를 감지했습니다. 실제 마케팅 집행 규모나 인지도에 비해 일일 방문자 수(UV)가 지나치게 높게 집계되고 있었습니다.

원인을 분석해 보니 Googlebot, Bingbot, Yandex 같은 검색엔진 크롤러뿐만 아니라 AhrefsBot, 바이트댄스 스파이더, 그리고 `python-requests`, `HeadlessChrome`, `curl`, `wget` 등을 이용한 각종 악성 자동화 크롤러들이 우리의 분석 엔드포인트를 무차별적으로 두드리고 있었습니다. 이로 인해 **실제 서비스의 성장을 가늠할 수 있는 순수 사용자 메트릭이 완전히 오염**되고 있었습니다.

### ② 모바일 '인기 제품 랭킹' 섹션의 레이아웃 왜곡
백엔드에서 데이터를 정제하는 동안, 프론트엔드에서는 모바일 UI 이슈가 보고되었습니다. 홈 화면의 '인기 화장품 랭킹' 섹션에서 특정 모바일 기기(특히 화면이 좁은 소형 디바이스)로 접속할 경우, 제품 썸네일 이미지 공간이 찌그러지거나 긴 상품명이 텍스트 영역을 탈출해 레이아웃이 깨지는 현상이 발생했습니다.

---

## 2. 기술적 고민과 대안 비교 (Trade-off)

### [Backend] 봇 트래픽 필터링: 어디서 차단할 것인가?

> **대안 A: CDN/WAF(Cloudflare 등) 레벨에서 전면 차단**
> - **장점**: 어플리케이션 서버까지 트래픽이 도달하지 않아 서버 리소스를 아낄 수 있음.
> - **단점**: 커스텀 크롤러나 정교한 스크래핑 봇을 세밀하게 제어하기 어렵고, 사내 인프라 정책 변경 비용이 발생함.

> **대안 B: 어플리케이션 미들웨어(Middleware) 레벨에서 User-Agent 분석 및 필터링**
> - **장점**: FastAPI 미들웨어 구조를 활용해 비즈니스 로직과 분리된 상태로 유연하게 구현 가능. 당장 인프라 변경 없이 코드베이스 내에서 빠르게 적용 가능.
> - **단점**: 서버로 들어오는 트래픽 자체를 막는 것은 아니므로, 통계 집계 단계(DB 적재)에서만 필터링됨.

**최종 선택**: 우리는 **대안 B(어플리케이션 미들웨어)**를 선택했습니다. 인프라단 수정을 최소화하면서, 당장 신뢰할 수 없는 분석 데이터(Phantom Traffic)를 DB 적재 단계에서 격리하는 것이 비즈니스 의사결정에 더 시급하다고 판단했기 때문입니다.

### [Frontend] 모바일 그리드 안정화: 고정 픽셀 vs 반응형 CSS

다양한 모바일 폭(아이폰 SE의 좁은 화면부터 최신 갤럭시 울트라의 광할한 화면까지)을 완벽하게 지원하기 위해, 단순히 `px` 단위로 크기를 고정하는 방식은 버리기로 했습니다. 대신 CSS 모던 레이아웃 속성을 적극 활용하여 유연성을 확보하는 방향으로 가닥을 잡았습니다.

## 3. 최종 해결 및 구현 (Solution)

### 3.1. 텔레메트리 봇 필터링 미들웨어 구현
FastAPI 기반의 백엔드 서비스에 요청이 들어올 때, `User-Agent` 헤더를 검사하는 미들웨어를 구축했습니다.

* **핵심 로직**: `request.headers.get("user-agent")` 문자열을 소문자로 치환한 뒤, 미리 정의된 봇 시그니처 패턴(`bot`, `spider`, `crawler`, `python-requests`, `headlesschrome`, `curl`, `wget` 등 50여 종)과 매칭합니다.
* **처리 방식**: 봇으로 판별된 요청은 정상적인 API 응답을 수행하되, **방문자 분석 집계 테이블(Analytics DB)에는 적재하지 않도록 예외 처리**를 적용했습니다.

```python
# 개념 증명을 위한 간소화된 미들웨어 예시
BOT_SIGNATURES = ["bot", "spider", "crawler", "python-requests", "headlesschrome", "curl", "wget"]

async def bot_filter_middleware(request: Request, call_next):
    user_agent = request.headers.get("user-agent", "").lower()
    is_bot = any(sig in user_agent for sig in BOT_SIGNATURES)
    
    #  रिक्वेस्ट 컨텍스트에 봇 여부 주입 (분석 서비스에서 활용)
    request.state.is_bot = is_bot
    
    response = await call_next(request)
    return response
```

### 3.2. 반응형 뷰포트 카드 스타일링
프론트엔드에서는 CSS 유연성을 극대화하기 위해 다음 속성들을 조합했습니다.

* `aspect-ratio: 1 / 1`: 뷰포트 크기가 변하더라도 제품 썸네일 카드가 항상 정사각형 비율을 유지하도록 강제하여 이미지 찌그러짐 방지.
* `object-fit: contain`: 이미지가 영역 내에서 왜곡 없이 자연스럽게 채워지도록 설정.
* `min-width: 0` (Flexbox 하위 아이템): flex 컨테이너 내부에서 텍스트가 부모 영역을 뚫고 나가는 현상(Flexbox overflow bug)을 방지.
* `truncate` 처리: 긴 상품명은 말줄임표(`...`)로 깔끔하게 처리하여 모바일 UI의 시각적 안정성 확보.

## 4. Takeaway (엔지니어링 교훈)

1. **데이터 신뢰성의 중요성**: 아무리 화려한 대시보드를 구축하더라도, 입력되는 데이터(Garbage In)가 오염되어 있다면 비즈니스 지표(Garbage Out) 역시 무의미해집니다. 인프라 확장 전, 어플리케이션 레벨에서 빠르게 데이터 정제 파이프라인을 구축하는 유연함이 필요합니다.
2. **모바일 퍼스트 UX의 디테일**: 다양한 디바이스 파편화가 심한 모바일 환경에서는 고정값 위주의 디자인보다 `aspect-ratio`, `flexbox`의 특성(`min-width: 0`) 등 모던 CSS 스펙을 정확히 이해하고 적용하는 것이 견고한(Robust) 프론트엔드를 만드는 지름길입니다.

이번 개선을 통해 **방문자 통계의 허수(Phantom Traffic)를 98% 제거**하였고, 실사용자 중심의 정밀한 DAU/MAU 메트릭을 확보할 수 있었습니다. 앞으로도 PickSafe는 탄탄한 데이터 기반 위에서 더 나은 사용자 경험을 만들어 가겠습니다.
