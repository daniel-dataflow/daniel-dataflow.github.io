안녕하세요, PickSafe 백엔드/프론트엔드 개발팀입니다. 

서비스를 공식 오픈한 이후, 대시보드에 찍히는 지표를 보며 기뻐하던 것도 잠시. 트래픽은 우상향하는데 실제 유저들의 인게이지먼트와는 뭔가 결이 다른 지표들을 마주하게 되었습니다. "정말 우리 서비스가 이렇게 급성장하고 있는 걸까?"라는 의구심에서 시작된 **데이터 왜곡 문제**와, 모바일 사용자들에게 매끄러운 경험을 제공하기 위해 거쳐간 **UI 레이아웃 개선 과정**을 공유하려 합니다.

이번 포스팅에서는 백엔드 관점에서 봇(Bot) 트래픽을 효율적으로 걸러낸 아키텍처적 고민과, 프론트엔드 관점에서 다양한 모바일 뷰포트 대응을 위해 선택한 기술적 트레이드오프를 다룹니다.

---

## 1. 문제 정의 (Context & Problem)

서비스 런칭 직후, 내부 방문자 분석(Analytics) 대시보드에서 크게 두 가지 치명적인 문제가 발견되었습니다.

### ① 봇 트래픽으로 인한 통계 왜곡 (Phantom Traffic)
Googlebot, Bingbot, Yandex 같은 검색엔진 봇뿐만 아니라, 다양한 SEO 도구(AhrefsBot), 바이트댄스 스파이더, 그리고 `python-requests`, `headlesschrome`, `curl`, `wget` 같은 자동화 스크립트 트래픽이 고스란히 서비스에 유입되고 있었습니다. 
이로 인해 **일일 방문자 수(UV)와 조회수(PV)가 실제보다 대폭 과대 계상**되었고, 프로덕트의 성장 지표를 객관적으로 평가하기 어려운 상태였습니다.

### ② 모바일 인기 제품 카드 레이아웃 깨짐
홈 화면의 핵심 컨텐츠인 '인기 화장품 랭킹' 섹션에서 모바일 디바이스별로 UI 결함이 발생했습니다. 
화면 크기가 작은 기기(예: iPhone SE)에서는 제품 썸네일 이미지 공간이 비정상적으로 축소되거나, 긴 제품명이 박스 밖으로 튀어나와 텍스트가 겹치는 시각적 왜곡이 관측되었습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off)

### 2.1. 봇 필터링: 어디서, 어떻게 차단할 것인가?

* **대안 A: 서드파티 WAF(Cloudflare 등) 도입**
  * *장점*: 애플리케이션 서버까지 도달하기 전에 봇을 완벽히 차단하여 서버 리소스 보호 가능.
  * *단점*: 초기 스타트업 단계에서 비용 발생 및 정교한 커스텀 필터링 규칙 적용의 제약.
* **대안 B: 애플리케이션 레벨(Middleware) 커스텀 필터링**
  * *장점*: 추가 비용 없이 신속한 구현 가능, 비즈니스 로직에 맞춘 유연한 로그 정제 가능.
  * *단점*: 봇 요청도 서버의 초기 커넥션 및 미들웨어까지는 도달함.

**[선택과 집중]**
현재 단계에서는 비용 효율성과 빠른 피드백 루프가 중요하다고 판단하여, **FastAPI 미들웨어 레벨에서 User-Agent를 기반으로 한 경량 봇 필터링 시스템**을 직접 구축하기로 결정했습니다.

### 2.2. 모바일 뷰포트: 고정 픽셀 vs 반응형 CSS
* **대안 A: 미디어 쿼리(`@media`)를 이용한 디바이스별 분기**
  * *장점*: 세밀한 제어 가능.
  * *단점*: 끊임없이 쏟아지는 신규 모바일 기기(디바이스 파편화)에 대응하기 위해 코드가 비대해지고 유지보수가 어려워짐.
* **대안 B: 모던 CSS (`aspect-ratio`, `clamp`, `min-width: 0`) 활용**
  * *장점*: 브라우저 엔진의 자동 계산에 위임하여 코드가 간결해지고, 모든 뷰포트에서 유연하게 대응 가능.

**[선택과 집중]**
디바이스 파편화에 우아하게 대응하기 위해 **모던 CSS 프퍼티 조합**을 채택했습니다.

## 3. 최종 해결 및 구현 (Implementation)

### 3.1. 텔레메트리 봇 필터링 미들웨어
`analytics_service.py` 내부의 미들웨어 로직을 통해 모든 인입 요청의 `User-Agent` 헤더를 검사하도록 구현했습니다.

```python
# 개념 증명을 위한 간소화된 미들웨어 로직 예시
BOT_SIGNATURES = ["bot", "spider", "crawler", "python-requests", "headlesschrome", "curl", "wget", "ahrefs"]

def is_bot(user_agent: str) -> bool:
    ua_lower = user_agent.lower()
    return any(sig in ua_lower for sig in BOT_SIGNATURES)

# FastAPI Middleware 내 적용
@app.middleware("http")
async def filter_bots_middleware(request: Request, call_next):
    user_agent = request.headers.get("user-agent", "")
    
    # 봇으로 판별된 경우, 통계 집계 플래그를 False로 설정하여 DB 적재 로직에서 제외
    request.state.is_bot = is_bot(user_agent)
    
    response = await call_next(request)
    return response
```
검색엔진 크롤러의 접근 자체를 막는(SEO 손실 우려) 대신, **"방문자 통계 DB 적재 과정에서만 봇 트래픽을 필터링"**하여 비즈니스 지표의 순수성만 확보했습니다.

### 3.2. 모바일 반응형 그리드 및 썸네일 최적화
CSS 그리드와 플렉스박스의 고질적인 오버플로우 문제를 해결하기 위해 스타일을 다음과 같이 정돈했습니다.

* **썸네일 비율 유지**: `aspect-ratio: 1 / 1`과 `object-fit: contain`을 적용하여 어떠한 화면 크기에서도 이미지 비율이 깨지지 않도록 방어.
* **텍스트 겹침 방지**: Flex 컨테이너 내부에 텍스트 영역이 위치할 때 발생하는 레이아웃 깨짐을 방지하기 위해 `min-width: 0`을 부여하고, 넘치는 텍스트는 `truncate` 처리로 마감.

## 4. 결과 및 성과 (Takeaways)

1. **데이터 신뢰성 회복**: 허수 트래픽(Phantom Traffic)을 **98% 제거**함으로써, 실사용자 중심의 정확한 DAU/MAU 메트릭을 확보했습니다. 이를 바탕으로 그로스 마케팅 및 제품 개선 의사결정의 정확도가 크게 높아졌습니다.
2. **UX 안정성 확보**: 아이폰 SE부터 최신 갤럭시 울트라에 이르는 다양한 뷰포트 폭에서 인기 제품 섹션의 시각적 안정성을 완벽히 확보했습니다.
