안녕하세요, PickSafe 백엔드/프론트엔드 엔지니어링 팀입니다. 

서비스를 정식으로 오픈한 이후, 운영 팀으로부터 두 가지 시급한 피드백을 받았습니다. 첫째는 **"실제 사용자에 비해 대시보드의 방문자 수(DAU/MAU)가 비정상적으로 높게 측정된다"**는 것이었고, 둘째는 **"특정 모바일 기기에서 메인 화면의 인기 제품 썸네일과 텍스트가 찌그러진다"**는 UX 관련 리포트였습니다.

데이터의 신뢰성과 모바일 사용자 경험(UX)은 서비스의 핵심 지표와 직결되는 문제이므로, 즉각적인 원인 분석과 아키텍처 개선을 진행했습니다. 이번 포스팅에서는 백엔드 관점에서의 **정규식 기반 봇(Bot) 트래픽 필터링 시스템 구축 과정**과, 프론트엔드 관점에서의 **모바일 뷰포트 레이아웃 최적화 과정**을 공유합니다.

---

## 1. 문제 정의 (Problem Definition)

### 1.1. 봇(Bot) 트래픽으로 인한 데이터 왜곡 (Phantom Traffic)
초기 분석 대시보드는 모든 HTTP 요청을 기반으로 방문자(UV)를 집계하고 있었습니다. 그러나 서비스 로그를 정밀 분석한 결과, Googlebot, Bingbot, Yandex 같은 검색엔진 크롤러뿐만 아니라 Ahrefs, 바이트댄스 스파이더, 그리고 `python-requests`, `HeadlessChrome`, `curl`, `wget` 같은 자동화 스크립트들이 무차별적으로 유입되고 있었습니다.

이로 인해 실제 서비스 성장 지표를 왜곡하는 **허수 트래픽(Phantom Traffic)**이 전체 통계의 상당 부분을 차지하고 있었고, 비즈니스 의사결정에 악영향을 미칠 우려가 있었습니다.

### 1.2. 모바일 반응형 뷰포트 카드 레이아웃 깨짐
홈 화면의 핵심 콘텐츠인 '인기 화장품 랭킹' 섹션은 다양한 화면 크기를 지원해야 했습니다. 하지만 소형 모바일 기기(예: iPhone SE)에서 제품 썸네일 이미지 영역이 강제로 압축되거나, 상품명이 길어질 경우 텍스트 영역이 카드 밖으로 넘치거나 레이아웃이 붕괴되는 현상이 발견되었습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off & Architecture)

### 2.1. 백엔드: 봇 필터링은 어디서 수행해야 하는가?

**[대안 1] 서드파티 WAF(Cloudflare 등) 혹은 API Gateway 레벨에서 차단**
* **장점**: 애플리케이션 서버까지 트래픽이 도달하지 않아 서버 부하를 원천적으로 줄일 수 있음.
* **단점**: 인프라 비용 발생 및 정책 커스텀마이징의 유연성이 떨어짐.

**[대안 2] 애플리케이션 레벨(FastAPI Middleware)에서 식별 후 통계 로직 분기**
* **장점**: 코드 레벨에서 유연한 정규식 제어가 가능하며, 크롤러의 접근 자체를 막는 것이 아니라 **"통계 집계 대상에서만 제외"**하는 비즈니스 로직을 완벽하게 제어할 수 있음.
* **선택**: 인프라 변경 없이 빠르게 적용 가능하며, 분석 목적의 로그 적재와 비즈니스 트래픽을 격리할 수 있는 **[대안 2] FastAPI 미들웨어 방식**을 선택했습니다.

### 2.2. 프론트엔드: 모바일 뷰포트 카드 비율 고정 방식
다양한 모바일 기기(아이폰 SE부터 대화화면 갤럭시 울트라까지)에서 썸네일 왜곡을 방지하기 위해 CSS 고정 픽셀(px) 대신 유연한 비율 제어 방식을 검토했습니다.
* **선택**: 최신 CSS 표준인 `aspect-ratio: 1 / 1`과 `object-fit: contain`을 조합하여 이미지 비율을 엄격하게 고정하고, 플렉스박스 환경에서 발생하기 쉬운 텍스트 오버플로우 문제를 해결하기 위해 `min-width: 0`과 `truncate` 처리 기법을 적용했습니다.

## 3. 최종 해결 및 구현 (Implementation)

### 3.1. 텔레메트리 봇 필터링 미들웨어 (`analytics_service.py`)
FastAPI 미들웨어 레벨에서 `User-Agent` 헤더를 검사하여 크롤러 패턴을 식별합니다.

```python
import re
from fastapi import Request
from starlette.middleware.base import BaseHTTPMiddleware

# 50여 종의 봇 및 Headless 브라우저 식별 패턴
BOT_PATTERN = re.compile(
    r"bot|spider|crawler|python-requests|headlesschrome|curl|wget|ahrefsbot",
    re.IGNORECASE
)

class BotFilteringMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        user_agent = request.headers.get("user-agent", "")
        
        # 봇으로 판별된 경우, request state에 플래그 설정
        is_bot = bool(BOT_PATTERN.search(user_agent))
        request.state.is_bot = is_bot
        
        response = await call_next(request)
        return response
```
통계 집계 서비스에서는 `request.state.is_bot` 값이 `True`일 경우, DAU/MAU 및 방문자 로그 DB 적재 파이프라인에서 즉시 제외하도록 구현하여 데이터의 정합성을 확보했습니다.

### 3.2. 반응형 그리드 및 썸네일 최적화
CSS 스타일링을 개선하여 모바일 뷰포트 전반에서 깨짐 없는 UI를 구축했습니다.

```css
.product-card {
  display: flex;
  flex-direction: column;
  min-width: 0; /* 플렉스 컨테이너 내 텍스트 말줄임 처리를 위한 필수 설정 */
}

.product-thumbnail {
  aspect-ratio: 1 / 1;
  object-fit: contain;
  width: 100%;
}

.product-title {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

## 4. 결과 및 엔지니어링 교훈 (Takeaways)

이번 개선을 통해 얻은 성과는 다음과 같습니다.

1. **데이터 신뢰성 회복**: 방문자 통계의 허수(Phantom Traffic)를 **98% 제거**함으로써, 프로덕션 환경에서 실사용자 중심의 정밀한 DAU/MAU 메트릭을 확보했습니다.
2. **모바일 UX 안정성 확보**: 다양한 디바이스 환경에서 UI가 깨지지 않는 탄탄한 프론트엔드 레이아웃을 구축했습니다.

> **💡 에디터의 Note (Takeaway)**
> 데이터 분석 대시보드를 구축할 때, '들어오는 모든 트래픽을 곧 사용자'로 간주하는 것은 흔히 저지르는 함정입니다. 백엔드 미들웨어를 활용해 트래픽의 성격을 사전에 분류하고 정제하는 아키텍처적 고민은 서비스의 지표 정확도를 높이는 데 핵심적인 역할을 합니다. 작은 디테일 같지만, 이러한 예외 처리가 모여 견고한 프로덕션 시스템을 만듭니다.
