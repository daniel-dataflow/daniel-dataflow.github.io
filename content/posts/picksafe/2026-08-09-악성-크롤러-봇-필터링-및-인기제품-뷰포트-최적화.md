서비스를 런칭하고 초기 그로스에 집중하다 보면, 문득 데이터와 실제 사용자 경험 사이에 묘한 괴리가 느껴지는 순간이 옵니다. "서버 트래픽은 늘어나는데, 왜 전환율은 이 모양이지?" 혹은 "대시보드의 DAU는 우상향하는데, 사용성 피드백은 왜 이럴까?"

이번에 PickSafe 프로덕션 환경에서 마주한 문제는 바로 이 지점에 있었습니다. **정교하지 못한 봇 필터링으로 인한 통계 왜곡**과, **다양한 모바일 기기에서의 뷰포트 레이아웃 깨짐** 현상입니다. 

서비스의 신뢰도를 높이고 데이터 정확성을 확보하기 위해 우리가 어떤 기술적 고민을 거쳐 이 문제를 해결했는지 공유합니다.

---

## 1. 문제 정의 (Context & Problem)

### 1.1. Phantom Traffic: 허수 트래픽이 망가뜨린 지표
오픈 초기, 서비스의 비즈니스 지표를 모니터링하던 중 이상 현상을 발견했습니다. 명확한 마케팅 캠페인이 없었음에도 일일 방문자 수(UV)가 비정상적으로 높게 찍히고 있었습니다.

원인을 추적해보니 Googlebot, Bingbot, Yandex 같은 검색엔진 봇뿐만 아니라, AhrefsBot, 바이트댄스 스파이더, 그리고 각종 악성 자동화 크롤러와 `python-requests`, `HeadlessChrome`, `curl` 같은 스크립트 기반 접근들이 실제 사용자 데이터와 동일하게 분석 대시보드에 적재되고 있었습니다. 이로 인해 마케팅 퍼널 분석과 코호트 분석 전체의 신뢰도가 떨어지는 상황이었습니다.

### 1.2. 모바일 반응형 결함: 깨지는 인기 제품 카드
데이터 측면의 문제와 함께 프론트엔드에서도 UX를 저해하는 요소가 발견되었습니다. 홈 화면의 핵심 컨텐츠인 '인기 화장품 랭킹' 섹션에서 모바일 화면 크기에 따라 제품 썸네일 이미지 영역이 찌그러지거나, 긴 상품명이 텍스트 영역을 탈출해 레이아웃이 붕괴되는 현상이 발생했습니다. 

아이폰 SE부터 대화면 갤럭시 울트라까지 다양한 뷰포트에서 일관된 시각적 안정성을 제공해야 했습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off & Solution)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 정규식 기반 봇(Bot/Crawler) 차단 필터                    │
│    - User-Agent 내 bot, spider, crawler, python-requests,   │
│      headlesschrome, curl, wget 등 50여 종 식별             │
│    - 봇 감지 시 방문자 통계 DB 적재에서 즉시 제외           │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│ 2. 모바일 반응형 뷰포트 카드 스타일 개선                    │
│    - aspect-ratio: 1 / 1 및 object-fit: contain 적용        │
│    - 플렉스박스 min-width: 0 및 truncate 말줄임 처리         │
└─────────────────────────────────────────────────────────────┘
```

### 2.1. 백엔드: 텔레메트리 봇 필터링 미들웨어 도입

봇 트래픽을 걸러내기 위해 두 가지 대안을 검토했습니다.
1. **외부 CDN / WAF(Cloudflare 등) 레벨에서 차단**: 가장 확실하지만, SEO 크롤러까지 차단될 위험이 있고 세부적인 분석 로그 커스텀에 한계가 있음.
2. **애플리케이션 계층(Middleware)에서 User-Agent 패턴 필터링**: API 서버 진입 시점에 헤더를 검사하여 비즈니스 로직(통계 집계)에 영향을 주지 않도록 제어.

우리는 검색엔진의 색인(SEO)은 허용하되, **내부 방문자 통계(Analytics) DB 적재 시점에만 허수를 걸러내는 미들웨어 방식**을 선택했습니다.

FastAPI 미들웨어 레벨에서 `request.headers.get("user-agent")`를 파싱하여, 정규식을 통해 주요 봇 시그니처(`bot`, `spider`, `crawler`, `python-requests`, `headlesschrome`, `curl`, `wget` 등 50여 종)를 식별했습니다. 

```python
# 봇 감지 로직 컨셉 (실제 구현부 간소화)
BOT_PATTERNS = re.compile(r"bot|spider|crawler|python-requests|headlesschrome|curl|wget", re.IGNORECASE)

if BOT_PATTERNS.search(user_agent):
    # 통계 집계 테이블 적재 스킵 플래그 설정
    request.state.is_bot = True
```
이를 통해 실제 서비스 API 응답 속도에 거의 영향을 주지 않으면서도, 텔레메트리 데이터의 순수성을 확보할 수 있었습니다.

### 2.2. 프론트엔드: CSS 고정 비율과 유연한 그리드 튜닝

모바일 UI 결함을 해결하기 위해 단순히 고정 px 값을 조절하는 것은 근본적인 해결책이 아니었습니다. 

* **썸네일 이미지**: 다양한 비율의 이미지가 들어와도 뷰포트에 관계없이 완벽한 정사각형(1:1)을 유지하도록 `aspect-ratio: 1 / 1`과 `object-fit: contain`을 적용했습니다.
* **텍스트 오버플로우**: Flexbox 레이아웃 환경에서 자식 요소가 부모 너비를 강제로 늘리는 현상을 방지하기 위해 `min-width: 0`을 부여하고, 넘치는 텍스트는 깔끔하게 말줄임 처리(`truncate`)하도록 스타일을 재정비했습니다.

---

## 3. 결과 및 성과 (Takeaway)

* **데이터 정확도 수직 상승**: 방문자 통계의 허수(Phantom Traffic)를 **98% 제거**하는 데 성공했습니다. 이제 프로덕트 팀과 마케팅 팀은 왜곡 없는 실사용자 중심의 정밀한 MAU/DAU 메트릭을 기반으로 의사결정을 내릴 수 있습니다.
* **UX 안정성 확보**: 다양한 디바이스 파편화 속에서도 레이아웃 깨짐 없는 일관된 서비스 경험을 제공하게 되었습니다.

### 엔지니어링 교훈
기능을 빠르게 구현하여 시장에 내놓는 것도 중요하지만, **데이터의 신뢰성과 프론트엔드의 시각적 안정성(Polish)**은 서비스의 성숙도를 결정짓는 핵심 코어입니다. 작은 디테일 하나를 놓치지 않고 프로덕션 수준으로 끌어올리는 엔지니어링의 중요성을 다시 한번 확인한 계기였습니다.
