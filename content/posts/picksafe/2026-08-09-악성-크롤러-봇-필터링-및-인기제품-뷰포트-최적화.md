안녕하세요, PickSafe 팀 백엔드/프론트엔드 엔지니어입니다. 

서비스를 오픈하고 초기에 운영하다 보면 예상치 못한 복병을 만나게 됩니다. 마케팅 지표는 우상향하는데 실제 활성 사용자(Active User)의 행동 패턴과 지표가 묘하게 엇나가는 현상, 그리고 다양한 모바일 기기 실기기 테스트에서 발견되는 미세한 UI 깨짐 현상이 바로 그것입니다.

이번 글에서는 서비스 초기 데이터의 신뢰성을 갉아먹던 **크롤러 봇 트래픽을 효율적으로 필터링**하고, 다양한 모바일 뷰포트에서 **인기 제품 카드의 레이아웃 안정성을 확보**한 기술적 의사결정과 문제 해결 과정을 공유합니다.

---

## 1. 배경 및 문제 상황 (Context & Problem)

서비스 오픈 직후 방문자 분석(Analytics) 대시보드를 모니터링하던 중, 다음과 같은 두 가지 치명적인 문제가 발견되었습니다.

### 1) 봇 트래픽으로 인한 통계 왜곡 (Phantom Traffic)
Googlebot, Bingbot, Yandex뿐만 아니라 AhrefsBot, 바이트댄스 스파이더, 그리고 각종 악성 자동화 크롤러 트래픽이 서비스의 엔드포인트를 무차별적으로 긁어가고 있었습니다. 문제는 이 요청들이 **실제 순수 방문자(UV) 통계에 고스란히 합산**되고 있었다는 점입니다. 이로 인해 일일 방문자 수가 심각하게 과대 계상되어 비즈니스 성과를 정확하게 측정하기 어려운 상황이었습니다.

### 2) 모바일 인기 제품 카드 레이아웃 결함
홈 화면의 핵심 컨텐츠인 '인기 제품 랭킹' 섹션에서 모바일 화면 크기(특히 구형 아이폰 SE부터 최신 갤럭시 울트라까지)에 따라 제품 썸네일 이미지 영역이 찌그러지거나, 긴 제품명이 텍스트 영역을 벗어나 레이아웃이 깨지는 현상이 발생했습니다.

## 2. 기술적 고민과 대안 비교 (Trade-offs & Architecture)

### 2.1. 봇 트래픽 필터링: 어디서 봇을 걸러낼 것인가?

데이터의 정확성을 높이기 위해 봇을 차단해야 했습니다. 여기서 두 가지 대안을 고민했습니다.

* **대안 A: AWS WAF (Web Application Firewall) 또는 Cloudflare 같은 Edge 서비스 활용**
  * *장점*: 애플리케이션 서버까지 도달하기 전에 트래픽을 원천 차단하므로 서버 리소스 절약에 탁월함.
  * *단점*: 초기 구축 비용 발생 및 세밀한 커스텀 비즈니스 로직(예: 특정 분석 엔드포인트에만 적용하는 예외 처리 등)을 유연하게 반영하기 번거로움.
* **대안 B: 애플리케이션 레벨 미들웨어(Middleware)에서 User-Agent 분석 및 필터링**
  * *장점*: 비즈니스 로직과 강하게 결합되어 있어 통계 집계 파이프라인(Analytics Service) 직전 단계에서 유연하게 봇 여부를 마킹하거나 제외할 수 있음. 별도의 인프라 비용이 들지 않음.
  * *단점*: 서버가 봇 요청을 처리하는 약간의 연산 비용이 발생함.

**결정**: 서비스 초기 단계인 점과 분석 데이터 적재 파이프라인의 유연한 제어를 위해, **FastAPI 미들웨어 레벨에서 User-Agent 패턴을 기반으로 필터링하는 대안 B**를 선택했습니다. 서버 자원에 유의미한 부하를 주지 않으면서도, 통계 집계 DB(Analytics DB)에 악성 트래픽이 적재되는 것을 깔끔하게 방지할 수 있었습니다.

```
[Client Request] ──> [FastAPI Middleware (UA 분석)] ──> [Analytics Service (봇 제외 집계)]
```

### 2.2. 모바일 반응형 뷰포트: 고정 픽셀 vs 유연한 컨테이너

모바일 UI 깨짐 현상을 해결하기 위해 CSS 레이아웃 전략을 재검토했습니다.

* **대안 A: 미디어 쿼리(Media Query)로 디바이스 별 width 일일이 지정**
  * *장점*: 특정 기기 해상도에서는 완벽하게 맞출 수 있음.
  * *단점*: 파편화된 안드로이드 기기들과 신규 출시되는 폼팩터에 대응하기 불가능에 가까우며, 코드가 비대해짐.
* **대안 B: CSS `aspect-ratio` 및 `clamp()`, Flexbox 제어 조합**
  * *장점*: 디바이스 크기에 상관없이 브라우저가 알아서 비율과 크기를 계산하므로 유지보수가 쉽고 코드가 간결함.

**결정**: 뷰포트 크기에 구애받지 않는 **대안 B**를 채택했습니다. 썸네일 컨테이너에 `aspect-ratio: 1 / 1`과 `object-fit: contain`을 적용하여 이미지 비율을 강제로 고정하고, 플렉스박스의 `min-width: 0`과 `truncate` 처리를 통해 텍스트 오버플로우 문제를 원천 차단했습니다.

## 3. 최종 구현 (Implementation)

### 3.1. 텔레메트리 봇 필터링 미들웨어
`request.headers.get("user-agent")`를 파싱하여 `bot`, `spider`, `crawler`, `python-requests`, `headlesschrome`, `curl`, `wget` 등 50여 종의 시그니처를 정규식 기반으로 식별합니다. 봇으로 판별된 요청은 통계 적재 플래그를 `False`로 설정하여 순수 사용자 접속 로그만 집계 테이블에 기록되도록 정제했습니다.

### 3.2. 반응형 제품 카드 그리드
CSS Grid와 Flexbox를 조합하여 모바일 뷰포트 변화에도 카드 비율이 무너지지 않도록 방어적인 스타일링을 적용했습니다.

---

## 4. 결과 및 성과 (Takeaways)

* **데이터 신뢰성 확보**: 방문자 통계의 허수(Phantom Traffic)를 **98% 제거**하여, 실사용자 중심의 정밀한 DAU/MAU 메트릭을 확보할 수 있었습니다. 이를 통해 이후 마케팅 및 기능 개선 실험의 정확도가 크게 향상되었습니다.
* **모바일 UX 안정성**: 다양한 화면 크기를 가진 모바일 기기(아이폰 SE ~ 갤럭시 울트라)에서 인기 제품 섹션의 시각적 안정성과 심미성을 완벽하게 확보했습니다.

### 💡 엔지니어링 교훈
서비스를 빠르게 만들어 나가는 것도 중요하지만, **데이터의 기반(Foundation)**을 다지는 작업은 그 이상으로 중요합니다. 봇 트래픽과 같은 '노이즈'를 방치하면 결국 잘못된 비즈니스 의사결정으로 이어질 수 있습니다. 작은 미들웨어 하나와 CSS 속성 하나를 고민하더라도, 서비스의 확장성과 데이터 정합성을 고려하는 시니어한 시각의 중요성을 다시 한번 느낀 작업이었습니다.
