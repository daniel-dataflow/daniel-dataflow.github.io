안녕하세요, PickSafe 백엔드 에디터입니다. 
글로벌 서비스로 도약하는 과정에서 마주치는 대표적인 기술 부채 중 하나는 바로 **'다국어 처리(Localization)'**입니다. 초기 개발 속도를 위해 도입했던 하드코딩 구조와 수동 번역 방식은 서비스가 성장함에 따라 개발 생산성을 떨어뜨리는 거대한 병목이 됩니다.

이번 포스팅에서는 PickSafe가 기존의 정적 다국어 시스템을 어떻게 **완전 동적(Dynamic) 구조**로 개편하고, **LLM(Gemini API)을 활용한 서버 사이드 일괄 번역 파이프라인**을 구축하여 유지보수 비용을 획기적으로 줄였는지 그 아키텍처적 고민과 의사결정 과정을 공유합니다.

---

## 1. Problem: 글로벌 확장의 발목을 잡던 하드코딩과 수동 번역

PickSafe는 초기 설계 단계에서 한국어, 영어, 일본어, 중국어(간/번체), 포르투갈어 등 주요 6개국 언어를 하드코딩된 형태로 지원하고 있었습니다. 하지만 비즈니스가 확장되면서 다음과 같은 치명적인 한계에 부딪혔습니다.

1. **높은 유지보수 비용 (Rigid Architecture)**: 새로운 언어(스페인어, 프랑스어 등)를 추가할 때마다 프론트엔드 UI 렌더링 코드, 백엔드 API 검증 로직, DB 테이블 컬럼 구성을 모두 수동으로 수정해야 했습니다.
2. **번역 리소스의 부재**: 언어 코드를 추가하더라도 방대한 양의 기존 `ui_string` 데이터를 사람이 직접 번역해야 하는 리소스 부족 문제가 발생했습니다.
3. **자동화 도구의 부재**: 어드민에서 특정 언어의 누락된 빈칸을 효율적으로 채울 수 있는 서버 주도형 자동화 수단이 없어, 품질 테스트 및 빈칸 누락 확인에 큰 공수가 들었습니다.

---

## 2. Decision: 동적 아키텍처 전환과 서버 사이드 LLM 파이프라인

이 문제를 해결하기 위해, 우리는 **"개발자 소스 수정 없는 동적 로케일 관리"**와 **"안전하고 빠른 서버 사이드 일괄 번역"**이라는 두 가지 축으로 시스템을 재설계했습니다.

### 2.1 다국어(로케일) 동적 렌더링 시스템
* **메타데이터 분리**: 백엔드 설정 파일에 글로벌 지원 가능한 17개국 이상의 언어 리스트(`GLOBAL_LOCALES`)를 정의했습니다.
* **DB 기반 활성화 (`system_locales`)**: 관리자가 어드민 UI에서 `[+ 언어 추가]`를 누르면 동적으로 `system_locales` 테이블에 저장되도록 변경했습니다.
* **프론트엔드 동적 렌더링**: 프론트엔드(HTML/JS)의 하드코딩된 언어 배열을 전면 제거하고, API를 통해 받아온 활성 언어 목록을 기반으로 UI(테이블 칼럼, 모달 폼 등)가 유연하게 그려지도록 구조를 개편했습니다.

### 2.2 백엔드(FastAPI) 주도의 Gemini API 일괄 번역 도입
프론트엔드에서 클라이언트 사이드 번역을 호출하는 방식은 API 키 노출 위험 및 네트워크 안정성 측면에서 부적합하다고 판단했습니다. 따라서 **FastAPI 서버 사이드에서 LLM을 호출하는 구조**를 채택했습니다.

* **안전한 인증**: 어드민 권한이 검증된 백엔드 환경에서 안전하게 보안 API 키(`PROD_OFFI_GEMINI_API_KEY`)를 사용하여 Gemini 1.5 Flash 모델에 접근합니다.
* **스마트 빈칸 타겟팅 전략**: 전체 데이터를 무작위로 덮어쓰는 방식은 사람이 직접 공들여 검수한 번역 데이터를 훼손할 위험이 있습니다. 이를 방지하기 위해 **"타겟 언어의 문자열이 빈칸('')인 경우에만"** 영어(English) 원문을 기반으로 프롬프트를 구성해 번역을 요청하도록 설계했습니다.
* **쿼터 관리 연동**: API 호출량이 과도하게 발생하지 않도록 내부 모니터링 시스템과 연동하여 사용량을 제어했습니다.

## 3. Trade-off & Engineering Learnings

### 👍 기대 효과 (Pros)
* **확장성 극대화**: 이제 새로운 국가 진출 시 개발자의 코드 배포 없이, 어드민 UI에서 클릭 한 번으로 1초 만에 시스템에 언어를 추가할 수 있습니다.
* **생산성 폭발**: 새로운 언어 추가 직후 `[✨ 빈칸 자동 번역]` 버튼을 누르면, 기존에 검수한 데이터는 완벽히 보호하면서 누락된 수백 개의 텍스트만 정확히 채워져 즉시 글로벌 서비스 배포가 가능해졌습니다.

### ⚠️ 고려사항 및 향후 개선점 (Cons & Mitigations)
* **서버 타임아웃 우려**: 현재 구현은 동기(Sync) 방식으로 동작하기 때문에, 번역해야 할 데이터가 수천 개 이상으로 늘어날 경우 HTTP 요청 지연(Timeout)이 발생할 수 있습니다.
* **Scale-up Plan**: 향후 지원 언어와 텍스트 데이터가 폭증할 것에 대비하여, 동기 처리 방식을 **비동기 워커(Celery / BackgroundTasks)** 기반으로 전환하고 어드민 UI에 실시간 진행률(Progress Bar)을 제공하는 방식으로 아키텍처를 고도화할 계획입니다.

## 💡 Takeaway

이번 다국어 시스템 개편을 통해 **"비즈니스 변화 속도에 맞춘 유연한 아키텍처 설계"**의 중요성을 다시 한번 깨달았습니다. 단순한 기능 구현을 넘어, 기존 데이터의 안정성(Non-destructive)을 보장하면서도 운영자의 생산성을 극대화하는 방향으로 기술적 트레이드오프를 조율한 점이 이번 프로젝트의 가장 큰 수확입니다.

PickSafe는 앞으로도 글로벌 유저들에게 더 빠르고 매끄러운 경험을 제공하기 위해 끊임없이 시스템을 고도화해 나갈 것입니다. 읽어주셔서 감사합니다!
