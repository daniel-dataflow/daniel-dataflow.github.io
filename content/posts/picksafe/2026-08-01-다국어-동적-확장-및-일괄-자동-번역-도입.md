안녕하세요, PickSafe 백엔드 에디터입니다. 
글로벌 서비스를 지향하는 프로덕트라면 누구나 한 번쯤 마주하는 고민이 있습니다. 바로 **"새로운 국가의 언어를 추가해야 할 때, 얼마나 많은 코드를 수정해야 하는가?"**입니다.

초기 PickSafe는 한국어, 영어, 일본어 등 6개 주요 언어를 하드코딩된 형태로 지원하고 있었습니다. 하지만 비즈니스가 확장되면서 새로운 언어 추가 요청이 빈번해졌고, 이 과정에서 치명적인 개발 부채(Technical Debt)를 마주하게 되었습니다.

이번 글에서는 하드코딩 구조를 탈피해 **동적 다국어 시스템**으로 전환하고, LLM(Gemini API)을 활용해 **백엔드 주도형 일괄 자동 번역 파이프라인**을 구축한 아키텍처 의사결정 과정을 공유합니다.

---

## 1. Problem: 하드코딩된 다국어 시스템의 한계

초기 시스템은 기능 구현 속도를 위해 다국어 처리를 비교적 단순하게 설계했습니다. 하지만 서비스가 성장하면서 다음과 같은 구조적 병목 현상이 발생했습니다.

1. **높은 유지보수 비용 (High Maintenance Cost)**
   - 새로운 언어(예: 스페인어, 프랑스어)를 추가하려면 프론트엔드 렌더링 코드, 백엔드 API 유효성 검증 로직, DB 테이블 컬럼 구성을 일일이 수정해야 했습니다. 언어 하나 추가하는 데 여러 파일의 수정과 배포가 동반되었습니다.
2. **번역 리소스 부족 및 품질 관리의 어려움**
   - 언어 구조를 확장하더라도, 방대한 양의 기존 `ui_string` 데이터를 채우는 것은 전적으로 사람의 손에 의존해야 했습니다. 
   - 어드민에서 누락된 빈칸을 직관적으로 확인하고 한 번에 채울 수 있는 자동화된 수단이 부재했습니다.

---

## 2. Technical Decisions: 아키텍처 개편과 대안 비교

이 문제를 해결하기 위해 시스템을 **완전한 동적(Dynamic) 구조**로 개편하고, 백엔드 중심의 자동화 파이프라인을 설계했습니다.

### ① 다국어(로케일) 동적 렌더링 시스템 구축
* **메타데이터 분리**: 전역에서 지원 가능한 17개국 이상의 언어 리스트를 백엔드 설정 파일에 상수로 정의(`GLOBAL_LOCALES`)했습니다.
* **DB 기반 활성화 관리 (`system_locales`)**: 관리자가 어드민 UI에서 언어를 추가하면 동적으로 DB에 적재되도록 설계했습니다.
* **프론트엔드 동적 렌더링**: 정적 배열을 완전히 제거하고, `/admin/locales` API를 통해 응답받은 시스템 설정 언어 목록을 기반으로 UI(테이블 컬럼, 입력 폼 등)가 유연하게 그려지도록 프론트엔드 구조를 재설계했습니다.

### ② 빈칸 자동 일괄 번역: 왜 프론트엔드가 아닌 백엔드(FastAPI + Gemini)인가?
번역 기능을 어디에 구현할 것인가에 대한 고민이 있었습니다.
- **Client-side 번역 (Google Translate JS 등)**: 구현은 간단하지만, API 키 노출 보안 위험이 있고 대량의 데이터를 브라우저에서 처리할 때 성능 저하 및 에러 핸들링이 어렵습니다.
- **Server-side 번역 (FastAPI + LLM API)**: 서버 환경 변수로 안전하게 API 키를 관리할 수 있으며, 데이터 정합성을 유지하면서 대량의 텍스트를 안정적으로 처리할 수 있습니다.

우리는 **안정성과 보안성**을 최우선으로 하여, FastAPI 백엔드 내에서 Gemini API를 호출하는 방식을 채택했습니다.

> **💡 핵심 번역 전략 (Smart Patching)**
> - 전체 DB 데이터를 무조건 덮어쓰는 방식은 사람이 직접 공들여 검수한 번역본을 훼손할 위험이 있습니다.
> - 따라서 **'타겟 언어의 텍스트가 빈 문자열("")인 경우에만'** 영어 원문(English Source)을 기반으로 프롬프트를 구성해 Gemini 1.5 Flash에 질의하고, 결과를 DB에 안전하게 적재하는 **누락 전용 패치 전략**을 적용했습니다.

## 3. Trade-off & Limitations

모든 아키텍처 결정에는 트레이드오프가 존재합니다. 이번 도입으로 얻은 이점과 향후 해결해야 할 과제는 다음과 같습니다.

### 👍 장점 (Pros)
- **확장성 극대화**: 개발자의 소스 코드 수정 없이, 어드민 UI 클릭만으로 새로운 언어를 시스템에 즉시 추가할 수 있습니다.
- **압도적인 생산성**: 새로운 언어 추가 후 `[✨ 빈칸 자동 번역]` 버튼 클릭 한 번으로 수백 개의 UI 텍스트가 일괄 번역되어 즉시 글로벌 서비스 런칭이 가능해졌습니다.
- **데이터 안정성 (Zero-Loss)**: 기존에 수동으로 정교하게 다듬어둔 번역 데이터는 완벽히 보호하면서, 빈칸만 정확히 채워 넣으므로 품질 리스크를 원천 차단했습니다.

### ⚠️ 고려사항 및 향후 개선 과제 (Cons & Mitigations)
- **서버 타임아웃 우려**: 향후 지원 언어와 UI 스트링이 수천 개 이상으로 폭증할 경우, 동기(Sync) 방식의 일괄 번역 API는 HTTP 타임아웃을 유발할 수 있습니다.
- **Mitigation Plan**: 텍스트 볼륨이 임계치를 넘어서는 시점에 맞춰, 해당 엔드포인트를 Celery 또는 FastAPI `BackgroundTasks` 기반의 **비동기 워커 구조**로 전환하고, 어드민 화면에는 실시간 프로그레스 바(Progress Bar)를 연동하여 UX를 고도화할 예정입니다.

---

## 4. Takeaway

이번 다국어 시스템 개편을 통해 **"확장성이 필요한 영역은 철저히 데이터베이스화하고, 반복적이고 소모적인 작업은 LLM과 백엔드 파이프라인으로 자동화한다"**는 엔지니어링 원칙을 다시 한번 체감했습니다. 

단순히 기능을 구현하는 것을 넘어, 비즈니스의 성장 속도(새로운 국가 진출)에 개발 조직이 발목 잡히지 않도록 선제적으로 시스템의 체질을 개선한 좋은 사례였습니다. PickSafe는 앞으로도 유연하고 확장 가능한 아키텍처를 바탕으로 글로벌 사용자에게 더 나은 가치를 전달하겠습니다.
