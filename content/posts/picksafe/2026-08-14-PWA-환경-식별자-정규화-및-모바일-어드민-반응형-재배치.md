안녕하세요, **PickSafe** 팀에서 백엔드와 프론트엔드 아키텍처를 담당하고 있는 Daniel입니다. 

서비스가 성장함에 따라 개발(Dev), 스테이징(Staging), 운영(Prod) 환경을 나누어 관리하는 것은 필수적입니다. 하지만 웹 환경을 넘어 **PWA(Progressive Web App)**를 통해 모바일 홈 화면에 앱 형태로 설치하는 사용자 경험(UX)을 제공하기 시작하면서, 예상치 못한 사소한(?) 인프라적 혼선과 마주하게 되었습니다.

이번 글에서는 **멀티 환경 PWA 식별자 충돌 문제**를 해결하고, 현장 관리자의 실시간 대응 속도를 2배 이상 끌어올린 **모바일 어드민 반응형 리팩토링** 과정에서 얻은 엔지니어링 교훈을 공유하려 합니다.

---

## 1. 문제 정의 (Context & Problem)

우리가 마주한 문제는 크게 두 가지였습니다.

### ① PWA 환경 식별자 및 캐시 오염
로컬 개발, 스테이징, 운영 환경의 웹앱을 모두 테스트용 스마트폰의 홈 화면에 추가하는 과정에서 앱 이름(`name`, `short_name`)과 아이콘이 엉키는 현상이 발생했습니다. 
* 브라우저와 서비스 워커(Service Worker)가 이전 환경의 매니페스트(`manifest.json`)와 정적 자산을 캐싱하고 있어, **"내가 지금 접속한 곳이 운영(Prod)인지 스테이징인지"** 육안으로 구별하기 어려웠습니다.
* 특히 배포 후에도 아이콘이나 앱 이름이 갱신되지 않고 구버전 캐시가 유지되는 고질적인 문제가 있었습니다.

### ② 모바일 어드민의 '엄지손가락 파괴' 현상
PickSafe는 식품 안전 정보 및 긴급 장애 대응을 다루는 서비스 특성상, 현장이나 이동 중에도 모바일로 어드민에 접속해 서버 상태를 확인하고 대응해야 하는 경우가 잦습니다. 
* 하지만 기존 어드민 뷰는 데스크톱 중심의 2열 레이아웃을 그대로 모바일에 구겨 넣은 형태였습니다.
* 스마트폰 화면에서 관리 카드와 네비게이션 버튼의 터치 타깃이 너무 작아 오클릭이 빈번했고, 레이아웃이 깨지는 현상으로 인해 긴급 상황 시 실시간 대응 속도가 저하되는 병목이 있었습니다.

## 2. 기술적 고민과 대안 비교 (Trade-offs & Implementation)

단순히 화면을 줄이는(Responsive) 것을 넘어, 엔지니어링 관점에서 두 가지 핵심 영역을 정비했습니다.

### 2.1 PWA 매니페스트 표준화 및 캐시 버저닝 전략

환경별로 명확한 식별자를 부여하기 위해 매니페스트 메타데이터를 분리하고, 서비스 워커의 생명주기(Lifecycle)를 재설계했습니다.

* **환경별 식별자 격리**: 운영 환경은 직관적인 브랜드 명칭과 함께 `start_url`에 특정 쿼리 파라미터(`/?mode=standalone`)를 주입하여 독립된 웹 앱 인스턴스로 동작하도록 강제했습니다.
* **공격적인 서비스 워커 캐시 Purge**: 
  기존의 모호한 캐시 정책을 버리고, 빌드 타임에 고유 버전 스탬프(`cache-v[YYYYMMDD]`)를 부여했습니다. 특히 서비스 워커의 `activate` 이벤트 단계에서 이전 버전의 캐시 스토리지를 즉시 찾아 삭제(Purge)하도록 구현하여, 사용자가 앱을 재실행하는 순간 최신 코드가 강제 로드되도록 보장했습니다.

```javascript
// 서비스 워커 activate 이벤트 예시 (Conceptual)
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames.map((cacheName) => {
          if (cacheName !== CURRENT_CACHED_VERSION) {
            return caches.delete(cacheName); // 구버전 캐시 즉시 제거
          }
        })
      );
    })
  );
});
```

### 2.2 엄지손가락 친화적(Thumb-friendly) 모바일 어드민 리팩토링

모바일 어드민의 사용성을 개선하기 위해 CSS 레이아웃 구조를 전면 개편했습니다.

* **터치 타깃 최적화**: 모바일 환경에서 사용자의 손가락 터치 오인식을 줄이기 위해 모든 주요 인터랙션 버튼의 최소 크기를 `48x48px` 이상으로 확보했습니다.
* **레이아웃 구조 전환**: 
  * 기존의 복잡한 2열 카드 스택 뷰를 모바일 화면 너비에 맞춘 **단일 컬럼(1-Column) 스택 뷰**로 재배치했습니다.
  * 상단 네비게이션은 **수평 스크롤 탭 바(Horizontal Scrollable Tab Bar)**를 적용하여, 한 손으로 스마트폰을 쥔 상태에서도 엄지손가락의 동선 내에서 식약처 수집 현황, 서버 상태, 1:1 고객 문의를 원스톱으로 전환하며 확인할 수 있게 개선했습니다.

## 3. 결과 및 성과 (Results & Takeaways)

이번 리팩토링을 통해 얻은 성과는 명확합니다.

1. **안정적인 PWA 멀티 엔바이런먼트 구축**: iOS 사파리와 안드로이드 크롬 환경 모두에서 개발/스테이징/운영 PWA 앱이 완벽하게 독립된 아이콘과 이름으로 홈 화면에 안착하게 되었습니다. 캐시 갱신 문제도 완전히 해결되어 배포 신뢰성이 높아졌습니다.
2. **모바일 장애 대응 속도 2배 이상 향상**: 현장 관리자가 스마트폰만으로도 쾌적하게 어드민을 조작할 수 있게 되면서, 실시간 장애 인지부터 1차 대응까지 소요되는 리드 타임이 눈에 띄게 단축되었습니다.

### 💡 Engineering Takeaway
> **"좋은 아키텍처는 서버 백엔드에만 국한되지 않는다."**
> 
> 이번 작업은 인프라(배포 환경 분리)와 프론트엔드(PWA 캐시 정책), 그리고 최종 사용자 경험(모바일 어드민 UI)이 어떻게 맞물려 비즈니스 가치(장애 대응 속도)로 직결되는지 보여준 좋은 사례였습니다. 개발 편의성뿐만 아니라, 시스템을 실제로 조작하는 '사람(User/Admin)'의 환경까지 고려하는 시니어리티의 중요성을 다시 한번 되새기게 되었습니다.

앞으로도 PickSafe는 안정적인 시스템 인프라 위에서 빠르고 견고한 사용자 경험을 만들어 나가는 과정을 공유하겠습니다. 감사합니다.
