안녕하세요, **PickSafe** 팀에서 프론트엔드와 웹 아키텍처를 담당하고 있는 시니어 엔지니어입니다. 

서비스가 성장함에 따라 우리는 다양한 사용자 환경(개발, 스테이징, 운영)을 마주하게 됩니다. 특히 웹 표준 기술을 활용해 네이티브 앱과 같은 사용자 경험을 제공하는 **PWA(Progressive Web App)** 환경을 구축할 때, 환경 간 경계가 모호해지면서 발생하는 사소하지만 치명적인 문제들을 겪기 쉽습니다.

이번 포스팅에서는 로컬/스테이징/운영 환경의 PWA 식별자 혼선을 해결하기 위해 적용한 **매니페스트 및 서비스 워커 캐시 버저닝 전략**, 그리고 현장 관리자의 실시간 대응 속도를 높이기 위한 **모바일 어드민 반응형 UX 리팩토링** 과정과 기술적 트레이드오프를 공유하고자 합니다.

---

## 1. 문제 정의 (Context & Problem)

프로덕션을 운영하며 맞닥뜨린 문제는 크게 두 가지였습니다.

### ① PWA 환경 식별자 및 캐시 오염 문제
로컬 개발(Dev), 스테이징(Staging), 운영(Prod) 환경의 웹앱을 모두 스마트폰 홈 화면에 추가해 테스트를 진행하는 과정에서 문제가 발생했습니다. 
* 각 환경의 `manifest.json` 속 앱 이름(`name`, `short_name`)과 아이콘 메타데이터가 명확히 분리되지 않아, 홈 화면에 설치된 아이콘만으로는 현재 접속한 앱이 어떤 환경인지 구별하기 어려웠습니다.
* 더욱이, 배포 이후에도 브라우저와 서비스 워커(Service Worker)가 이전 버전의 캐시를 붙잡고 있어 **아이콘이나 정적 리소스가 갱신되지 않는 현상**이 빈번하게 발생했습니다.

### ② 모바일 어드민의 조작성(Usability) 한계
운영진이 데스크톱 환경이 아닌 스마트폰 브라우저를 통해 긴급히 어드민에 접속해 현황을 확인해야 할 상황이 생겼습니다. 하지만 기존의 데스크톱 중심 UI를 그대로 모바일에 축소해 놓은 상태였기 때문에 다음과 같은 한계가 있었습니다.
* 관리 카드 및 네비게이션 버튼의 터치 타깃(Touch Target)이 너무 작아 오타가 빈발함.
* 2열 레이아웃이 모바일 화면 너비에 찌그러지며 정보 가독성이 극단적으로 저하됨.
* 결과적으로 모바일 환경에서의 실시간 장애 대응 속도가 떨어지는 병목 발생.

## 2. 기술적 고민과 대안 비교 (Trade-off)

### 2.1. PWA 캐시 갱신 전략: 불변성 vs 동적 캐시
서비스 워커가 정적 자산을 캐싱할 때, 리소스의 최신성을 보장하는 것은 언제나 까다로운 문제입니다.

* **대안 A (Cache-First + Query Param Versioning):** 리소스 요청 URL에 쿼리스트링을 붙여 우회하는 방식.
  * *Pros:* 구현이 비교적 단순함.
  * *Cons:* 서비스 워커 내부의 생명주기 관리와 맞물리지 않으면 여전히 이전 캐시가 살아남는 누수 발생 가능.
* **대안 B (Explicit Cache Naming & Lifecycle Purging - 선택함):** 명확한 캐시 이름(버전)을 부여하고, `activate` 이벤트 시점에 구버전 캐시를 원자적으로(Atomic) 소멸시키는 방식.
  * *Pros:* 배포 시점과 캐시 수명이 동기화되어 클라이언트가 항상 최신 자산과 매니페스트를 보장받음.
  * *Cons:* 배포 파이프라인에서 캐시 버전 관리 스크립트나 정책을 명시적으로 관리해야 함.

우리는 **대안 B**를 선택했습니다. `CACHE_NAME`을 빌드 타임 혹은 고유 버전(`picksafe-vYYYYMMDD`)으로 격리하고, 새로운 서비스 워커가 활성화되는 순간(`activate` 이벤트) 이전 세대의 캐시 스토리지를 즉시 `purge`하도록 구현했습니다.

### 2.2. 모바일 어드민 레이아웃: 반응형 축소 vs 모바일 전용 뷰어 전환
* **대안 A (CSS Media Query를 통한 단순 Flex/Grid 조정):** 기존 데스크톱 컴포넌트의 크기만 줄이는 방식.
  * *Pros:* 개발 리소스 최소화.
  * *Cons:* 엄지손가락의 터치 영역(Fitts's Law)을 고려하지 않아 모바일 UX가 여전히 불편함.
* **대안 B (Thumb-Friendly 모바일 어드민 전면 리팩토링 - 선택함):** 터치 타깃 기준 확대 및 컴포넌트 스택 구조 변경.
  * *Pros:* 모바일 환경에서 압도적인 조작 편의성과 가독성 확보.
  * *Cons:* 화면 크기에 따른 조건부 렌더링 및 스타일 분기 코드가 늘어남.

결정적으로 운영 환경의 긴급 대응력을 높이는 것이 비즈니스 임팩트가 더 크다고 판단하여 **대안 B**를 채택했습니다.

## 3. 최종 해결 및 구현 (Solution)

### ① PWA 매니페스트 및 서비스 워커 표준화
운영 환경 기준으로 매니페스트 메타데이터를 명확히 고정하고, 시작 URL과 테마 컬러를 정비했습니다.

```json
{
  "name": "PickSafe (픽세이프)",
  "short_name": "PickSafe",
  "start_url": "/?mode=standalone",
  "display": "standalone",
  "background_color": "#f8fafc",
  "theme_color": "#ffffff"
}
```

또한, 서비스 워커의 생명주기 훅을 아래와 같이 개선하여 캐시 파편화 문제를 원천 차단했습니다.

```javascript
const CACHE_NAME = 'picksafe-v20260814';

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames.map((cacheName) => {
          if (cacheName !== CACHE_NAME) {
            console.log('[ServiceWorker] Old cache purged:', cacheName);
            return caches.delete(cacheName);
          }
        })
      );
    })
  );
});
```

### ② 엄지손가락 친화적(Thumb-friendly) 모바일 어드민 구축
* **터치 타깃 확장:** 모바일 환경에서 모든 주요 버튼과 인터랙션 요소의 최소 크기를 `48x48px` 이상으로 보장하여 터치 미스릴을 줄였습니다.
* **레이아웃 구조 개편:** 좁은 화면에서 찌그러지던 2열 카드를 **1열 수직 스택(Stack) 뷰**로 전환하고, 핵심 메뉴 이동은 **수평 스크롤 탭 바**를 적용해 한 손으로도 원활한 네비게이션이 가능하도록 개선했습니다.

## 4. 성과 및 맺음말 (Takeaways)

이번 개선을 통해 얻은 성과는 다음과 같습니다.

1. **PWA 설치 경험 안정화:** iOS 사파리 및 안드로이드 크롬 환경에서 환경별(Dev/Stage/Prod) 앱 아이콘과 이름이 정확히 분리되었으며, 배포 직후 캐시 갱신 누락 이슈가 0건으로 줄어들었습니다.
2. **모바일 어드민 생산성 향상:** 현장 및 이동 중에도 관리자가 스마트폰으로 식약처 수집 현황, 서버 상태, 고객 문의에 즉각 대응할 수 있게 되면서 **모바일 환경에서의 실시간 장애 대응 속도가 2배 이상 개선**되었습니다.

사용자가 마주하는 첫 화면(PWA 매니페스트)부터 백그라운드 리소스 관리(서비스 워커), 그리고 내부 운영진의 도구(모바일 어드민)까지 디테일을 챙기는 것이 결국 서비스의 신뢰도를 결정한다는 것을 다시 한번 깨달은 작업이었습니다. 

앞으로도 PickSafe는 기술적 부채를 기민하게 해결하며 견고한 아키텍처를 만들어 나갈 것입니다. 읽어주셔서 감사합니다!
