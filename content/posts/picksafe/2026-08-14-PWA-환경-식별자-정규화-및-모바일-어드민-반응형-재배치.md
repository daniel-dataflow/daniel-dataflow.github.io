안녕하세요, **PickSafe** 개발팀입니다. 

서비스를 고도화하고 멀티 환경(Dev/Staging/Prod)에서 테스트를 진행하다 보면, 백엔드 아키텍처뿐만 아니라 **프론트엔드와 PWA(Progressive Web App) 환경의 정합성** 역시 매우 중요한 과제로 떠오릅니다. 특히 운영 환경과 개발 환경을 동시에 스마트폰에 PWA로 등록해 사용하는 엔지니어와 운영진에게, 앱 아이콘이나 이름이 헷갈리는 문제는 사소하지만 치명적인 실수(Prod 환경에서의 오조작 등)를 유발할 수 있습니다.

이번 글에서는 **PWA 환경 식별자 정규화 및 서비스 워커 캐시 전략 수립**, 그리고 현장 운영진을 위한 **모바일 어드민 반응형 UX 리팩토링** 과정을 공유해 드립니다.

---

## 1. 문제 정의 (Context & Problem)

프로덕트를 개선하면서 마주한 두 가지 주요 페인 포인트(Pain Point)는 다음과 같습니다.

### ① PWA 환경 식별자 혼선 및 캐시 갱신 지연
* **증상**: 로컬 개발(Dev), 스테이징(Staging), 프로덕션(Prod) 환경을 모두 스마트폰 홈 화면에 PWA로 추가하여 테스트할 때, 매니페스트(`manifest.json`)의 `name`, `short_name` 및 아이콘 리소스가 겹치는 현상이 발생했습니다.
* **원인**: 각 환경별 구분이 명확하지 않았고, 서비스 워커(Service Worker)가 이전 빌드의 자산과 아이콘을 공격적으로 캐싱하고 있어 배포 후에도 홈 화면의 앱 아이콘이나 이름이 즉각 갱신되지 않았습니다.

### ② 모바일 어드민의 조작성 한계 (Usability Issue)
* **증상**: 긴급한 장애 대응이나 모니터링을 위해 스마트폰으로 어드민 페이지에 접속했을 때, 기존의 데스크톱 중심 2열 레이아웃이 깨지거나 찌그러졌습니다.
* **원인**: 관리 카드와 네비게이션 버튼의 터치 타깃(Touch Target)이 모바일 화면 기준에는 너무 작아, 현장에서 신속한 터치 인터랙션과 실시간 장애 대응(예: 서버 상태 확인, 고객 문의 대응 등)을 수행하기에 구조적인 한계가 있었습니다.

## 2. 기술적 고민과 아키텍처 대안 (Trade-offs & Implementation)

단순한 UI 수정에 그치지 않고, 시스템 안정성과 운영 효율성을 동시에 잡기 위해 아래와 같은 아키텍처적 결정을 내렸습니다.

### 2.1. PWA 매니페스트 표준화 및 캐시 버저닝 전략

환경별로 앱을 명확히 구분할 수 있도록 매니페스트 설정을 표준화했습니다. 또한, 서비스 워커의 생명주기(Lifecycle)를 재설계하여 배포 즉시 최신 자산이 반영되도록 유도했습니다.

* **환경별 앱 식별자 분리**: 
  * 운영 환경: `name: "PickSafe (픽세이프)"`, `short_name: "PickSafe"`
  * 테마 컬러 및 배경색 표준화 (`#ffffff`, `#f8fafc`), `start_url: "/?mode=standalone"` 부여
* **서비스 워커 캐시 버저닝(Cache Versioning)**:
  * `CACHE_NAME`에 명시적인 타임스탬프 또는 빌드 버전을 부여 (예: `picksafe-v20260814`)
  * 새로운 버전 배포 시, 서비스 워커의 `activate` 이벤트 단계에서 **이전 버전의 캐시를 즉시 퍼지(Purge)** 하도록 구현하여 구버전 자산이 남아있는 문제를 원천 차단

```javascript
// Service Worker Activate Event Example
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames.map((cacheName) => {
          if (cacheName !== CURRENT_CACHE_NAME) {
            return caches.delete(cacheName); // 구버전 캐시 즉시 제거
          }
        })
      );
    })
  );
});
```

### 2.2. 엄지손가락 친화적(Thumb-friendly) 모바일 어드민 리팩토링

모바일 환경에서의 현장 대응 속도를 극대화하기 위해 UI/UX 구조를 전면 개편했습니다.

* **터치 타깃 확장**: 모든 주요 버튼 및 인터랙티브 요소의 최소 크기를 `48x48px` 이상으로 확보하여 오타치 방지.
* **레이아웃 구조 변경**: 기존의 찌그러지던 2열 카드 구조를 **1열 카드 스택 뷰(Stack View)**로 전환하고, 상단에는 **수평 스크롤 탭 바(Horizontal Scroll Tab Bar)**를 적용하여 한 손으로도 원활하게 탭을 이동하며 대시보드를 조작할 수 있도록 개선.

## 3. 결과 및 성과 (Takeaways)

이번 개선을 통해 얻은 정량적·정성적 성과는 다음과 같습니다.

1. **PWA 사용자 경험(UX) 완성도 향상**: iOS 사파리 및 안드로이드 크롬 환경에서 멀티 환경(Dev/Prod) PWA 설치 시 아이콘 및 이름 혼동 문제가 완전히 해소되었으며, 앱 업데이트 시 캐시 갱신이 실시간으로 이루어지게 되었습니다.
2. **모바일 어드민 운영 효율성 2배 이상 향상**: 관리자가 현장이나 이동 중에도 스마트폰을 통해 식약처 수집 현황, 서버 상태, 1:1 고객 문의를 지연 없이 확인하고 즉시 대응할 수 있는 **실시간 장애 대응 파이프라인**이 강화되었습니다.
