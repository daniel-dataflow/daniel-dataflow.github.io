화장품 및 화학물질 규제/안전 정보 서비스인 **PickSafe**에서 가장 중요한 자산은 **'데이터의 무결성(Data Integrity)'**입니다. 특히 성분을 식별하는 고유 번호인 **CAS(Chemical Abstracts Service) 번호**와 국제 성분명인 **INCI(International Nomenclature Cosmetic Ingredient)명**은 단 하나의 오차도 허용되어서는 안 되는 핵심 정보입니다.

최근 국내 식약처 데이터 수집 과정에서 CAS/INCI 정보가 누락된 일부 복합 성분 및 식물 추출물 데이터를 보강하기 위해 **다중 소스(EU CosIng, K-REACH 등) 연동 설계**를 진행했습니다. 

이 과정에서 우리 팀이 마주한 **기술적 이상과 현실의 간극**, 그리고 **과감하게 설계를 백지화하고 '인간 중심의 검증 시스템(Human-in-the-Loop)'으로 피벗(Pivot)하게 된 엔지니어링 의사결정 과정**을 공유합니다.

---

## 1. 문제 정의: 식약처 데이터의 빈틈을 어떻게 채울 것인가?

국내 식약처 API를 통해 수집되는 성분 중 약 10여 건의 특수 성분(복합 성분, 식물 추출물 등)에서 CAS 번호와 영문 INCI명이 누락되는 현상이 발견되었습니다. 기존에는 대한화장품협회(KCIA) 스크래핑 데이터만을 보완재로 사용했으나, 커버리지를 넓히기 위해 글로벌 공신력을 가진 세 가지 후보 소스를 검토했습니다.

| 후보 소스 | 연동 적합성 평가 | 채택 여부 및 방식 |
| :--- | :--- | :--- |
| **EU CosIng** | **[적합]** EU 공식 오픈데이터로 대량 다운로드 및 매칭 가능 | **우선 반영 대상 (최초 설계 시)** |
| **K-REACH** | **[보통]** 유해화학물질 등록 시스템 중심이라 화장품 성분 커버리지 불확실 | **수동 참고 링크로만 제공** |
| **PCPC / wINCI** | **[부적합]** 고가의 연간 구독제 및 API 부재 | **자동화 대상에서 제외** |

처음 수립한 이상적인 아키텍처는 **"EU CosIng의 전체 인벤토리를 로컬 DB에 캐싱(Local Caching)하여, 외부 API 호출 지연(Latency) 없이 100% 일치(Exact Match)하는 데이터를 자동으로 찾아 결합하는 파이프라인"**이었습니다.

## 2. 기술적 고민과 트레이드오프: "자동화의 달콤한 함정"

### 초기의 설계안 (Ideal Plan)
네트워크 IO로 인한 파이프라인 지연을 방지하기 위해, 매번 EU 서버에 검색 요청을 날리는 대신 **CosIng 전체 데이터를 로컬 테이블(`cosing_reference`)에 주기적으로 적재**하기로 했습니다.

```
[식약처 수집 파이프라인] 
     │
     ▼ (CAS/INCI 누락 발견)
[로컬 DB: CosIng 캐시 조회] ──(Exact Match)──► [임시 승인 대기 상태로 저장]
```

- **장점**: 수집 파이프라인 내부에서 단일 `SELECT` 쿼리 수준으로 동작하므로 오버헤드가 극히 적음.
- **제약 조건**: 오매칭 리스크를 방지하기 위해 유사도 매칭(Fuzzy Match)은 전면 배제하고 완전히 일치하는 문자열만 매칭하도록 제약 처리.

### 현실의 벽: 데이터 출처의 무결성(Data Provenance) 문제
구현 단계에 진입했을 때 치명적인 변수가 발생했습니다. **EU CosIng 공식 포털에서 전체 인벤토리를 단일 파일(CSV/JSON 등)로 일괄 다운로드하는 공식 API나 기능을 제공하지 않았던 것**입니다.

대안으로 Kaggle이나 GitHub 등지에 업로드된 서드파티(Third-party) 오픈소스 크롤링 데이터셋을 활용하는 방안이 제시되었습니다. 하지만 여기서 심각한 트레이드오프가 발생했습니다.

1. **업데이트 주기 불확실성**: 서드파티 데이터는 실시간 규제 변화를 반영하지 못합니다.
2. **출처의 불완전성**: 신뢰할 수 없는 스크래핑 데이터로 인해 잘못된 CAS 번호가 PickSafe DB에 유입될 경우, 규제 정보 서비스로서의 신뢰도가 통째로 무너집니다.

> **"무결성이 보장되지 않는 자동화는, 수동 작업보다 훨씬 비싼 비용(데이터 오염)을 치르게 만든다."**

우리는 과감하게 **CosIng 로컬 캐시 연동 계획을 전면 백지화(Rollback)**하기로 결정했습니다.

## 3. 최종 해결책: 오퍼레이터의 생산성을 극대화하는 '수동 검증 도구'로의 피벗

자동 매칭을 포기하는 대신, 관리자가 직접 눈으로 확인하고 1초 만에 교정할 수 있도록 **어드민 검증 도구(Human-in-the-Loop)의 편의성을 극대화하는 방향**으로 노선을 틀었습니다.

### 해결책 1. 지능형 수동 검색 라우팅 (K-REACH 연동)
관리자가 외부 사전을 일일이 검색하는 낭비를 줄이기 위해, 기존 KCIA/CosIng 버튼 옆에 환경부의 **K-REACH 시스템 다이내믹 검색 링크**를 추가했습니다.

```python
# 관리자 포털에서 검색 버튼 클릭 시 동작하는 동적 라우팅 예시 (Concept Code)
def get_kreach_search_url(ingredient_name_ko: str, ingredient_name_en: str | None) -> str:
    # 영문 INCI명이 존재하면 영문명으로 검색, 없으면 국문명으로 분기하여 정확도 향상
    search_query = ingredient_name_en if ingredient_name_en else ingredient_name_ko
    base_url = "https://kreach.example.go.kr/search"  # 실제 외부 엔드포인트는 보안상 마스킹 처리
    return f"{base_url}?query={encode_uri_component(search_query)}"
```

### 해결책 2. 원스톱 CAS / INCI 동시 편집 폼 구축
기존에는 CAS 번호만 교정할 수 있었으나, 실제 현업에서는 INCI명도 동시에 비어있는 경우가 많았습니다. 이에 입력 폼을 개선하여 **CAS 번호와 영문 INCI명을 한 화면에서 상하로 배치해 원클릭으로 백엔드에 반영하고 동시 갱신**할 수 있도록 구현했습니다.

### 해결책 3. 극한의 가독성을 위한 UI 레이아웃 최적화
화학 물질명은 한국어든 영어든 극단적으로 깁니다. (예: `2-알킬-N-카복시메틸-N-하이드록시에틸이미다졸리늄베타인` 등)
데이터 검수 화면에서 글자가 찌그러지거나 테이블 레이아웃이 깨지면 오퍼레이터의 피로도가 극도로 올라갑니다.

이를 해결하기 위해 CSS Grid와 Flexbox를 조합하여 다음과 같은 UI 수정을 진행했습니다.
- **최소 너비 방어선 구축**: 가로 스크롤(Swipe) 최소 범위를 지정하여 화면이 좁아져도 컬럼이 압착되거나 텍스트가 세로로 찢어지는 현상 방지.
- **정보 우선순위 배치**: `실패/경고 사유 > 성분명(국문) > INCI명(영문)` 순으로 가로 비율을 우선 널찍하게 할당.
- **유연한 요소 배치(Wrap 적용)**: '사전 검색' 단추 세트들은 가로 공간 부족 시 찌그러지는 대신 아래 줄로 자연스럽게 흐르도록(Flex Wrap) 처리.

## 4. 이번 스프린트에서 얻은 엔지니어링 교훈 (Takeaways)

1. **자동화는 은총알(Silver Bullet)이 아니다**
   엔지니어는 모든 것을 코드로 자동화하고 싶어 하는 본능이 있습니다. 하지만 **연동 소스의 신뢰성이 담보되지 않는다면, 훌륭하게 설계된 자동화 파이프라인은 단지 '쓰레기를 더 빠르게 수집하는 도구'로 전락**할 뿐입니다. 

2. **도메인 특성을 고려한 현실적인 타협(Trade-off)**
   B2C 커머스나 일반 서비스와 달리, **'규제/안전(Safety-Critical)' 도메인에서는 99%의 자동화보다 100%의 정확성이 우선**입니다. 이때는 신뢰성이 낮은 자동 매칭 대신, 잘 설계된 검증 UI(Human-in-the-Loop)를 제공하는 것이 비즈니스와 기술 모두에 이득입니다.

3. **피벗(Pivot)은 실패가 아니라 고도화 과정이다**
   구현 단계에서 기획과 아키텍처를 뒤엎는 것은 뼈아프지만, **더 큰 데이터 재앙을 사전에 예방했다는 점에서 값진 의사결정**이었습니다. 이번 실패 경험을 발판 삼아, 향후 EU CosIng의 공식 대량 다운로드 기능이 릴리즈되면 즉시 도입할 수 있는 준비 태세를 갖추게 되었습니다.
