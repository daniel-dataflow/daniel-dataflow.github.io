제품을 개발하다 보면 **"모든 것을 자동화해야 한다"**는 엔지니어링적 욕심에 빠지기 쉽습니다. 특히 외부 데이터 수집 파이프라인을 구축할 때, 사람의 개입 없이 스케줄러가 알아서 부족한 식별 정보(CAS No., INCI명 등)를 채워주는 아키텍처는 매력적으로 보입니다.

하지만 **규제 준수(Compliance) 및 안전 데이터를 다루는 도메인**이라면 이야기가 달라집니다. 데이터 하나가 잘못 매칭되는 순간, 서비스 전체의 신뢰성이 무너질 수 있기 때문입니다.

이번 포스팅에서는 성분 데이터의 신뢰성 향상을 위해 **EU CosIng(유럽 화장품 성분 데이터베이스)** 자동 연동 파이프라인을 설계하고 검토했다가, **데이터 출처 무결성(Data Provenance) 문제로 이를 전면 백지화하고 'Human-in-the-Loop(HITL)' 방식으로 피벗(Pivot)한 의사결정 과정**을 공유합니다.

---

## 1. 문제 정의: 식약처 성분 데이터의 빈틈

안전성 분석 플랫폼 **PickSafe**는 국내외 여러 정부/공공기관의 성분 공시 데이터를 기반으로 작동합니다. 그러나 공공 API나 스크래핑 데이터셋은 불완전한 경우가 많습니다.

* **식약처 공시 데이터의 한계:** 복합 성분, 식물 추출물 등의 경우 표준 **INCI(국제 화장품 성분명)** 또는 **CAS 번호(화학물질 고유 번호)**가 누락(캡처/분석 기준 다수 발생)되어 존재했습니다.
* **영향:** 식별 데이터가 비어있으면 데이터간 교차 검증이 불가능해지고, 결국 유저에게 정확한 규제/안전 정보를 전달하기 어려워집니다.

이를 보완하기 위해 기존 **KCIA(대한화장품협회)** 외에 **EU CosIng**, **K-REACH(환경부)** 등 다중 소스를 연동해 CAS/INCI 식별자를 보완하는 아키텍처 확장을 기획하게 되었습니다.

---

## 2. 초기 아키텍처 설계와 기술적 고민

처음 구상했던 아키텍처의 핵심 원칙은 **"속도에 영향을 주지 않는 로컬 캐시 기반 자동 매칭"**이었습니다.

```
[식약처 API 데이터 수집]
       │
       ▼
(INCI/CAS 누락 발생?)
       │
       ├─► (Yes) ──► [EU CosIng 로컬 캐시 DB 조율] ──► [정확도 100% 매칭 시 자동 채움]
       │
       └─► (No) ───► [정상 적재]
```

### 왜 실시간 스크래핑 대신 대량 다운로드 방식을 선택했는가?
1. **네트워크 지연 및 부하 최소화:** 식약처 데이터 수집 루프 내에서 외부 API/웹사이트를 매번 실시간 조회하면 수집 파이프라인 전체가 병목에 빠집니다.
2. **사고 방지 (유사도 매칭 배제):** 기존 검색 스크래핑 방식에서 일어날 수 있는 '유사도 상위 항목 오매칭' 위험을 없애기 위해, 전체 인벤토리를 로컬 DB에 구축하고 **100% 완전 일치(Exact Match)**하는 건만 자동으로 찾아내려 했습니다.

---

## 3. 대전환: 왜 자동 연동 파이프라인을 전면 백지화했는가?

기획 및 검토 단계에서 치명적인 블로커(Blocker)를 발견했습니다.

### 🔴 데이터 출처(Provenance) 및 무결성 문제
* **EU CosIng 공식 포털**은 전체 인벤토리를 단일 파일(CSV/JSON 등)로 일괄 제공하는 공식 API/다운로드 기능을 지원하지 않았습니다.
* 대안으로 **Kaggle이나 GitHub 등 3rd-Party 오픈소스 스크래핑 데이터셋**을 활용하는 방안을 검토했습니다.
* **위험 평가:** 비공식 데이터셋은 **① 데이터의 갱신 주기를 신뢰할 수 없고 ② 데이터 정제 과정에서의 무결성을 보장할 수 없다**는 결론에 도달했습니다.

> **"오염된 외부 데이터가 자동화 파이프라인을 통해 DB에 유입되면, 잘못된 규제 데이터가 서비스에 노출된다."**

규제 데이터 관리 플랫폼인 PickSafe의 기준에서 이는 절대 용납할 수 없는 리스크였습니다. 따라서 엔지니어링 팀은 **EU CosIng 자동 매칭 및 로컬 캐시 구축 시스템 전체를 전면 백지화(Scrap)**하기로 결정했습니다.

---

## 4. 최종 해결책: 'Human-in-the-Loop' 도구 고도화

자동화가 불가능하다면, **"관리자(Domain Expert)가 가장 빠르고 정확하게 데이터를 검증하고 수정할 수 있는 환경"**을 만드는 것으로 전략을 피벗(Pivot)했습니다.

```
[식약처 데이터 수집] ──► [미식별 성분 발생] ──► [관리자 통합 검토 UI]
                                                      │
                                   ┌──────────────────┼──────────────────┐
                                   ▼                  ▼                  ▼
                             [KCIA 원클릭]      [CosIng 원클릭]    [K-REACH 원클릭]
                                   └──────────────────┼──────────────────┘
                                                      ▼
                                           [인라인 CAS/INCI 동시 수정] ──► [DB 반영]
```

### 1) 다중 소스 딥링크(Deep Linking) 시스템 구축
관리자가 외부 데이터베이스 사이트에 들어가 성분명을 직접 재검색하는 번거로움을 줄이기 위해, **원클릭 외부 사전 검색 시스템**을 구현했습니다.
* **KCIA**, **CosIng**과 더불어 **K-REACH(환경부 유해화학물질 시스템)** 라우팅 버튼을 추가했습니다.
* 성분 데이터의 구조에 따라 **영문 INCI가 존재할 때는 영문 검색, 없을 때는 국문 성분명 검색으로 자동 분기 처리**하도록 동적 파라미터를 적용했습니다.

### 2) 인라인 원자적 입력(Atomic Inline Editing) 폼 제공
기존 UI는 CAS 번호만 교정할 수 있어 INCI명이 누락된 건을 처리하기 어려웠습니다.
* CAS 입력창과 **INCI 영문명 입력창을 상하로 나란히 배치**하여, 관리자가 외부 사전에서 확인한 두 식별자를 한 번에 입력하고 백엔드로 반영할 수 있도록 개선했습니다.

### 3) 대용량 트래픽 및 좁은 화면을 고려한 UX 최적화
관리자 화면의 데이터 밀도가 높아짐에 따라 발생하던 UI 깨짐 현상을 방지했습니다.

```css
/* 테이블 컬럼 찌그러짐 및 텍스트 찢어짐 방지 CSS 예시 */
.admin-table-cell-cause {
  min-width: 240px;
  word-break: keep-all;
}

.search-button-group {
  display: flex;
  flex-wrap: wrap; /* 공간 부족 시 자연스러운 2줄 배치가 가능하도록 설계를 변경 */
  gap: 4px;
}
```
* **공간 배분 우선순위 부여:** `실패 사유 > 성분명(국문) > INCI명(영문)` 순으로 가로 넓이 최소 기준을 보장했습니다.
* **Button Wrap 대응:** 반응형 화면 크기에 맞춰 '사전 검색' 버튼 세트가 세로로 찢어지지 않고 자연스럽게 다음 줄로 라인 랩(Wrap)되도록 개선하여 작업 효율성을 높였습니다.

## 5. 엔지니어링 교훈 (Takeaway)

### 1. "안전한 데이터가 빠른 자동화보다 우선한다"
모든 문제를 자동화 코드로 풀 필요는 없습니다. 특히 **데이터 무결성이 서비스의 핵심 가치**일 때, 신뢰할 수 없는 외부 소스를 자동화에 편입시키는 것은 기술 부채를 넘어 비즈니스 리스크가 됩니다.

### 2. 백지화(Scrap)도 훌륭한 엔지니어링 의사결정이다
이미 기획된 기능을 구현하는 것보다, **위험 요소를 사전에 파악하고 계획을 철회하는 결단**이 시스템 전체의 품질을 지킵니다.

### 3. Human-in-the-Loop (HITL) 시스템의 중요성
자동화를 철회한 대안으로 관리자 도구를 극도로 효율화(단축키, 딥링크, 레이아웃 최적화)함으로써, **정확도 100%를 유지하면서도 작업 생산성을 기존 수동 방식 대비 300% 이상 향상**시킬 수 있었습니다.
