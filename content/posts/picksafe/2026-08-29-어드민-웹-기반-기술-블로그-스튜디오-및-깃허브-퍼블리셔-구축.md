안녕하세요, PickSafe Core Architecture Team입니다.

우리는 그동안 서비스 내부의 수많은 기술적 고민과 아키텍처 결정을 55개의 아키텍처 의사결정 문서(ADR, Architecture Decision Record)로 축적해 왔습니다. 그리고 이 소중한 지식 자산을 외부 개발자 커뮤니티 및 동료 엔지니어들과 나누기 위해 대외 공개용 기술 블로그(`daniel-dataflow.github.io`) 운영을 기획했습니다.

하지만 블로그 자동화를 구축하는 과정에서 **"개발자의 손길을 거치지 않는 완전 자동화의 한계"**라는 벽에 부딪히게 되었고, 이를 해결하기 위해 사내 어드민 내부에 **원스톱 블로그 스튜디오(Blog Studio)**를 직접 구축하게 되었습니다. 

이번 글에서는 100% 자동화의 딜레마를 어떻게 해결했으며, FastAPI와 현대적인 웹 기술을 활용해 어떻게 '개발자 친화적인 마이크로 CMS'를 설계했는지 그 기술적 의사결정 과정(ADR)을 공유합니다.

---

## 1. 배경 및 문제 정의: 왜 '자동화'만으로는 부족했을까?

초기 구상은 심플했습니다. `docs/decisions/` 경로에 쌓이는 ADR 마크다운 파일을 GitHub Actions를 통해 파이썬 스크립트로 파싱한 뒤, 블로그 레포지토리에 자동으로 커밋·푸시하는 **100% 전면 자동화 파이런라인**을 구축하는 것이었죠. 

하지만 시제품을 테스트해보며 치명적인 한계들을 마주했습니다.

1. **검수 불가 딜레마와 유실 위험**
   - 사내 문서는 엔지니어링 관점의 날것의 정보가 많아, 외부 독자들이 이해하기 쉬운 문맥, 강조 포인트, 생생한 디테일을 가미하는 '사람의 손길'이 필수적이었습니다.
   - 만약 블로그 레포지토리에서 직접 글을 수정한다면, 추후 내부 저장소에서 단방향 동기화가 일어날 때 수정본이 덮어씌워져 유실될 위험이 컸습니다.
2. **시각적 검증(WYSIWYG)의 부재**
   - 텍스트 기반의 마크다운만으로는 실제 웹 브라우저에서 제목 서식, 줄바꿈, 글 중간 이미지 배치가 어떻게 렌더링될지 실시간으로 확인하기 어려웠습니다.
3. **복잡한 개발 도구 의존성**
   - 글 하나를 발행하기 위해 매번 터미널을 열고 Git 명령어나 파이썬 수동 스크립트를 실행하는 것은 프로덕트 팀의 생산성을 떨어뜨리는 요인이었습니다.

> **"브라우저 어드민 화면에서 '선택 ➔ AI 초안 ➔ 직접 수정 & 이미지 드래그앤드롭 ➔ 원클릭 발행'이 가능한 원스톱 CMS 솔루션이 필요하다."**

## 2. 시스템 아키텍처 및 작업 흐름 (Architecture & Workflow)

이러한 문제를 해결하기 위해, 우리는 별도의 무거운 외부 CMS(Wordpress 등)를 도입하는 대신 **현재 운영 중인 FastAPI 백엔드와 어드민 웹 인터페이스를 확장**하여 가볍고 강력한 자체 블로그 스튜디오를 구현했습니다.

## 3. 세부 기술 명세 및 설계 포인트

### 1) 백엔드: FastAPI를 활용한 유연한 콘텐츠 파이프라인 (`app/routers/admin/blog.py`)
FastAPI의 비동기 처리 능력과 직관적인 라우팅 구조를 활용해 블로그 스튜디오의 코어 API를 구현했습니다.

* **문서 파싱 (`GET /admin/api/blog/decisions`)**: `docs/decisions/` 디렉토리를 스캔하고, 연대순 인덱스 메타데이터(`README.md`)를 기반으로 55개의 ADR을 정렬하여 번호, 제목, 작성일자, 초안 상태를 JSON으로 반환합니다.
* **보안 마스킹 및 AI 초안 생성 (`POST /admin/api/blog/generate-draft`)**: 
  - 외부 공개 시 문제가 될 수 있는 사내 비즈니스 로직, 내부 API 엔드포인트, 민감한 키 값 등을 정규식 및 LLM 프롬프트를 통해 안전하게 마스킹합니다.
  - Gemini API를 호출하여 딱딱한 기술 문서 포맷을 독자 친화적인 기술 블로그 포맷 초안으로 1초 만에 변환합니다.
* **이미지 처리 (`POST /admin/api/blog/upload-image`)**: 에디터 본문에 드래그 앤 드롭된 이미지를 안전하게 서버에 캐싱하고, 마크다운에 즉시 삽입될 수 있는 상대/절대 경로를 반환합니다.
* **원클릭 깃허브 퍼블리시 (`POST /admin/api/blog/publish`)**: 검수가 완료된 최종 마크다운과 에셋을 **GitHub REST API**를 통해 대외 블로그 레포지토리(`daniel-dataflow.github.io`)의 지정된 경로에 직접 커밋 & 푸시합니다.

### 2) 프론트엔드: 3단 반응형 스튜디오 UI
개발자가 글쓰기에만 온전히 집중할 수 있도록 UI/UX를 설계했습니다.
* **문서 탐색기 (좌측)**: 55개의 방대한 ADR 목록을 실시간 검색하고, 작성일 뱃지로 가독성을 높였습니다.
* **스마트 마크다운 에디터 (중앙)**: 자주 사용하는 서식 툴바, 단축키, 그리고 무엇보다 **이미지 드래그 앤 드롭**을 지원하여 별도의 파일 업로드 창을 띄울 필요가 없습니다.
* **실시간 라이브 렌더링 뷰포트 (우측)**: 타이핑하는 즉시 실제 블로그와 100% 동일한 디자인으로 결과물을 미리 볼 수 있는 스플릿 뷰를 제공합니다.

## 4. 도입 이점 및 엔지니어링 Takeaways

이번 블로그 스튜디오 구축을 통해 우리는 다음과 같은 명확한 이점을 얻었습니다.

1. **개발 생산성과 콘텐츠 퀄리티의 동시 확보**: 
   - AI가 80%의 초안 작성과 보안 마스킹(고단한 반복 작업)을 대신하고, 개발자(대표님 및 코어 팀)는 20%의 핵심 인사이트와 문맥을 다듬는 데만 집중할 수 있게 되었습니다.
2. **무결하고 안전한 배포 파이프라인**: 
   - 자동화의 편리함은 취하되, 사람이 직접 눈으로 최종 검수한(Human-in-the-loop) 완성본만 배포되므로 동기화 충돌이나 민감 정보 유출(Security Leak) 위험을 원천 차단했습니다.
3. **로컬/프로덕트 환경 완벽 호환**: 
   - 복잡한 SaaS CMS를 도입하지 않고 사내 모놀리식/마이크로서비스 백엔드(FastAPI) 내부에 간결하게 녹여내어 로컬 개발 환경(`http://localhost:8100/admin/blog`)에서도 동일하게 테스트 및 활용이 가능합니다.

우리와 함께 안전하고 확장 가능한 기술 문화를 만들어갈 동료들의 많은 관심 바랍니다. 감사합니다!
