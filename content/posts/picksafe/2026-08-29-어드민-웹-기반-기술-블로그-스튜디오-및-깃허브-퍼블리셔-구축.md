안녕하세요, PickSafe Core Architecture Team입니다. 

PickSafe는 그동안 축적해 온 55개의 기술 의사결정 문서(ADR)를 대외 기술 블로그(`daniel-dataflow.github.io`)를 통해 투명하게 공유하고 있습니다. 하지만 내부 문서를 외부 블로그로 전환하는 과정에서 **"자동화의 편리함"**과 **"콘텐츠 품질 검수의 중요성"** 사이의 딜레마에 부딪혔습니다.

이번 포스팅에서는 이 문제를 해결하기 위해 내부 어드민 웹 내부에 구축한 **'기술 블로그 스튜디오(Blog Studio)'**의 아키텍처와 기술적 고민(Trade-off), 그리고 엔지니어링 교훈을 공유합니다.

---

## 1. Problem: 전면 자동화의 딜레마와 개발자 도구 의존성

초기에는 GitHub Actions를 활용해 내부 ADR 문서를 자동으로 퍼블리시하는 100% 자동화 파이프라인을 고려했습니다. 하지만 다음과 같은 치명적인 한계가 있었습니다.

1. **검수 불가 딜레마**: 개발자가 실제 발행될 글의 문맥, 강조 포인트, 시각적 디테일을 사전에 확인하기 어렵습니다. 만약 블로그 레포지토리에서 직접 글을 수정하더라도, 추후 단방향 동기화 과정에서 수정본이 덮어씌워져 유실될 위험이 있었습니다.
2. **시각적 피드백 부재**: 마크다운 원문 텍스트만으로는 웹 브라우저에서 제목 서식, 줄바꿈, 이미지 배치가 어떻게 보일지 실시간으로 검증하기 힘들었습니다.
3. **복잡한 개발 도구 의존성**: 글을 하나 발행하기 위해 매번 터미널에서 Git 명령어나 파이썬 스크립트를 실행해야 하는 번거로움이 있었습니다.

> **"브라우저 어드민 화면에서 '선택 ➔ AI 초안 ➔ 직접 수정 & 이미지 업로드 ➔ 원클릭 발행'이 가능한 원스톱 CMS가 필요하다."**

---

## 2. Architecture & Trade-off: 어떻게 설계할 것인가?

우리는 별도의 외부 CMS(예: WordPress, Notion 연동 등)를 도입하는 대신, 이미 구축되어 있는 **FastAPI 백엔드와 어드민 웹 인터페이스 내부에 '블로그 스튜디오'를 통합**하는 방식을 채택했습니다.

```mermaid
flowchart LR
    subgraph Admin_Frontend [어드민 기술 블로그 스튜디오 UI]
        A1[55개 ADR 문서 선택] --> A2[AI 초안 생성]
        A2 --> A3[스플릿 웹 에디터<br/>직접 수정 & 이미지 드래그앤드롭]
        A3 --> A4[깃허브 블로그 즉시 발행]
    end

    subgraph Backend_Engine [FastAPI 백엔드 서비스]
        B1[연대순 문서 파서]
        B2[AI 기반 보안 마스킹]
        B3[이미지 로컬 캐싱]
        B4[GitHub REST API 연동]
    end

    A1 --> B1
    A2 --> B2
    A3 --> B3
    A4 --> B4
    B4 --> C[🌐 외부 블로그 배포 완료]
```

### 주요 기술 스택 및 구현 방식

1. **백엔드 (`app/routers/admin/blog.py`)**
   - **문서 파싱**: `docs/decisions/` 디렉토리의 마크다운을 연대순 목록(`README.md`)에 맞춰 파싱하여 메타데이터와 함께 반환합니다.
   - **AI 초안 생성**: 선택된 ADR 문서를 LLM API로 전달하되, **사내 보안 정보(내부 엔드포인트, 비밀 키 등)를 철저히 마스킹**한 뒤 매력적인 기술 블로그 포맷으로 변환합니다.
   - **GitHub REST API 연동**: 최종 승인된 마크다운과 이미지를 별도의 Git 클라이언트 설치 없이 GitHub REST API를 통해 타겟 블로그 레포지토리에 직접 커밋 & 푸시합니다.

2. **프론트엔드 (`blog.html`, `blog.js`, `blog.css`)**
   - **3단 반응형 레이아웃**: 좌측에는 55개 ADR 탐색기, 중앙에는 마크다운 에디터, 우측에는 실시간 라이브 렌더링 뷰포트를 배치하여 생산성을 극대화했습니다.

---

## 3. Takeaway: 무엇을 배웠는가?

1. **AI는 대체재가 아닌 '가속기' (AI 80% + Human 20%)**:
   - 100% 완전 자동화는 예외 케이스(보안 유출, 어색한 문맥)에 취약합니다. AI가 초안의 80%를 빠르게 작성하고, 개발자가 나머지 20%의 디테일을 다듬는 구조가 콘텐츠 품질과 생산성 모두를 잡는 가장 이상적인 형태임을 확인했습니다.
2. **도구의 단순화가 곧 생산성**:
   - 개발자가 터미널을 떠나 익숙한 브라우저 어드민 환경에서 마우스 드래그 앤 드롭과 클릭 한 번으로 콘텐츠를 발행할 수 있게 되면서, 기술 지식 공유 주기가 획기적으로 단축되었습니다.
3. **보안과 자동화의 공존**:
   - 내부 시스템과 외부 퍼블릭 블로그를 연결할 때, 자동화 파이프라인 단계에서 민감 정보(시크릿, 내부망 주소 등)를 원천 차단하는 필터링 로직이 필수적임을 재인식했습니다.

PickSafe는 앞으로도 개발자 경험(DevEx)을 높이고, 기술적 성과를 투명하게 공유하기 위한 인프라를 지속적으로 고도화해 나갈 것입니다.
