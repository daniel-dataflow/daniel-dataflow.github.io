안녕하세요, PickSafe Core Architecture Team입니다.

스타트업이나 테크 기업이 성장하면서 마주하는 공통된 고민 중 하나는 **"우리가 치열하게 고민하고 내린 기술적 의사결정을 어떻게 대외에 효과적으로 공유할 것인가"**입니다. PickSafe 역시 그동안 쌓아온 55개의 아키텍처 의사결정 문서(ADR)를 퍼블릭 기술 블로그(`daniel-dataflow.github.io`)에 발행해야 하는 과제를 안고 있었습니다.

처음에는 GitHub Actions를 이용해 내부 문서를 외부 블로그 레포지토리에 100% 자동 동기화하는 방식을 고려했습니다. 하지만 이 방식은 치명적인 한계에 부딪혔습니다.

이번 포스팅에서는 **전면 자동화의 딜레마를 극복하고, 개발 및 검수 경험을 극대화하기 위해 사내 어드민 웹 내에 '블로그 스튜디오(Blog Studio)'를 구축하게 된 기술적 의사결정 과정(ADR)**을 공유합니다.

---

## 1. 배경 및 문제 정의 (Context & Problem Statement)

기술 블로그 운영을 자동화하려 할 때 마주한 문제는 크게 세 가지였습니다.

### 1) 전면 자동화의 검수 불가 딜레마
GitHub Actions 기반의 100% 자동 변환은 휴먼 에러를 줄여주지만, **실제 발행될 글의 문맥, 개발자의 생생한 회고, 비즈니스적 강조 포인트 등을 사전에 눈으로 확인하고 보충하기 어렵다**는 단점이 있었습니다. 
그렇다고 외부 블로그 레포지토리에서 직접 글을 수정하자니, 추후 사내 시스템에서 변경된 문서를 단방향 동기화하는 과정에서 **수정본이 덮어씌워져 유실될 위험**이 존재했습니다.

### 2) 마크다운 렌더링 및 이미지 배치 확인의 어려움
순수 마크다운 원문 텍스트만으로는 실제 웹 브라우저에서 제목 서식, 줄바꿈, 글 중간 이미지 배치가 어떻게 보일지 실시간 시각적 검증이 불가능했습니다. 

### 3) 개발 도구 의존성 탈피 필요
글을 하나 올릴 때마다 매번 터미널에서 Git 명령어를 치거나 파이썬 스크립트를 수동 실행하는 것은 에디터 입장에서 피로도가 높았습니다. 브라우저 어드민 화면에서 **"선택 ➔ AI 초안 ➔ 직접 수정 및 이미지 드래그앤드롭 ➔ 원클릭 발행"**이 가능한 직관적인 원스톱 CMS 솔루션이 절실했습니다.

## 2. 시스템 아키텍처 및 작업 흐름 (Architecture & Workflow)

이러한 문제를 해결하기 위해, FastAPI 기반의 백엔드 엔진과 글래스모피즘 기반의 3단 반응형 웹 에디터를 결합한 **'Blog Studio'**를 설계했습니다.

## 3. 세부 기술 명세 및 구현 (Technical Specifications)

### 1) 백엔드 블로그 관리 라우터 (`app/routers/admin/blog.py`)
FastAPI를 활용해 문서 파싱부터 외부 퍼블리싱까지의 파이프라인을 구축했습니다.

* **문서 탐색 및 파싱**: 저장소 내의 ADR 문서들을 연대순 목록 순서대로 파싱하여 번호, 제목, 작성일자, 초안 상태를 JSON으로 반환합니다.
* **AI 초안 생성**: LLM API를 연동하여 선택한 ADR 문서 내의 영업비밀이나 내부 보안 정보를 자동으로 마스킹하고, 대중이 읽기 매력적인 기술 블로그 포맷의 초안을 1초 만에 생성합니다.
* **이미지 처리**: 에디터 본문에 드래그 앤 드롭된 이미지를 서버에 안전하게 캐싱하고 마크다운 삽입 경로를 반환합니다.
* **원클릭 퍼블리싱**: 최종 수정된 마크다운과 이미지를 **GitHub REST API**를 통해 외부 블로그 레포지토리의 지정된 경로로 직접 커밋 & 푸시(`git commit & push`)합니다.

### 2) 프론트엔드 3단 반응형 블로그 스튜디오 UI
사용자 경험(UX)을 극대화하기 위해 프론트엔드를 세 개의 영역으로 분할했습니다.
1. **문서 탐색기 (좌측)**: 55개의 ADR 목록과 작성일 뱃지, 실시간 검색 필터 제공
2. **스마트 마크다운 에디터 (중앙)**: 서식 툴바, 단축키, 이미지 드래그 앤 드롭 지원
3. **실시간 라이브 렌더링 뷰포트 (우측)**: 타이핑 즉시 실제 블로그와 100% 동일한 뷰포트로 실시간 렌더링 확인

## 4. 트레이드오프와 배운 점 (Trade-offs & Takeaways)

### 왜 완전 자동화 대신 '휴먼 인 더 루프(Human-in-the-loop)' CMS를 선택했는가?
초기에는 '모든 문서를 일괄 변환하여 푸시하는 파이프라인'을 구축하는 것이 비용이 적게 들 것으로 보였습니다. 하지만 기술 블로그는 단순한 데이터 이관이 아니라, **"외부 독자에게 우리 회사의 기술적 성숙도를 어필하는 브랜딩 수단"**입니다. 

기계적인 변환 과정에서 발생할 수 있는 문맥의 유실, 민감한 보안 정보 노출 위험, 그리고 시각적 완성도 저하라는 트레이드오프를 방지하기 위해 **"AI가 80%의 뼈대를 잡고, 개발자(에디터)가 20%의 디테일을 완성하는 구조"**를 택했습니다. 결과적으로 자동화의 편리함과 수동 검수의 무결성을 모두 잡을 수 있었습니다.

## 5. 기대 효과 및 마무리 (Benefits)

* **개발 환경 완벽 호환**: 로컬 개발 서버 환경에서도 브라우저만 열면 언제든지 즉시 콘텐츠를 생산할 수 있습니다.
* **생산성과 퀄리티의 동반 상승**: AI 초안과 개발자의 세심한 터치가 만나 최고 퀄리티의 포스팅을 단 몇 분 만에 발행할 수 있게 되었습니다.
* **무결점 배포**: 덮어쓰기로 인한 데이터 유실 걱정 없이, 검수가 끝난 완성본만 정확하게 타겟 레포지토리에 반영됩니다.

PickSafe는 앞으로도 내부의 치열한 기술적 고민들을 이러한 도구들을 통해 투명하고 매력적인 방식으로 외부 개발자 생태계와 공유해 나갈 예정입니다. 많은 관심 부탁드립니다!
