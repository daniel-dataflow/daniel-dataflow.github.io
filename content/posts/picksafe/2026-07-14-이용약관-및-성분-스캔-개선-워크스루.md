## 1. 글로벌 규정 준수를 위한 약관 동의(TOS) 체계 및 다국어 폴백 설계

글로벌 유저 베이스를 확장함에 따라, 각국 법률 요건을 충족하는 유연한 약관 동의 프로세스가 필수적이었습니다.

* **동의 순서 표준화**: `이용약관(TOS) -> 개인정보처리방침 -> 민감정보 동의` 순으로 플로우를 고정하고, 온보딩 단계에서 누락 시 즉시 리다이렉트되도록 방어 로직을 구현했습니다.
* **다국어 폴백 체인(Fallback Chain)**: 
  다양한 국가의 유저를 위해 `요청 언어` $\rightarrow$ `영어(en)` $\rightarrow$ `한국어(ko)` 순으로 순차 탐색하는 폴백 체인을 구축하여, 번역 데이터가 누락되더라도 서비스가 중단되지 않고 기본 영어 버전이 안전하게 렌더링되도록 설계했습니다.

## 2. [Troubleshooting] 외부 API 실시간 호출 병목 및 오발 매칭 해결 (Option B)

### 🚨 마주한 문제 (Problem)
초기 스캔 시스템은 캐시나 DB에 미매칭된 성분을 마주할 때마다 외부 식약처 API를 실시간으로 탐색했습니다. 이 과정에서 두 가지 치명적인 문제가 발생했습니다.
1. **성능 저하 (3분 딜레이)**: 노이즈 문자열이 대량 포함된 이미지를 스캔할 경우 외부 API 호출이 누적되어 응답 속도가 3분 이상 소요되는 심각한 지연 현상 발생.
2. **오발 매칭 (False Positive)**: 유사 검색 결과의 첫 번째 항목(예: '가공소금' 등)이 노이즈 문자열에 임의로 매핑되는 데이터 오염 현상 발생.

### 🛠️ 기술적 고민과 대안 비교 (Trade-off)
* **대안 A (전체 사전 일괄 다운로드)**: 외부 API를 실시간으로 호출하지 않고 모든 데이터를 미리 적재하는 방식. 
  * *한계*: 데이터의 변동성이 크고 초기 적재 비용이 과도하게 큼.
* **대안 B (엄격한 검증 및 제한이 포함된 실시간 조회)**: 외부 API를 활용하되, **정확 일치 검증(Exact Match)**과 **호출 상한선(Rate Limit)**을 두어 안전장치를 강화하는 방식. (선택)

### ✨ 최종 해결 (Option B 재설계)
* **정확 일치 검증 도입**: API로 반환된 성분명(한글/영문)을 스캔 문자열과 정규화(공백 제거, 대소문자 통일)하여 **완벽히 일치하는 경우에만** 캐싱 및 매치 판정을 내리도록 변경했습니다.
* **스캔당 호출 상한선(Max 5 Limit) 제어**: 1회 스캔 요청 시 외부 API 호출을 최대 5회로 제한하여, 노이즈가 많은 입력값에도 시스템이 1~2초 내에 고속 응답할 수 있도록 방어벽을 구축했습니다.
* **결과**: 스캔 응답 속도가 **3분에서 1초 이내**로 대폭 단축되었으며, 임의 매칭 현상이 원천 차단되었습니다.

## 3. 대규모 데이터 동기화를 위한 백그라운드 스케줄러와 어드민 대시보드

약 2만 2천여 개에 달하는 식약처 공공 성분 데이터를 안정적으로 관리하고 모니터링하기 위해 아키텍처를 확장했습니다.

* **FastAPI 이벤트 기반 스케줄러**: 
  웹 서비스 기동(`startup` 이벤트)과 동시에 백그라운드 상시 비동기 스레드 루프(`seeding_scheduler_loop`)를 구동하여, 설정된 주기에 따라 전체 성분 데이터 동기화 배치를 안전하게 실행합니다.
* **실패 데이터 격리 및 CAS 교정 메커니즘**:
  데이터 포맷 불량 등으로 수집에 실패한 이력은 전용 스키마(`ingredient_seed_errors`)에 분리 저장합니다. 어드민 대시보드에서 관리자가 직접 잘못된 CAS 번호를 교정하고 **[재적재]** 버튼을 누르면, 즉시 DB에 반영되고 오류 목록에서 제외되는 안전한 수동 개입 인터페이스를 완성했습니다.
* **실시간 모니터링 터미널**:
  어드민 대시보드를 통해 누적 적재량, 상태 배지, 5주기 갱신형 실시간 로그 스트리밍 뷰를 제공하여 분산 환경에서의 배치 상태를 투명하게 가시화했습니다.
