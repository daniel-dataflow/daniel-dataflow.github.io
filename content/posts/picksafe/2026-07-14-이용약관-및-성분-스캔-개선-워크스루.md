제품의 사용자가 늘어나고 서비스가 글로벌로 확장될 때, 엔지니어링 팀은 두 가지 핵심 과제에 직면합니다. **첫째는 시스템 성능 및 데이터 정확성의 보장이며, 둘째는 법적 컴플라이언스 및 운영 효율화**입니다.

PickSafe 팀은 최근 영수증 및 제품 성분표 OCR 스캔 과정에서 발생하던 **최대 3분의 지연 시간 문제를 1초대로 단축**하고, **2만 1천여 건의 공공 성분 공공 데이터 파이프라인 구축**, 그리고 **글로벌 다국어 약관 동의 체계**를 통합 재설계했습니다. 

이번 포스팅에서는 기술적 문제를 정의하고, 대안 간의 트레이드오프(Trade-off)를 검토하며, 이를 어떻게 성공적으로 해결했는지 공유합니다.

---

## 1. Problem: 스캔 지연 시간 3분과 데이터 오매칭 현상

### 문제의 원인
PickSafe의 성분 스캔 기능은 이미지 내 텍스트(OCR)를 추출한 뒤, 로컬 DB/메모리 캐시와 비교하여 성분을 매칭합니다. 미매칭 성분에 대해서는 식약처 외부 공공 API를 실시간 호출하여 조회하는 구조였습니다.

그러나 다음과 같은 심각한 문제가 발생했습니다:
1. **외부 API 호출 폭주 및 지연**: OCR 결과로 추출된 텍스트에는 다량의 노이즈(오타, 특수문자 등)가 포함될 수 있습니다. 노이즈 문자열이 수십 개 포함될 경우, 미매칭 항목마다 외부 API를 동기/비동기로 순차 호출하면서 스캔 완료까지 **최대 3분이 소요**되는 현상이 발생했습니다.
2. **유사 검색 결과로 인한 데이터 오염 (Ghost Matching)**: 식약처 API의 키워드 검색 특성상, 노이즈 문자열을 검색했을 때 유사도가 높은 첫 번째 결과(예: '가공소금')를 반환하는 문제가 있었습니다. 시스템은 이를 정답으로 판단해 DB 및 캐시에 저장했고, 사용자는 엉뚱한 성분 분석 결과를 받아보게 되었습니다.

## 2. Decision & Architecture: 실시간 API 호출 안전장치 재설계 (Option B)

팀 내부에서는 외부 API 의존도를 줄이기 위해 두 가지 대안을 검토했습니다.

*   **Option A (완전 오프라인화)**: 실시간 외부 API 호출을 전체 차단하고, 오직 로컬 DB의 성분 사전으로만 매칭.
    *   *장점*: 속도가 매우 빠르고 외부 장애 영향이 없음.
    *   *단점*: 신규 추가되는 성분이나 희귀 성분에 대한 커버리지 감소.
*   **Option B (정확 일치 검증 + 상한선 제어)**: 실시간 호출을 허용하되, **정확도 검증(Exact Match)**과 **호출 횟수 상한(Hard Limit)**을 둔 제어형 구조.

우리는 사용자 경험의 연속성과 데이터 커버리지를 모두 잡기 위해 **Option B**를 선택하고, 아래와 같이 아키텍처를 고도화했습니다.

```
[OCR 텍스트 추출] 
       │
       ▼
[로컬 캐시/DB 매칭] ──(매칭 성공)──► [성공 반환]
       │
    (미매칭)
       ▼
[실시간 외부 API 호출 조건 검증]
 ├─① 호출 횟수 제한 (스캔당 Max 5회)
 └─② 정확 일치 검증 (Normalization & Exact Match)
       │
 ┌─────┴────────────────┐
 │                      │
(일치)                (불일치/상한 초과)
 ▼                      ▼
[DB 저장 및 캐싱]    [N/A 처리 및 미매칭 반환]
```

### 주요 개선 로직

1. **정확 일치 검증 (Exact Match Validation)**
   외부 API가 반환한 성분명(한글/영문)을 스캔 문자열과 정규화(공백 제거, 대소문자 통일)한 뒤 **100% 정확하게 일치하는 경우만** 유효 데이터로 승인합니다. 노이즈로 인해 잘못 매핑되던 '가공소금' 오매칭 현상을 원천 차단했습니다.

2. **스캔당 호출 상한선 제어 (Circuit Breaker 성격의 Max Limit)**
   1회 스캔 요청 시 실시간 외부 API 조회를 **최대 5회**로 제한했습니다. 5회를 초과하는 미매칭 노이즈 텍스트는 즉시 N/A 처리하여 응답 속도를 보장합니다.

3. **로컬 캐시 동적 합류**
   검증을 통과한 신규 성분은 로컬 DB 및 메모리 캐시에 동적 반영되어, 다음 스캔부터는 API 통신 없이 즉각 매치됩니다.

> **Result**: 실시간 API 요청 제어를 통해 스캔 응답 시간을 **3분에서 1초 미만으로 단축**시켰으며, 데이터 정밀도를 100% 수준으로 끌어올렸습니다.

## 3. Data Pipeline: 2만 건의 공공 사전 백그라운드 동기화 및 모니터링

실시간 API 호출을 5회로 제한함에 따라 발생할 수 있는 데이터 미매칭 문제는 **대용량 백그라운드 동기화 시스템**으로 보완했습니다.

### 비동기 스케줄러 & 어드민 대시보드 구축

*   **비동기 루프 기반 스케줄러**: FastAPI 서비스 구동 시 백그라운드로 실행되는 스케줄러 루프를 구현하여, 약 21,800여 건의 전체 식약처 성분 공공 데이터를 서비스 지연 없이 주기적(매일/매주/매월)으로 동기화하도록 조치했습니다.
*   **실시간 모니터링 & 터미널 로그**: 웹 기반 어드민 화면에서 수집 진행 상태를 실시간 배지 및 스트리밍 터미널 로그로 모니터링할 수 있게 구축했습니다.

```
+-----------------------------------------------------------------------+
|  Admin Seeding Dashboard                                              |
|                                                                       |
|  [Status: Running]  [Total Synced: 21,833 / 21,833]  [Run Manual]    |
|                                                                       |
|  [Real-Time Terminal Log]                                             |
|  > [2026-07-14 09:01:02] Fetching batch #42... Success.                |
|  > [2026-07-14 09:01:03] Indexing memory cache... Done.                |
|                                                                       |
|  [Failed Records & Manual Recovery]                                   |
|  - ID 1042 | CAS: Invalid Format -> [ Edit CAS ] -> (Retry Seeding)   |
+-----------------------------------------------------------------------+
```

*   **Human-in-the-Loop 에러 복구**: CAS 번호 포맷 오류 등으로 수집에 실패한 데이터는 별도 예외 테이블(`ingredient_seed_errors`)에 격리됩니다. 관리자가 대시보드에서 CAS 번호를 수동 교정 후 클릭 한 번으로 DB에 즉시 재적재할 수 있는 자가 치유(Self-healing) 인터페이스를 완성했습니다.

## 4. Compliance: 글로벌 확장성을 고려한 약관 및 동의 시스템

글로벌 서비스를 지향함에 따라 법적 요구사항 준수와 사용자 경험 간의 균형이 필요했습니다.

### 다국어 폴백 체인 (Fallback Chain)

사용자의 로케일(Locale) 요청에 부합하는 약관 문서가 없을 경우, 서비스가 중단되지 않도록 단계별 폴백 구조를 설계했습니다.

$$\text{Requested Language} \longrightarrow \text{English (en)} \longrightarrow \text{Korean (ko)}$$

*   온보딩 게이트웨이 구현: 필수 약관(`Terms of Service`, `Privacy Policy`) 동의 이력을 검증하는 미들웨어를 신설하여, 동의가 누락된 유저는 온보딩 진입 시 동의 페이지로 자동 리다이렉트됩니다.
*   게스트-회원 전환 연동: 게스트 상태에서 수집된 동의 이력이 소셜 로그인 전환 시 손실 없이 회원 DB로 이관되는 파이프라인을 구축했습니다.

## Takeaways: 엔지니어링 교훈

1. **외부 API는 절대 신뢰하지 않는다 (Fail Fast, Cap Hard)**
   외부 인프라나 제3자 API는 우리가 제어할 수 없는 변수입니다. 무제한 재시도나 동기식 대기는 전체 시스템의 병목이 됩니다. 명확한 호출 상한(Limit)과 타임아웃, 그리고 Strict 한 검증 로직이 시스템의 무결성을 지킵니다.
2. **트레이드오프 중심의 데이터 설계**
   모든 데이터를 실시간으로 완벽하게 가져올 필요는 없습니다. *'핵심 데이터는 백그라운드 배치가, 미세 보완은 제어된 실시간 API가 담당한다'*는 분산 전략을 통해 성능과 데이터 정확도를 동시에 확보했습니다.
3. **운영자 관점의 관측 가능성(Observability)**
   자동화 파이프라인 구축만큼 중요한 것은 실패 시 이를 손쉽게 모니터링하고 수동으로 교정(Human-in-the-Loop)할 수 있는 어드민 도구를 제공하는 것입니다.

PickSafe 팀은 앞으로도 대규모 데이터 처리와 안정적인 시스템 아키텍처를 바탕으로 더욱 빠르고 정확한 성분 분석 경험을 제공할 예정입니다.
