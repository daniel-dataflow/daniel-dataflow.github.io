제품이 성장하고 외부 API 연동 및 데이터 모델이 복잡해질 때, 엔지니어링 팀이 마주하는 가장 큰 숙제는 **"시스템의 예측 가능성과 확장성을 어떻게 유지할 것인가?"**입니다.

최근 픽세이프(PickSafe) 팀은 성분 스캔 기능의 실시간 외부 API 응답 지연 현상(최대 3분 소요)과 데이터 오매칭 문제를 극복하고, 서비스 안정성을 끌어올리기 위한 아키텍처 재설계를 진행했습니다. 

본 포스팅에서는 **1) 실시간 외부 API 의존성 병목 해결, 2) 대규모 성분 데이터의 비동기 백그라운드 동기화, 3) 글로벌 서비스를 위한 다국어 폴백 아키텍처 구축 과정**에서 직면한 문제와 공학적 의사결정(Trade-off) 내역을 공유합니다.

---

## 1. 실시간 OCR 스캔 병목: 3분의 지연을 1초로 단축하기

### 🔴 문제 상황 (Problem)
제품 성분표나 영수증 이미지를 OCR로 읽어 식약처 공공 DB와 실시간 매칭하는 과정에서 심각한 병목이 발생했습니다. 
* **노이즈 문자열 폭주**: OCR 특성상 이미지 상태에 따라 수십 개의 의미 없는 노이즈 문자열이 생성되었습니다.
* **외부 API 지연 전파**: 캐시되지 않은 무수한 노이즈 문자열이 실시간 외부 공공 API 호출로 이어져, 단일 스캔 요청이 끝날 때까지 **최대 3분**이 소요되는 현상이 발생했습니다.
* **유사 검색 결과 오매치 (False Positive)**: 공공 API의 쿼리 특성상, 정확히 일치하지 않는 노이즈 검색어에 대해 유사 검색 결과의 첫 번째 항목(예: '가공소금')을 임의 매핑하여 데이터 오염이 발생했습니다.

### ⚖️ 아키텍처 고민과 대안 비교 (Trade-off)
* **대안 A: 실시간 외부 API 완전 제거 (100% 로컬 DB 조회)**
  * *장점*: 응답 속도가 100ms 이내로 매우 빠름.
  * *단점*: 미적재된 최신 성분이 스캔될 경우 매칭률이 떨어져 유저 경험 저하.
* **대안 B: 방어적 실시간 API 샌드박스 + 2단계 검증 기법 (선택)**
  * 실시간 조회를 허용하되, **호출 상한선 제한(Circuit Breaker 유사 기법)**과 **엄격한 문자열 정규화 검증**을 조합.

### 💡 최종 해결책 (Solution)
1. **정확 일치 검증 (Exact Match Normalization)**
   * 외부 API가 반환한 성분명(한글/영문)과 OCR 추출 문자열을 정규화(공백 제거, 대소문자 통일)하여 **100% 일치하는 경우에만 유효 데이터로 판정**하고 DB 및 동적 캐시에 적재하도록 변경했습니다. (유사 매칭으로 인한 오발 매핑 원천 차단)
2. **스캔당 외부 API 호출 상한선 제어 (Max 5 Call Limit)**
   * 단일 스캔 요청에서 캐시 미스(Cache Miss)가 발생하더라도 외부 API 호출 횟수를 **최대 5회**로 강제 제한했습니다.
3. **결과**
   * 노이즈 문자열이 아무리 많아도 전체 처리 시간이 **3분에서 1~2초 내로 단축(99% 이상의 지연 시간 감소)**되었으며, 데이터의 정확도 또한 확보했습니다.

```
[OCR 추출 텍스트] ──> [메모리/DB 캐시 체크] ──(Miss)──> [외부 API 제한적 호출 (Max 5)]
                                                              │
                                                        [정확 일치 검증]
                                                              │ (Match Only)
                                                       [로컬 DB 동적 적재]
```

## 2. 21,000+ 성분 데이터 동기화: 비동기 스케줄러 & Dead Letter Queue

실시간 스캔 시 외부 API 호출을 제한함에 따라, 로컬 DB가 식약처 성분 공공 데이터(21,833건)를 최신 상태로 유지하는 **백그라운드 동기화 시스템**의 필요성이 대두되었습니다.

```
+-------------------------------------------------------------------------+
|                    FastAPI Application Startup                          |
+-------------------------------------------------------------------------+
                                    │
                                    ▼
                     [Async Background Scheduler Loop]
                                    │
                     (Cron / Interval Trigger Event)
                                    │
                                    ▼
                    [Fetch Public API Batch Data]
                                    │
             ┌──────────────────────┴──────────────────────┐
             ▼                                             ▼
     [Validation Pass]                             [Validation Fail]
             │                                             │
             ▼                                             ▼
   [Upsert Target DB]                         [Push to Seed Errors DB]
                                                           │
                                                           ▼
                                            [Admin Dashboard Manual Fix]
```

### 💡 구조 개선 (Implementation)
1. **FastAPI 이벤트 루프 기반 비동기 스케줄러 구축**
   * 서비스 기동(`startup` 이벤트) 시 상시 동작하는 비동기 백그라운드 스레드 루프를 바인딩했습니다. 
   * 설정된 주기(매일/매주/매월)에 따라 메인 서비스의 I/O 멈춤(Blocking) 없이 2만 여 건의 공공데이터 배치를 백그라운드로 동기화합니다.
2. **실패 격리 및 수동 교정 UI (Human-in-the-loop DLQ)**
   * 공공 데이터 파싱 중 발생하는 검증 오류(예: CAS 번호 포맷 불량, 필수 필드 누락 등)로 인해 전체 동기화가 중단되지 않도록 **전용 에러 이력 테이블**에 실패 데이터를 격리했습니다.
   * 관리자 어드민 대시보드에 **실시간 모니터링 터미널** 및 **실패 항목 CAS 번호 수동 교정/재적재 인터페이스**를 구축하여 운영 효율성을 최적화했습니다.

## 3. 글로벌 정합성을 위한 다국어 폴백 체인 & 약관 동의 아키텍처

서비스 확장 및 글로벌 사용자 유입에 대비하여 약관 및 민감정보 수동 동의 흐름의 구조적 개편을 진행했습니다.

### 💡 주요 아키텍처 설계
* **다국어 폴백 체인 (Multilingual Fallback Chain)**
  * 법적 공지 문서 로드 시, 사용자의 요청 언어 자원이 부재할 경우 서비스가 중단되는 대신 Graceful Degradation 전략을 적용했습니다.
  * **`요청 언어 (User Target)` $\rightarrow$ `영어 (en)` $\rightarrow$ `한국어 (ko)`** 순으로 복귀하는 폴백 체인을 구축하여 안정적인 콘텐츠 노출을 보장합니다.

* **게스트-회원 이관 시 동의 이력 보존 (Consent Audit Trail)**
  * 게스트 사용자가 소셜 가입/로그인을 통해 정식 회원으로 전환(`/guest-convert`)될 때, 최초 게스트 시점에 수집된 필수 약관 동의 이력이 데이터베이스 상에서 손실 없이 연동·저장되도록 상태 이행 트랜잭션을 보장했습니다.

## 4. 엔지니어링 교훈 (Takeaways)

이번 아키텍처 개편 및 성능 고도화 작업을 통해 얻은 핵심 레슨은 다음과 같습니다.

1. **외부 API는 결코 신뢰의 대상이 아니다 (Zero Trust External API)**
   * 실시간 서비스 트래픽 경로 상에 외부 API를 직접 노출하는 것은 매우 위험합니다. Circuit Breaker, 서킷 타임아웃, 호출 상한선(Cap Limit) 등 방어 기직 구축이 필수적입니다.
2. **동기(Synchronous) 처리와 비동기(Asynchronous) 배치의 적절한 분리**
   * 사용자 요청 시점에는 최소한의 검증된 로컬 데이터만 빠르게 응답하고, 거대 데이터 동기화는 백그라운드 스케줄러로 이전함으로써 사용자 경험(UX)을 크게 향상시킬 수 있었습니다.
3. **운영 자동화에는 반드시 '수동 개입을 위한 안전장치'가 동반되어야 한다**
   * 자동화 스케줄러 구축만큼이나 중요한 것은 **수집 실패 데이터의 격리(DLQ) 및 어드민 UI를 통한 인간(Human)의 손쉬운 데이터 재정제 인터페이스**였습니다.
