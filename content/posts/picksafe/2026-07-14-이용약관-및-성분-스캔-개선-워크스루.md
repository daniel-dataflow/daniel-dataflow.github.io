안녕하세요. **PickSafe**의 백엔드 아키텍처를 담당하고 있는 시니어 개발자입니다.

성분 스캔 기반의 헬스테크/푸드테크 서비스에서 가장 중요한 가치는 **'정확하고 신속한 정보 전달'**입니다. 하지만 공공데이터 포털이나 정부 기관의 외부 API를 실시간 비즈니스 로직에 결합할 때, 외부 서버의 성능 저하나 네트워크 지연은 고스란히 우리 서비스의 UX 저하로 이어지곤 합니다.

최근 저희 PickSafe 팀은 성분 스캔 과정에서 발생하던 **최대 3분의 지연 시간(Latency)을 단 1초로 단축**시키고, 오발 매칭률을 0%로 수렴시킨 성능 개선 작업 및 운영 도구 구축을 진행했습니다. 이 과정에서 겪은 기술적 페인 포인트와 의사결정 과정을 공유합니다.

---

## 1. Problem: 3분의 벽과 '가공소금'의 덫 (실시간 스캔 API의 한계)

### 1-1. 외부 API 호출 지연으로 인한 UX 붕괴
기존 PickSafe의 성분 스캔 흐름은 이미지에서 텍스트를 추출한 뒤, 로컬 DB/캐시에 존재하지 않는 성분들을 실시간으로 식약처(식품의약품안전처) 외부 공공 API에 조회하여 매칭하는 방식이었습니다. 

하지만 사용자가 업로드한 영수증이나 성분표 이미지에 노이즈 문자열(예: 특수문자, 깨진 텍스트 등)이 대량 포함되어 있을 경우 다음과 같은 치명적인 문제가 발생했습니다.

1. **지연 시간 폭발**: 수십 개의 노이즈 텍스트마다 개별 외부 API 아웃바운드 호출이 발생했습니다. 외부 API 응답 대기 시간이 누적되면서, 단 한 번의 스캔 요청에 **최대 3분** 동안 응답이 지연되는 현상이 발생했습니다.
2. **오발 매칭(False Positive)의 습격**: 식약처 API의 유사 검색 결과 사양으로 인해, 분석 불가능한 노이즈 텍스트(예: `N/A`)를 조회했을 때 API가 검색 결과의 첫 항목인 '가공소금' 등을 반환하는 현상이 있었습니다. 이로 인해 사용자는 아무 관련 없는 유해 성분이 매칭되었다는 오작동 화면을 보게 되었습니다.

## 2. Technical Decisions: 실시간 API 안전장치 고도화

이 문제를 해결하기 위해 저희 팀은 실시간 통신을 제어하고 매칭 알고리즘을 강화하는 **'실시간 API 안전장치 아키텍처(Option B)'**를 재설계했습니다.

```
[스캔 요청] ➔ [로컬 DB/캐시 조회] ➔ (미매칭 성분 발생)
                                      │
          ┌───────────────────────────┴──────────────────────────┐
          ▼ (No)                                                 ▼ (Yes, Max 5회 제한)
  [즉시 결과 반환] ◀── [정확 일치(Exact Match) 검증] ◀── [식약처 API 호출]
```

### 대안 비교 및 트레이드오프

| 비교 항목 | 대안 A: 실시간 API 전면 제거 (완전 오프라인) | 대안 B: 상한선 제어 및 정확 일치 검증 (선택안) |
| :--- | :--- | :--- |
| **UX 레이턴시** | **극도로 낮음 (1초 이내)** | **매우 낮음 (최대 5회 제한으로 1~2초 내 제어)** |
| **데이터 최신성** | 주기적인 배치 주기에 의존 (실시간 반영 불가) | 신규 성분에 대해 실시간으로 캐시 보강 가능 |
| **구현 복잡도** | 낮음 | 중간 (정밀 매칭 로직 및 호출 제한 필요) |

저희는 **대안 B**를 선택했습니다. 실시간성을 완전히 포기하기보다는, 영리한 제어 장치를 두어 시스템 안정성과 데이터 최신성을 모두 잡기로 결정했습니다.

### 2-1. 정확 일치 검증 (Exact Match Validation) 도입
외부 API가 유사 검색 결과를 반환하더라도, 시스템이 이를 맹목적으로 신뢰하지 않도록 방어벽을 쳤습니다.
* API가 반환한 성분명(한글/영문)과 원본 스캔 문자열을 비교할 때, **공백을 제거하고 대소문자를 통일하는 정규화(Normalization)** 과정을 거친 후 정확하게 일치하는 케이스만 DB에 캐싱하고 사용자에게 매칭 결과를 제공하도록 개선했습니다.
* 이로써 '가공소금' 등 쌩뚱맞은 성분으로 잘못 매핑되는 노이즈 필터링 성능을 100% 확보했습니다.

### 2-2. 스캔당 아웃바운드 호출 상한선 강제 (Max 5 Limit)
* 하나의 스캔 요청 컨텍스트 내에서 외부 API 호출 횟수를 **최대 5회**로 엄격히 제한했습니다.
* 아무리 지저분한 영수증 이미지가 들어와 백 개의 노이즈 텍스트가 추출되더라도, 5번의 API 호출 이후에는 즉시 루프를 탈출하여 사용자에게 1~2초 내에 응답을 반환합니다.

### 2-3. Write-Through 방식의 로컬 캐싱 유지
* 정확 일치로 판별된 신규 유효 성분은 즉시 백엔드 로컬 DB 및 메모리 캐시에 동적으로 합류시킵니다.
* 다음 사용자가 동일한 성분을 스캔할 때는 외부 API 호출 없이 메모리 레이어에서 즉각 응답하게 함으로써 점진적으로 아웃바운드 트래픽을 감소시키는 선순환 구조를 만들었습니다.

## 3. Deep Dive: 2만 개 데이터의 안정적 동기화와 모니터링 시스템

실시간 API 호출을 제한했다면, 로컬 DB의 성분 사전 데이터(약 21,833개)가 항상 최신 상태를 유지할 수 있도록 하는 강력한 배치 시스템이 필요합니다.

### 3-1. FastAPI 기반 백그라운드 비동기 스케줄러 구축
웹 서버의 메인 스레드를 차단하지 않고 대용량 데이터를 동기화하기 위해, FastAPI의 `startup` 이벤트를 활용한 **비동기 상시 루프 스케줄러**를 구현했습니다.

```python
# 내부 구현 추상화 예시
@app.on_event("startup")
async def start_scheduler():
    loop = asyncio.get_event_loop()
    loop.create_task(seeding_scheduler_loop())
```

이 루프는 주기적으로 설정 DB를 체크하며, 관리자가 지정한 주기(매일, 매주, 매월)에 도달하면 백그라운드에서 조용히 대용량 동기화 배치를 수행합니다.

### 3-2. 장애 극복(Failover)을 위한 데이터 스키마 및 어드민 대시보드
배치 도중 공공데이터 포털의 일시적 장애나 데이터 포맷 오류(예: 올바르지 않은 CAS 등록 번호 등)로 인해 수집이 실패하는 일이 흔히 발생합니다. 저희는 이를 방치하지 않고 추적 가능하게 설계했습니다.

1. **실패 전용 스키마 분리**: 수집 오류가 발생한 원본 데이터와 오류 로그를 보관하는 `ingredient_seed_errors` 테이블을 설계하여 수동 디버깅의 번거로움을 덜었습니다.
2. **어드민 실시간 제어 센터 구축**:
   * **실시간 로그 스트리밍**: 관리자 웹 화면에서 5초 주기 폴링을 통해 백그라운드 배치 상태를 터미널 스타일로 모니터링할 수 있게 구현했습니다.
   * **CAS 번호 교정 및 즉시 재적재**: 검증 오류로 누락된 데이터가 있을 경우, 관리자가 어드민 대시보드에서 직접 올바른 데이터 값을 교정하여 "재적재" 버튼을 클릭하면 즉시 메인 데이터베이스에 반영되고 오류 목록에서 제거되는 직관적인 어드민 UX를 제공합니다.

## 4. Global Compliance: 다국어(i18n) 폴백과 안전한 온보딩 아키텍처

글로벌 서비스를 지향하는 PickSafe는 사용자 약관(TOS) 및 민감정보 동의 흐름도 유연하고 안전하게 개선해야 했습니다.

### 4-1. 다국어 폴백 체인 (Fallback Chain)
다국어 지원 시스템에서 현지화 리소스가 준비되지 않았을 때의 안전장치는 필수적입니다. 저희는 다음과 같은 흐름으로 언어 리소스 폴백 체인을 구축했습니다.

$$\text{요청 언어(Requested Locale)} \longrightarrow \text{영어(en)} \longrightarrow \text{한국어(ko)}$$

만약 브라질 사용자가 포르투갈어(`pt`)로 진입했으나 특정 마이너 약관의 포르투갈어 번역이 누락되었다면, 에러 페이지를 보여주는 대신 자연스럽게 글로벌 공용어인 영어(`en`) 버전을 노출해 법적 컴플라이언스 공백을 방지합니다.

### 4-2. 게스트 유저 가입 전환(Migrate) 트랜잭션 보장
PickSafe는 사용성을 해치지 않기 위해 비회원 게스트 상태로 스캔 서비스를 즉시 이용할 수 있도록 지원합니다. 
이후 사용자가 소셜 가입을 통해 정식 회원으로 전환(`guest-convert`)할 때, **게스트 시절 동의했던 이용약관 및 개인정보 동의 이력 데이터가 정식 회원 프로필과 함께 원자적(Atomic)으로 이전**되도록 트랜잭션 가드라인을 꼼꼼하게 설계하여 법적 동의 누락 리스크를 원천적으로 방어했습니다.

## 5. Engineering Takeaways (배운 점)

1. **외부 의존성은 결코 믿음의 대상이 아니다**: 외부 API는 언제든 느려지거나 잘못된 응답을 줄 수 있습니다. 호출 수 제한(Rate Limit)과 상한선(Cap), 그리고 반환 데이터의 엄격한 교차 검증(Exact Match)은 필수적인 방어적 프로그래밍 패턴입니다.
2. **도구에 투자하는 비용은 결국 절약되어 돌아온다**: 개발 초기 단계에서 백그라운드 배치 에러 로그와 상태를 시각화하고 즉각 수정-재적재할 수 있는 어드민 대시보드를 구축한 덕분에, 데이터 정합성 이슈 해결에 드는 운영 공수를 80% 이상 절감할 수 있었습니다.
3. **최적의 사용자 경험은 트레이드오프에서 나온다**: 실시간성을 100% 고집하기보다 적절한 수준의 로컬 캐시와 하이브리드 전략을 결합하는 유연함이 3분이라는 끔찍한 UX를 1초짜리 쾌적한 UX로 만드는 열쇠였습니다.

앞으로도 PickSafe는 견고한 엔지니어링을 바탕으로, 전 세계 사용자들이 안심하고 안전하게 먹거리를 스캔할 수 있는 세상을 만들어 가겠습니다. 긴 글 읽어주셔서 감사합니다.
