안녕하세요, **PickSafe** 개발 팀입니다.

서비스의 초기 빌드 단계에서는 '기능의 완성'에 집중하기 마련입니다. 하지만 사용자가 늘어나고 서비스가 성숙해짐에 따라, 미처 신경 쓰지 못했던 미시적인 UX와 시스템 구조가 비즈니스 지표(특히 리텐션과 이탈률)에 거대한 영향을 미치고 있음을 발견하게 됩니다.

최근 PickSafe 팀은 유저의 잔존율(Retention)을 극대화하고, 우발적인 이탈(Churn)을 방지하기 위해 **세션 관리 아키텍처를 개편하고 설정/계정 관리 UX를 완전히 재설계**했습니다. 기획, 디자인, 백엔드, 프론트엔드가 긴밀하게 협업하여 기술적 문제를 해결한 과정을 공유합니다.

---

## 1. 우리가 마주한 문제들 (Problem Definition)

개편 전 PickSafe는 다음과 같은 세 가지 주요 페인 포인트(Pain Point)를 가지고 있었습니다.

### 1.1 모바일/PWA 환경에서의 협소한 모달 팝업 설정창
기존에는 마이페이지 내에서 톱니바퀴 아이콘을 누르면 레이어 팝업(Modal) 형태로 설정 창이 떴습니다. 그러나 모바일 웹 및 PWA(Progressive Web App) 환경에서 모달 방식은 화면 집중도를 떨어뜨렸습니다. 특히 다국어(6개 국어) 설정, 세부 계정 정보, 보안 설정을 한정된 모달 공간에 모두 담으려다 보니 정보의 시각적 위계가 무너지고 답답한 사용성을 유발했습니다.

### 1.2 짧은 세션 만료로 인한 잦은 재로그인 요구
PickSafe는 유저가 설정한 기피 성분 필터링 정보와 개인 찜 목록을 기반으로 개인화된 가치를 제공합니다. 이 핵심 데이터를 지속적으로 경험하게 하려면 로그인 유지가 필수적입니다. 하지만 기존 시스템은 세션 유지 기간이 짧게 설정되어 있었고, 헤더 영역에 로그아웃 버튼이 무방비하게 노출되어 있어 유저가 실수로 로그아웃을 눌러 세션이 끊기는 일이 빈번했습니다.

### 1.3 1-Click 탈퇴 구조로 인한 우발적 이탈 위험
기존의 회원 탈퇴 및 로그아웃은 너무나도 쉽게 실행되었습니다. 데이터 복구가 불가능한 '회원 탈퇴'라는 민감한 의사결정이 충분한 안내나 방어 장치 없이 단일 단계(1-Step)로 진행되면서, 유저의 실수 혹은 일시적인 감정에 의한 우발적 탈퇴를 방어하지 못하고 있었습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off)

문제를 해결하기 위해 기술적 설계 관점에서 몇 가지 치열한 논의와 절충(Trade-off)이 있었습니다.

### 고민 1. 세션 만료 시간 연장: 보안 vs 사용 편의성
*   **대안 A: 단기 세션 유지 + Refresh Token 도입**
    *   *장점:* 보안성이 높고 토큰 탈취 시 대응이 용이함.
    *   *단점:* 단기간 내 시스템 복잡도가 급격히 증가하며, 추가적인 토큰 저장소 및 갱신 로직 필요.
*   **대안 B: 보안 속성이 강화된 장기 세션 쿠키 (선택)**
    *   *장점:* 금융 서비스처럼 민감한 개인정보를 직접 다루지 않는 서비스 특성상, 장기 세션(365일) 쿠키를 제공하되 `HttpOnly`, `Secure`, `SameSite=Lax` 속성을 강제 적용하여 타협점 마련. 복잡한 인프라 공수 없이 즉각적인 retention 상승 기대 가능.

### 고민 2. 설정 화면 구조: SPA형 렌더링 vs 독립 라우트 분리
*   **대안 A: 기존 마이페이지 내 JS 동적 콤포넌트 전환**
    *   *장점:* 페이지 이동이 없어 전환 속도가 빠름.
    *   *단점:* 다국어 리소스 바인딩 및 라우팅 상태 관리가 복잡해지고 모바일 뒤로가기 제어가 까다로움.
*   **대안 B: 전용 백엔드 라우트(`/settings`) 분리 (선택)**
    *   *장점:* 뒤로가기(`← 마이페이지`) 네비게이션이 브라우저 기본 동작으로 깔끔하게 처리됨. 서버 사이드 템플릿 엔진을 활용해 유저 가입 정보(구글/페이스북/이메일 유형 및 가입일)를 안전하고 정적으로 렌더링 가능. 유지보수성 향상.

## 3. 최종 해결 및 구현 (Implementation)

팀은 위 의사결정을 바탕으로 백엔드(FastAPI)와 프론트엔드(Vanilla JS, HTML/CSS) 구조를 전면 개편했습니다.

### 3.1 독립 설정 페이지(`/settings`) 신설 및 백엔드 라우팅 개편
기존 마이페이지의 모달 뷰 의존성을 제거하고, FastAPI 백엔드에 전용 라우터를 구축했습니다.

```python
# web/backend/app/routers/mypage.py (추상화된 예시 코드)
from fastapi import APIRouter, Request, Depends
from fastapi.responses import HTMLResponse
from dependency_injector.wiring import Provide

router = APIRouter()

@router.get("/settings", response_class=HTMLResponse)
async def get_settings_page(
    request: Request,
    current_user: User = Depends(get_current_user)
):
    # 사용자의 가입 유형, 이메일, 가입일 및 6개국 다국어 번역 키를 템플릿으로 전달
    return templates.TemplateResponse(
        "settings.html",
        {
            "request": request,
            "user_info": {
                "email": current_user.email,
                "provider": current_user.provider,
                "created_at": current_user.created_at.strftime("%Y-%m-%d")
            }
        }
    )
```

`/settings` 페이지 내부는 크게 3가지 섹션으로 구조화하여 시각적 인지 부하를 줄였습니다.
1.  **언어 설정 (Language Settings):** 글로벌 사용자를 위한 6개 공식 언어 즉시 전환 탭.
2.  **계정 정보 (Account Information):** 로그인된 이메일 주소 및 인증 제공업체 표시.
3.  **보안 및 계정 관리:** 로그아웃과 회원 탈퇴를 깊숙한 경로로 숨겨 단순 실수를 방지함.

### 3.2 365일 장기 세션 쿠키 적용 및 이탈 방어
사용자가 매번 다시 로그인해야 하는 번거로움을 제거하기 위해 로그인 처리부에서 세션 쿠키의 `max_age` 값을 **1년(31,536,000초)**으로 연장했습니다.

```python
# web/backend/app/routers/auth.py (추상화된 예시 코드)
@router.post("/login/finalize")
async def finalize_login(response: Response, token: str):
    # 1년(365일) 세션 유지 적용
    ONE_YEAR_SECONDS = 31_536_000
    
    response.set_cookie(
        key="session_token",
        value=token,
        max_age=ONE_YEAR_SECONDS,
        httponly=True,   # XSS 공격 방지
        secure=True,     # HTTPS 프로토콜 전용
        samesite="lax"   # CSRF 공격 방어와 편의성 균형
    )
    return {"status": "success"}
```

동시에 헤더 네비게이션에서 로그아웃 버튼을 제거했습니다. 이제 사용자는 로그아웃을 하려면 **[마이페이지 > 설정 > 보안 관리]**의 단계를 명확히 인지하고 진입해야 합니다. 불필요한 실수 로그아웃이 획기적으로 줄어들었습니다.

### 3.3 우발적 탈퇴를 막는 2단계 확인(Two-Step Modal) UX 구축
회원 탈퇴 프로세스에는 심리학적 방어 기제를 적용했습니다. 단순히 버튼을 눌러 탈퇴되는 구조가 아닌, **2단계 경고 모달**을 구현했습니다.

```javascript
// web/frontend/static/js/auth.js (구현 흐름 예시)
const withdrawalWorkflow = {
  currentStep: 1,

  showFirstModal() {
    this.currentStep = 1;
    // 1단계: 탈퇴 시 모든 데이터(기피 성분, 찜 목록 등)가 영구 삭제됨을 강력히 경고
    modalTitle.innerText = "정말 탈퇴하시겠습니까?";
    modalContent.innerText = "탈퇴 시 고객님의 맞춤형 안심 성분 데이터와 즐겨찾기 목록이 즉시 소멸되며 복구할 수 없습니다.";
    
    // UX 핵심: "계속 이용하기(취소)" 버튼을 기본 강조(Primary) 스타일로, "탈퇴하기"는 보조(Danger) 스타일로 배치
    btnPrimary.innerText = "계속 이용하기"; // Focus
    btnSecondary.innerText = "다음 단계";
  },

  showSecondModal() {
    this.currentStep = 2;
    // 2단계: 최종 의사 확인 및 이탈 방어 문구 재노출
    modalTitle.innerText = "마지막으로 확인해주세요";
    modalContent.innerText = "모든 서비스 혜택이 영구적으로 사라집니다. 정말로 계정을 삭제하시겠습니까?";
    
    btnPrimary.innerText = "가지 않고 계속 이용할래요";
    btnSecondary.innerText = "계정 영구 삭제"; // 실제 삭제 API 트리거
  }
};
```

특히 취소 동작(Keep-using)을 기본 포커스 스타일(Primary CTA)로 지정하고, 탈퇴 진행 동작을 무채색 톤의 서브 스타일로 디자인하여 사용자가 관성적으로 "예"를 눌러 탈퇴하는 것을 방지했습니다.

## 4. 결과 및 엔지니어링 교훈 (Takeaways)

이번 개편을 통해 우리는 코드의 단순 명료함뿐만 아니라 비즈니스 지표의 개선이라는 값진 결과를 얻을 수 있었습니다.

1.  **UX 집중도 향상:** 설정 페이지를 독립 웹 페이지인 `/settings`로 분리함으로써 모바일 뷰에서의 복잡한 CSS 해킹 및 예외 처리가 사라졌습니다. 반응형 웹 디자인 대응이 한결 쉬워졌습니다.
2.  **보안 속성이 가미된 세션 극대화:** 1년 장기 세션을 유지하되 `HttpOnly` 및 `SameSite` 등 브라우저 단의 보안 설정을 견고히 다져 안전성과 사용 편의성이라는 두 마리 토끼를 잡았습니다.
3.  **지표 중심의 엔지니어링:** 프론트엔드와 백엔드의 세밀한 제어(헤더 버튼 정리, Cursor CSS 디테일 수정, 2단계 모달 적용)가 실제 유저의 우발적 이탈을 효과적으로 방어할 수 있음을 증명했습니다.

개발자에게 시스템의 성능 향상만큼이나 중요한 것은 **"유저가 서비스 내에서 겪는 마찰력(Friction)을 최소화하는 것"**입니다. PickSafe 팀은 앞으로도 세밀한 메트릭 관찰과 아키텍처 개선을 통해 더 매끄러운 유저 경험을 만들어 나가겠습니다.
