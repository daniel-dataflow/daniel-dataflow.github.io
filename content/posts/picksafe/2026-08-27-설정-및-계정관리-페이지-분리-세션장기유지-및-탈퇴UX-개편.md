안녕하세요, PickSafe 개발팀입니다. 
서비스를 고도화하면서 기능이 추가됨에 따라, 초기에 가볍게 도입했던 UI 패턴들이 사용자 경험(UX)과 서비스 지표에 걸림돌이 되는 순간이 찾아옵니다. 

이번 글에서는 **모바일 웹 및 PWA 환경을 고려하여 설정 화면을 팝업에서 독립 페이지로 분리**하고, **세션 유지 정책 개편** 및 **안전한 회원 탈퇴 UX를 구축**한 아키텍처 의사결정 과정과 기술적 교훈을 공유합니다.

---

## 1. Problem: 작은 편의가 부른 거대한 UX 부채

우리가 직면한 문제는 크게 세 가지였습니다.

1. **모바일 환경에서 한계에 다단 팝업 모달**
   기존에는 설정 기능이 모달 팝업 형태로 제공되었습니다. 하지만 모바일 웹과 PWA(Progressive Web App) 환경에서 화면 집중도가 떨어졌고, 언어 설정·계정 정보·보안 관리 등을 한 번에 다루기에는 공간이 너무 협소했습니다.
2. **단기 세션과 잦은 로그아웃 위험**
   개인화된 데이터(기피 성분, 찜 목록 등)를 다루는 서비스 특성상 장기적인 로그인 유지 유무가 핵심 리텐션 지표와 직결됩니다. 그러나 기존 세션 유효기간이 상대적으로 짧았고, 상단 헤더에 떡하니 노출된 로그아웃 버튼 때문에 사용자가 실수로 세션을 잃는 경우가 발생했습니다.
3. **치명적인 오작동을 유발하는 1단계 계정 이탈 인터랙션**
   로그아웃과 회원 탈퇴 같은 중대한 계정 조작이 단순 1단계 버튼으로 노출되어 있어, 의도치 않은 계정 삭제 및 이탈 리스크가 상존했습니다.

## 2. Trade-off & Decision: 무엇을 버리고 무엇을 취했는가

### ① 모달 폐지 vs 전용 독립 페이지(`/settings`) 신설
* **대안 비교**: 
  * *모달 유지 및 확장*: 기존 구조를 유지하되 크기를 키우는 방식. 구현은 빠르지만 모바일 브라우저의 뒤로가기(Back Button) 제스처와 호환되지 않아 웹 표준에 어긋남.
  * *독립 라우트 분리*: 브라우저 히스토리 스택을 자연스럽게 활용할 수 있고, 모바일 화면 전체를 온전히 활용 가능.
* **최종 결정**: 독립 페이지인 `/settings`를 신설하고, 3대 섹션(언어, 계정 정보, 보안/관리)으로 구조화하여 정보 가독성을 극대화했습니다.

### ② 세션 1년 장기 유지(`max_age=31536000`)와 헤더 버튼 제거
* **보안 vs 편의성 Trade-off**: 금융 앱 수준의 보안이 강제되지 않는 라이프스타일/개인화 서비스에서, 매번 로그인을 요구하는 것은 치명적인 이탈 요인입니다. 글로벌 빅테크 서비스의 표준에 맞춰 세션 쿠키의 `max_age`를 **1년(31,536,000초)**으로 연장했습니다.
* **오클릭 방지**: 상단 네비게이션 헤더에 노출되던 로그아웃 버튼을 과감히 제거하고, 반드시 **[설정 > 보안 및 계정 관리]** 단계를 거치도록 동선을 깊게 설계하여 데이터 보존성과 안정성을 높였습니다.

### ③ 회원 탈퇴 2단계 모달(Two-Step Modal) UX 도입
* 우발적인 계정 삭제를 방지하기 위해 2단계 검증 모달을 구축했습니다. 특히, 시각적 계층 구조(Visual Hierarchy)를 조정하여 기본 강조 버튼을 '계속 이용하기(취소)'로 배치하고, 삭제 버튼은 보조 스타일로 처리하여 다크 패턴을 지양하면서도 확실한 방어막을 쳤습니다.

## 3. Implementation: 백엔드부터 프론트엔드까지

이번 개편은 백엔드 라우트 조정부터 프론트엔드 템플릿, 그리고 다국어 시드 데이터까지 전방위적인 수정이 수반되었습니다.

* **Backend (`FastAPI`)**: 
  * `/settings` 라우트를 신설하여 언어 설정, 사용자 계정 정보, 가입 일시 등의 컨텍스트를 템플릿에 안전하게 바인딩(`mypage.py`).
  * 인증 라우터에서 쿠키 생성 시 만료 시간을 1년으로 명시적 설정(`auth.py`).
* **Frontend (`Template & Vanilla JS`)**:
  * `settings.html` 뷰 템플릿을 신규 작성하고, 기존 헤더의 불필요한 툴팁 및 로그아웃 버튼을 일괄 정돈.
  * `auth.js`를 통해 2단계 탈퇴 모달의 상태 관리 및 비동기 인터랙션 구현.
* **i18n**: 
  * 6개 국어 환경을 지원하기 위해 다국어 데이터베이스 시드 스크립트를 업데이트하여 글로벌 확장성 확보.

## 4. Takeaway: 시니어 에디터의 회고

이번 리팩토링의 핵심 교훈은 **"사용자 인터랙션의 깊이(Depth)는 귀찮음이 아니라 안전장치다"**라는 점입니다. 

기능을 한 화면에 우겨넣는 '모달' 방식은 개발자 관점에서는 빠르게 만들 수 있지만, 모바일 웹 환경의 사용자에게는 피로감을 줍니다. 또한, 중요한 액션(탈퇴, 로그아웃)일수록 적절한 마찰력(Friction)을 제공하는 것이 오히려 장기적인 프로덕트 신뢰도를 높인다는 것을 증명한 사례였습니다.

앞으로도 PickSafe는 빠르기만 한 서비스가 아닌, 사용자의 맥락을 배려하는 단단한 아키텍처를 만들어 나갑니다.
