서비스의 폭발적인 성장 단계에서 개발팀이 마주하는 가장 중요한 화두 중 하나는 **"어떻게 하면 사용자를 서비스에 더 오래 머무르게 할 것인가(Retention)?"**입니다. 흔히 리텐션 향상은 마케팅이나 기획의 영역으로만 여겨지기 쉽지만, 실제로는 백엔드의 세션 관리 정책, 프론트엔드의 네비게이션 구조 등 기술적 의사결정의 디테일에서 결정적인 차이가 발생합니다.

글로벌 타겟 맞춤형 헬스케어 서비스 **PickSafe** 개발팀은 최근 사용자의 불편함을 유발하던 모바일/PWA 환경의 설정 레이아웃을 개편하고, 세션 유지 정책을 대대적으로 수정하여 유저 이탈률을 방어하는 엔지니어링 작업을 진행했습니다. 

이번 포스팅에서는 우리가 마주했던 기술적 페인 포인트(Pain Point)들과, 이를 해결하기 위해 내린 아키텍처적 선택 및 트레이드 오프(Trade-off) 과정을 공유합니다.

## 1. 문제 정의 (Problem): 사소하지만 치명적이었던 3가지 UX 결함

기존 PickSafe의 마이페이지와 인증 시스템은 빠른 MVP 출시를 목표로 설계되어, 몇 가지 구조적 한계를 가지고 있었습니다.

### ① 모바일/PWA 환경에서의 모달 팝업의 한계
기존의 설정 화면은 마이페이지 내에서 팝업 모달(Modal) 형태로 렌더링되었습니다. 하지만 모바일 웹 및 PWA(Progressive Web App) 환경에서 모달 방식은 화면 집중도를 떨어뜨렸습니다. 특히 PickSafe는 **6개 국어 다국어 설정, 계정 정보 조회, 보안 관리** 등 밀도가 높은 정보들을 다루어야 했기에, 좁은 모달창 내부의 사용성은 극도로 답답해지는 문제가 있었습니다.

### ② 잦은 로그인 만료로 인한 개인화 경험 단절
PickSafe는 유저가 설정한 '기피 성분'과 '찜 목록' 기반의 맞춤형 데이터를 제공합니다. 즉, 로그인 상태가 지속되어야 서비스의 가치가 극대화됩니다. 그러나 기존의 세션 유효기간은 상대적으로 짧게 설정되어 있어 유저가 재방문 시 다시 로그인을 해야 하는 번거로움이 있었습니다. 설상가상으로 상단 헤더 영역에 로그아웃 버튼이 무방비하게 노출되어 있어, 실수로 로그아웃을 눌러 세션이 끊기는 일도 빈번했습니다.

### ③ '돌아올 다리'를 끊어버리는 1단계 회원 탈퇴/로그아웃 UX
회원 탈퇴나 로그아웃과 같은 민감한 계정 조작이 단 한 번의 클릭(1단계 인터랙션)으로 실행되거나 경고가 미흡했습니다. 이는 의도치 않은 계정 탈퇴로 이어져 소중한 유저 데이터가 영구 삭제되는 치명적인 유저 경험 저해 요인이었습니다.

## 2. 기술적 고민과 대안 비교 (Trade-off)

우리는 위 문제들을 해결하기 위해 백엔드 구조와 프론트엔드 네비게이션의 대대적인 체질 개선을 단행했습니다.

### 고민 1. 독립된 `/settings` 라우트 도입 vs 모달 컴포넌트 고도화

* **대안 A (기존 모달 고도화):** 반응형 CSS를 극대화하여 모바일 전용 모달 뷰를 고도화하는 방안. 
  * *장점:* 추가적인 라우터 설계가 필요 없고 프론트엔드 작업만으로 완결 가능.
  * *단점:* 브라우저 '뒤로가기' 버튼 클릭 시 모달이 닫히는 대신 이전 페이지로 넘어가 버리는 고질적인 모바일 UX 오류 제어의 한계. URL 공유 불가능.
* **대안 B (독립 페이지 분리 - 선택):** `/settings` 전용 엔드포인트를 신설하고, 설정을 독립된 하나의 페이지 뷰로 렌더링하는 방안.
  * *장점:* 명확한 상태 관리, 브라우저 히스토리 백(Back) 기능과의 완벽한 호환, 3대 섹션(언어/계정/보안)의 여유로운 레이아웃 확보.
  * *선택 이유:* 모바일 및 PWA 환경에서 네이티브 앱과 같은 부드러운 전환 효과를 주기 위해서는 독립적인 라우트 관리가 필수적이라고 판단했습니다.

### 고민 2. 세션 만료 정책: 보안(Short-lived) vs 편의성(Long-lived)

보안 관점에서 세션 쿠키의 수명은 짧을수록 안전합니다. 하지만 금융/결제 서비스가 아닌 PickSafe의 도메인 특성상, **"유저 편의성과 리텐션"**이 보안보다 더 높은 비즈니스 우선순위를 가집니다.

* **결정:** 글로벌 빅테크 및 SNS 서비스의 로그인 유지 정책을 벤치마킹하여, 세션 토큰 쿠키의 유효기간(`max_age`)을 **1년(31,536,000초)**으로 대폭 늘렸습니다. 
* **보안 보완책:** 세션 수명을 늘리는 대신, 유저가 실수로 로그아웃 경로를 밟지 않도록 로그아웃 진입 장벽을 높였습니다. 상단 헤더에서 로그아웃 버튼을 완전히 제거하고, **[마이페이지 > 설정 > 보안 및 계정 관리]**의 깊숙한 경로 내부로 이동시켜 우발적인 세션 파괴를 방지했습니다.

## 3. 최종 해결 및 엔지니어링 구현 (Implementation)

개발팀은 백엔드(FastAPI)와 프론트엔드 아키텍처 전반에 걸쳐 유기적인 변경을 적용했습니다. 보안을 위해 내부 비즈니스 로직과 민감 정보는 마스킹 처리된 구조적 흐름으로 설명합니다.

```
[User] ──(Click Settings)──> /settings (FastAPI Router)
                                   │
                                   ├──> Multi-language Seed Check (6 Languages)
                                   ├──> Fetch Account Meta (Provider, Masked Email)
                                   └──> Render settings.html (Unified View)
```

### 1) 백엔드: 안정적인 대용량 쿠키 세션 생명주기 설정 (FastAPI)
백엔드 로그인 완료 처리기(`finalize_login`)에서 세션 토큰 발행 시 `max_age` 값을 설정하여 브라우저가 유효기간을 1년간 유지하도록 처리했습니다.

```python
# web/backend/app/routers/auth.py (일부 도식화)
from fastapi import APIRouter, Response

router = APIRouter()

@router.post("/login/finalize")
async def finalize_login(response: Response, user_id: str):
    # 세션 토큰 생성 로직 (보안 마스킹 처리)
    session_token = generate_secure_session_token(user_id)
    
    # 1년(365일) 장기 세션 쿠키 설정
    ONE_YEAR_SECONDS = 365 * 24 * 60 * 60 # 31,536,000초
    
    response.set_cookie(
        key="session_id",
        value=session_token,
        max_age=ONE_YEAR_SECONDS,
        httponly=True,
        secure=True, # HTTPS 환경 필수 적용
        samesite="lax"
    )
    return {"status": "success"}
```

### 2) 프론트엔드: 이탈 방어형 'Defensive UX' (Two-Step Modal)
회원 탈퇴 시 우발적인 이탈을 막기 위해 **2단계 모달(Two-Step Modal)** 시스템을 구축했습니다. 특히, 심리학적 UX 설계를 도입하여 유저가 본능적으로 누르기 쉬운 '강조 버튼'에 탈퇴가 아닌 **[계속 이용하기(취소)]**를 배치하고, 탈퇴 실행 버튼은 채도가 낮은 서브 스타일로 배치하여 사용자가 한 번 더 숙고하도록 유도했습니다.

```javascript
// web/frontend/static/js/auth.js (추상화된 구조)
const AccountManager = {
    currentStep: 1,

    showDeleteModal() {
        this.renderStep(1);
    },

    renderStep(step) {
        if (step === 1) {
            // 1단계: 데이터 영구 삭제 경고 및 안내
            Modal.show({
                title: "정말 탈퇴하시겠습니까?",
                body: "기피 성분 설정 및 찜 목록이 모두 삭제되며 복구할 수 없습니다.",
                primaryBtn: { text: "계속 이용하기", action: () => Modal.close() }, // 이탈 방어
                secondaryBtn: { text: "다음 단계", action: () => this.renderStep(2) }
            });
        } else if (step === 2) {
            // 2단계: 복구 불가 최종 확인 후 API 요청
            Modal.show({
                title: "마지막으로 확인해주세요",
                body: "지금 탈퇴하시면 모든 맞춤형 혜택이 영구 소멸됩니다.",
                primaryBtn: { text: "계속 이용하기", action: () => Modal.close() },
                secondaryBtn: { text: "탈퇴 완료", action: () => this.requestAccountDeletion() }
            });
        }
    },

    async requestAccountDeletion() {
```

## 4. 엔지니어링 교훈 (Takeaways)

이번 개편 작업을 통해 개발팀은 기술적으로 큰 도약을 이룰 수 있었으며, 다음과 같은 중요한 교훈을 배웠습니다.

1. **기술적 결정은 비즈니스 지표(KPI)와 직결된다:** 
   단순히 보안 표준만을 고집하여 짧은 세션 만료 시간을 유지하는 것보다, 비즈니스 특성(개인화 추천 서비스)을 고려해 세션 주기를 1년으로 대폭 확장한 것이 유저 편의성과 리텐션 지표에 훨씬 긍정적인 영향을 미쳤습니다.
2. **때로는 '불편함(Friction)'이 훌륭한 기능이 된다:**
   일반적으로 개발자는 마찰 없는(Frictionless) 매끄러운 UX를 추구해야 합니다. 하지만 회원 탈퇴나 로그아웃처럼 되돌릴 수 없는 파괴적인 액션에 대해서는 의도적인 시스템적 마찰(2단계 모달, Depth 깊게 하기)을 제공하는 것이 사용자 데이터를 안전하게 보호하고 고객 이탈을 방어하는 '좋은 엔지니어링 패러다임'임을 깨달았습니다.
3. **PWA 시대의 프론트엔드는 모바일 중심(Mobile-First)이어야 한다:**
   웹 서비스를 패키징하여 앱처럼 사용하는 PWA 환경에서는 모달 팝업보다 명확한 단독 페이지 라우팅(`/settings`)이 훨씬 안정적인 네비게이션 제어력과 쾌적한 뷰를 보장합니다.

앞으로도 PickSafe 기술 블로그에서는 사용자 경험을 개선하기 위한 기술적 고군분투기를 지속적으로 공유하겠습니다. 의견이나 질문이 있으시다면 언제든 댓글로 남겨주세요!
