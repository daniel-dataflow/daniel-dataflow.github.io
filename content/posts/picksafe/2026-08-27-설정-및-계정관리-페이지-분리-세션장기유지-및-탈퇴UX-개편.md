안녕하세요, **PickSafe** 개발팀입니다. 
서비스를 고도화하면서 기능이 추가됨에 따라, 초기에 가볍게 설계했던 UI와 세션 관리 정책들이 사용자 경험(UX)의 발목을 잡는 순간이 찾아옵니다. 

이번 포스팅에서는 **모바일 웹 및 PWA 환경에서 마이페이지 설정 화면을 전면 개편**하고, **세션 정책 및 위험한 인터랙션(로그아웃, 회원 탈퇴)을 재설계**한 기술적 의사결정 과정과 트레이드오프를 공유하고자 합니다.

---

## 1. Problem: 작은 화면 속 모달과 빈번한 세션 만료의 불편함

우리가 마주한 문제는 크게 세 가지였습니다.

1. **모바일/PWA 환경에서의 팝업 모달 한계**
   기존에는 마이페이지 상단의 톱니바퀴 아이콘을 누르면 **모달 팝업** 형태로 설정 레이어가 떴습니다. 하지만 모바일 화면에서 언어 설정, 계정 정보, 보안 관리 등 다양한 정보를 팝업 안에 우겨넣다 보니 화면 집중도가 극도로 떨어지고 공간이 협소해 답답한 UX를 제공하고 있었습니다.
2. **짧은 세션 주기로 인한 개인화 데이터 접근성 저하**
   PickSafe는 사용자의 기피 성분과 찜 목록 등 핵심 개인화 데이터를 다룹니다. 연속적인 경험을 제공해야 함에도 세션 유효기간이 상대적으로 짧았고, 상단 헤더에 떡하니 노출된 로그아웃 버튼 때문에 사용자가 실수로 로그아웃되는 리스크가 존재했습니다.
3. **치명적인 인터랙션(회원 탈퇴/로그아웃)의 낮은 진입 장벽**
   중요한 계정 조작인 로그아웃과 회원 탈퇴가 헤더나 단순 1단계 버튼으로 노출되어 있었습니다. 특히 회원 탈퇴의 경우, 사용자가 한 번 더 숙고할 수 있는 안전장치가 부족하여 우발적인 계정 이탈 위험이 컸습니다.

---

## 2. Trade-off & Architecture: 어떻게 해결할 것인가?

문제를 해결하기 위해 백엔드와 프론트엔드 전반에 걸쳐 아키텍처와 UX 정책을 수정했습니다.

### ① 팝업 모달 폐지 및 독립 전용 페이지(`/settings`) 신설
* **Alternative (기존 모달 유지 + 반응형 CSS 개선):** 개발 공수가 적지만, 모바일 디바이스의 제한된 뷰포트 문제를 근본적으로 해결할 수 없었습니다.
* **Decision:** 독립적인 라우트(`/settings`)를 신설하여 풀페이지(Full-page) 뷰로 전환했습니다. 
  * 상단에 명확한 뒤로가기(`← 마이페이지`) 네비게이션을 배치하고, 페이지를 **언어 설정 / 계정 정보 / 보안 및 계정 관리** 3대 섹션으로 구조화하여 정보 가독성을 극대화했습니다.

### ② 세션 쿠키 365일 장기 유지 및 헤더 클린업
* **Alternative (단기 세션 + 리프레시 토큰 로직 구현):** 보안성은 높으나, 현재 서비스 규모와 인프라 리소스 대비 구현 및 유지보수 비용이 컸습니다.
* **Decision:** 글로벌 빅테크 앱(카카오 등)의 패턴을 차용하여, 로그인 완료 시 세션 토큰 쿠키의 `max_age`를 **1년(31,536,000초)**으로 대폭 늘렸습니다. 
* 이와 동시에, 헤더에 노출되던 로그아웃 버튼을 전면 제거하고 **[설정 > 보안 및 계정 관리]** 내부로 깊숙이 숨겼습니다. 실수로 로그아웃될 위험을 원천 차단하고 개인화 데이터 보존성을 높인 트레이드오프입니다.

### ③ 2단계 모달(Two-Step Modal) UX 도입
* **Alternative (단순 "정말 탈퇴하시겠습니까?" 윈도우 팝업):** 브라우저 기본 `confirm()`은 디자인 통일성을 해치고 사용자의 주의를 환기시키기 어렵습니다.
* **Decision:** 커스텀 2단계 모달을 구축했습니다.
  * **1단계:** 데이터 영구 삭제 경고 및 안내
  * **2단계:** 최종 확인 및 복구 불가 안내
* 특히, 다크패턴의 반대 개념으로 **취소 버튼(`계속 이용하기`)을 시각적으로 강조**하고, 삭제 버튼은 보조 스타일로 배치하여 사용자의 우발적 이탈을 효과적으로 방어했습니다.

## 3. Implementation Overview

실제 구현은 FastAPI 백엔드 라우터와 Jinja2 템플릿, 그리고 Vanilla JavaScript(`auth.js`)를 활용해 깔끔하게 분리했습니다.

* **Backend (`routers/mypage.py`, `routers/auth.py`):**
  * `/settings` 전용 라우트를 신설하여 언어 설정, 가입 공급자(Google/Facebook/Email), 가입 일시 등의 메타데이터를 템플릿에 안전하게 주입.
  * 로그인 완료 시점의 쿠키 설정에 `max_age=31536000` 적용.
* **Frontend (`settings.html`, `auth.js`):**
  * 6개 국어 다국어(`i18n`) 시드 데이터를 연동하여 글로벌 유저 대응.
  * 탈퇴 프로세스를 상태값(Step 1, Step 2)에 따라 유연하게 제어하는 JS 이벤트 리스너 구현.

## 4. Takeaway: 시니어 에디터의 회고

이번 리팩토링은 단순히 화면 몇 개를 고치고 디자인을 바꾼 작업이 아닙니다. **"사용자에게 편안함을 주는 동시에, 서비스가 지켜야 할 핵심 데이터와 세션을 안전하게 보호하는 균형을 찾는 과정"**이었습니다.

1. **UX는 동선뿐만 아니라 '심리적 안전장치'도 포함한다:** 탈퇴나 로그아웃 같은 파괴적인 액션은 의도적으로 접근성을 낮추고(Friction 추가), 반대로 자주 쓰는 기능이나 개인화 데이터 유지는 접근성을 극대화하는 것이 올바른 UX 설계라는 점을 다시 한번 확인했습니다.
2. **모바일 퍼스트는 '공간 활용'에서 시작된다:** 모바일 웹에서 모달은 편할 것 같지만, 정보량이 많아지는 순간 오히려 독이 됩니다. 과감하게 독립 페이지로 라우팅을 분리한 것이 장기적으로 확장성 있는 선택이 되었습니다.

앞으로도 PickSafe는 작은 디테일 하나까지 놓치지 않는 견고한 엔지니어링을 선보이겠습니다. 감사합니다!
