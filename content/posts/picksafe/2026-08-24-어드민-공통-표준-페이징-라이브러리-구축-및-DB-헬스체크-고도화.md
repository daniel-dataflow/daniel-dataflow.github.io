안녕하세요, PickSafe 백엔드/플랫폼 팀입니다. 

서비스가 급성장함에 따라 성분 마스터 데이터(3만 건 이상), 방문자 로그, 고객 문의 등 관리해야 할 대형 데이터셋이 급증했습니다. 이에 비례하여 백오피스(어드민) 시스템의 사용 빈도도 높아졌지만, 역설적으로 **"어드민 코드가 파편화되어 유지보수가 어려워지고, DB 장애 인지가 지연되는 문제"**가 수면 위로 떠올랐습니다.

이번 글에서는 어드민 시스템의 기술 부채를 과감히 청산하고, 시스템 안정성과 운영 효율성을 동시에 끌어올린 아키텍처 개선 여정을 공유합니다.

---

## 1. 문제 정의 (Context & Problem)

비즈니스 속도에 맞춰 기능을 빠르게 추가하다 보니, 어드민 시스템 내부에 다음과 같은 구조적 문제가 누적되었습니다.

1. **페이징 로직의 파편화 (Frontend Tech Debt)**
   * 페이지마다 개발 당시의 필요에 따라 `renderPagination`, `createPageNav` 등 제각각의 페이징 UI 함수를 파편화하여 구현하고 있었습니다.
   * 이로 인해 디자인 일관성이 깨지고, 페이징 관련 버그 수정 시 모든 페이지를 일일이 수정해야 하는 높은 유지보수 비용이 발생했습니다.
2. **단순 DB 핑(Ping) 방식의 한계 (Observability Blind Spot)**
   * 메인 DB와 보조(DW) DB 간의 헬스체크 로직이 단순 연결 확인 수준에 머물렀습니다.
   * 실제 Failover 스위칭 상태나 커넥션 풀 고갈 상황을 정확히 반영하지 못해, 관리자 화면에 불필요한 오탐 알람이 발생하거나 반대로 실제 장애를 놓치는 사각지대가 존재했습니다.
3. **슬랙 장애 알림의 가독성 및 맥락 부족**
   * 서버 다운타임이나 예외 발생 시 전송되는 슬랙 알림에 에러 스택트레이스와 발생 맥락(Context) 정보가 부족하여, 원인 규명(Debugging)에 불필요한 시간이 소요되었습니다.

---

## 2. 기술적 고민과 아키텍처 대안 비교

이 문제를 해결하기 위해 팀 내 논의를 거쳐 다음과 같은 원칙을 세우고 개선 작업을 진행했습니다.

### 2.1. 프론트엔드: 전역 공통 모듈 기반의 `renderStandardPagination` 설계
* **대안 비교**: 
  * *Option A)* 각 페이지별 컴포넌트 리팩토링 (제외: 비용 대비 효과 낮음)
  * *Option B)* 바닐라 JS 기반의 가벼운 전역 공통 모듈화 (`admin_common.js`) (채택)
* **구현**: 어드민 전체 하위 페이지(성분 관리, 번역, 로그 등)에서 단 1줄의 함수 호출로 직관적인 반응형 페이지 네비게이션이 렌더링되도록 일원화했습니다. 또한 페이지당 노출 개수(10/20/50개)를 동적으로 변경할 수 있는 셀렉터를 내장하여 데이터 탐색 편의성을 극대화했습니다.

### 2.2. 백엔드: 무중단 DB 헬스체크 프로브 (Health Probe) 도입
* **고민**: 헬스체크 쿼리가 메인 DB에 과도한 부하를 주거나, 복제 지연으로 인한 잘못된 상태를 반환하면 안 됩니다.
* **해결**: 
  * `SELECT 1` 쿼리에 엄격한 타임아웃(2초)을 적용하고, 실제 읽기/쓰기 가능 여부를 가볍게 점검하도록 프로브를 최적화했습니다.
  * 메인 DB와 보조 DB의 활성 상태를 실시간 배지 UI로 어드민 상단에 시각화하여, 운영자가 시스템의 데이터소스 상태를 직관적으로 인지할 수 있게 했습니다.

### 2.3. 텔레메트리: 슬랙 Block Kit 기반 리치 알림 고도화
* 단순 텍스트 에러 로그 전송 방식에서 벗어나, 슬랙 Block Kit 포맷을 도입했습니다.
* 서버 호스트, 정확한 에러 메시지, 영향받은 라우터 정보, 타임스탬프를 구조화하여 장애 발생 시 즉각적으로 원인을 유추할 수 있도록 텔레메트리를 강화했습니다.

## 3. 최종 결과 및 엔지니어링 교훈 (Takeaway)

이번 표준화 및 헬스체크 고도화 작업을 통해 다음과 같은 정량적/정성적 성과를 거두었습니다.

* **코드 베이스 경량화**: 어드민 프론트엔드 전반에 걸쳐 중복되던 파편화된 코드 **1,000라인 이상을 제거**하고 유지보수성을 대폭 향상.
* **장애 대응 시간(MTTD) 단축**: 실시간 DB 상태 시각화와 상세한 슬랙 텔레메트리 덕분에, 시스템 이상 징후 인지 및 초기 대응 시간이 **80% 단축**.

### 💡 에디터의 요약 (Takeaway for Interviewers)
이번 프로젝트는 **"기술 부채를 방치하지 않고 공통화(Standardization)와 관측 가능성(Observability) 확보를 통해 프로덕트의 기초 체력을 다진 모범적인 사례"**입니다. 단순히 기능을 만드는 것을 넘어, 대규모 데이터를 다루는 백오피스 환경에서 운영 효율성과 시스템 신뢰성을 어떻게 높여야 하는지 고민한 엔지니어링 역량이 잘 드러납니다.
