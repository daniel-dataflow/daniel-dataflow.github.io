안녕하세요, PickSafe 백엔드/인프라스트럭처 팀입니다.

서비스가 가파르게 성장함에 따라 마스터 데이터, 방문자 로그, 고객 문의 등 관리해야 할 데이터가 수만 건 이상으로 급증했습니다. 이에 비례하여 운영을 담당하는 어드민 시스템의 중요도도 함께 높아졌죠. 

하지만 빠른 기능 개발에 집중하다 보니 어드민 코드베이스는 서서히 기술 부채를 안게 되었습니다. 이번 글에서는 **어드민 프론트엔드 코드 파편화 해결**, **DB 헬스체크 메커니즘 고도화**, 그리고 **장애 인지 시간(MTTD)을 획기적으로 단축한 슬랙 텔레메트리 개선 과정**을 공유하고자 합니다.

---

## 1. 마주한 문제 (Problem)

급격한 스케일업 과정에서 어드민 시스템은 다음과 같은 구조적 한계에 부딪혔습니다.

1. **페이징 로직의 파편화 (코드 중복)**
   성분 관리, 방문자 로그, 1:1 문의 등 각 메뉴마다 페이징 UI를 그리는 함수(`renderPagination`, `createPageNav` 등)가 제각각 구현되어 있었습니다. 페이지 이동당 구현 방식이 달라 유지보수가 어려웠고, 신규 기능 추가 시마다 동일한 UI 코드를 반복 작성하는 비효율이 발생했습니다.
2. **단순 DB 핑(Ping) 헬스체크의 한계**
   메인 DB와 보조(DW) DB 간의 상태를 체크할 때 단순한 연결 테스트에 의존했습니다. 실제 커넥션 풀 포화 상태나 장애로 인한 Failover 스위칭 상황을 정확히 감지하지 못해 관리자 화면에 불필요한 노이즈 알람을 주거나, 반대로 실제 장애를 놓치는 경우가 발생했습니다.
3. **불충분한 장애 맥락(Context)**
   서버 장애 발생 시 슬랙(Slack)으로 전송되는 에러 로그에 단순 스택트레이스만 담겨 있어, 어떤 호스트에서 발생한 문제인지, 어떤 비즈니스 라우터에 영향을 미쳤는지 파악하기 위해 로그 시스템을 일일이 뒤져야 하는 시간 손실이 있었습니다.

---

## 2. 기술적 고민과 아키텍처 대안 (Trade-off & Solution)

### 2.1. 프론트엔드 공통 표준 페이징 모듈화 (`admin_common.js`)

**[대안 검토]**
* **안 A (각 페이지별 유지 및 리팩토링)**: 리소스는 적게 들지만 향후 기능 추가 시 파편화가 더욱 가속화됨.
* **안 B (써드파티 UI 라이브러리 도입)**: 무거운 의존성이 추가되고, 어드민의 가벼운 바닐라 자바스크립트 구조에 과도한 오버헤드 발생.
* **안 C (전역 바닐라 모듈 기반 표준 렌더러 구현)**: 가볍고 커스텀이 용이하며, 단 1줄의 함수 호출로 일관된 UI 제공 가능.

**[선택 및 구현]**
우리는 **안 C**를 채택하여 `admin_common.js` 내에 `renderStandardPagination` 표준 함수를 구현했습니다. 
* 30,000건 이상의 대용량 성분 데이터나 로그를 효율적으로 탐색할 수 있도록 `[<< 이전] [1] ... [4] [5] [6] ... [20] [다음 >>]` 형태의 직관적인 반응형 네비게이션 구조를 정립했습니다.
* 사용자가 데이터 조회 단위를 유연하게 바꿀 수 있도록 페이지당 노출 개수(10/20/50개) 동적 셀렉터를 내장하여 사용성을 극대화했습니다.

### 2.2. 부하를 최소화하는 무중단 DB 헬스체크 프로브 (Health Probe)

헬스체크 자체가 메인 DB에 과부하를 주지 않으면서도 실제 쓰기/읽기 가용성을 정확히 판단해야 했습니다.

* **타임아웃 제어**: 2초 이내에 응답하지 않는 경우 비정상으로 간주하는 가벼운 쿼리 프로브(`SELECT 1` 기반)를 적용했습니다.
* **Active DB 시각화**: 메인 DB와 보조 DB 간의 Failover 상태를 실시간으로 감지하여, 어드민 상단 대시보드에 현재 활성화된 DB 노드 상태를 배지 UI로 즉시 시각화하도록 개선했습니다.

### 2.3. 슬랙 Block Kit 기반 리치 텔레메트리 구축

장애 발생 시 3초 안에 원인을 직관적으로 파악할 수 있도록 슬랙 알림 구조를 개편했습니다.
* 단순 텍스트 대신 슬랙 **Block Kit** 포맷을 도입하여 에러 메시지, 영향받은 서버 호스트, 라우터 정보, 정확한 타임스탬프를 시각적으로 분리하여 전송했습니다.

## 3. 결과 및 성과 (Takeaway)

이번 개선을 통해 다음과 같은 정량적/정성적 성과를 거둘 수 있었습니다.

* **코드 품질 향상**: 어드민 프론트엔드 전체에서 중복되던 뷰 렌더링 코드 **1,000라인 이상을 제거**하여 응집도를 높였습니다.
* **MTTD(Mean Time To Detect) 80% 단축**: 상세한 슬랙 텔레메트리와 직관적인 DB 상태 시각화 덕분에, 시스템 이상 징후 발생 시 원인 파악 및 대응까지 소요되는 시간이 대폭 단축되었습니다.
* **운영 안정성 확보**: 대용량 데이터 환경에서도 일관된 UX를 제공하는 표준 페이징 인프라를 다져 향후 서비스 확장 기반을 공고히 했습니다.

> **에디터의 한 줄 평**: 
> 기술 부채는 방치하면 복리로 이자가 붙습니다. 이번 어드민 표준화 작업은 단순한 코드 정리를 넘어, 시스템의 관측 가능성(Observability)을 높여 운영 효율성을 극대화한 모범적인 리팩토링 사례입니다.
