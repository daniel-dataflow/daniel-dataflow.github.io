안녕하세요, PickSafe 백엔드/인프라스트럭처 엔지니어 Daniel & Antigravity입니다. 

서비스가 성장함에 따라 다루어야 할 데이터의 규모도 급증합니다. 성분 마스터 데이터(3만 건 이상), 방대한 방문자 로그, 고객 문의 내역 등 어드민에서 처리해야 할 데이터가 늘어나면서, **"초기 속도에 집중하느라 미처 다듬지 못한 기술 부채"**들이 수면 위로 드러나기 시작했습니다.

이번 포스팅에서는 어드민 시스템의 유지보수성을 극적으로 끌어올리고, 시스템 장애 인지 시간(MTTD)을 80% 단축시킨 **어드민 공통 표준 페이징 라이브러리 구축**과 **DB 헬스체크 고도화** 과정에서 마주한 문제와 해결 방안(Trade-off)을 공유합니다.

---

## 1. 배경 및 문제 상황 (Context & Problem)

초기 MVP 단계의 속도전을 거치며 어드민 페이지들은 다음과 같은 고질적인 아키텍처적 한계를 안고 있었습니다.

### ① 페이징 코드의 심각한 파편화
페이지별로 개발 시점이 다르다 보니, 데이터 목록을 렌더링하는 페이징 UI 함수(`renderPagination`, `createPageNav` 등)가 각 페이지마다 제각각 구현되어 있었습니다. 새로운 필터 조건을 추가하거나 디자인을 수정할 때마다 모든 파일을 찾아 수정해야 했고, 이는 곧 휴먼 에러와 버그로 직결되었습니다.

### ② 단순 DB 핑(Ping)의 한계와 가시성 부족
메인 DB와 보조 DW(Data Warehouse) 간의 이중화 환경에서 헬스체크 로직이 단순 커넥션 핑 수준에 머물렀습니다. 이로 인해 실제 Failover 스위칭 상태나 커넥션 풀의 고갈을 정확히 반영하지 못했고, 관리자 화면에 불필요한 오탐(False Positive) 알람이 빈번하게 발생했습니다.

### ③ 장애 텔레메트리의 맥락(Context) 부족
서버 에러 발생 시 슬랙(Slack)으로 전달되는 알람에 단순 에러 메시지만 덩그러니 찍혀 있어, 어떤 라우터에서 어떤 호스트로 인해 발생한 문제인지 파악하려면 일일이 로그 서버를 뒤져야 했습니다.

## 2. 해결 방안 및 기술적 구현 (Technical Implementation)

우리는 이 문제를 해결하기 위해 **프론트엔드 코드 표준화**, **경량화된 헬스 프로브**, 그리고 **풍부한 텔레메트리**라는 세 가지 축을 중심으로 개선 작업을 진행했습니다.

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 표준 공통 페이징 라이브러리 (renderStandardPagination)   │
│    - static/js/admin/admin_common.js 전역 모듈화             │
│    - [<< 이전] [1] ... [4] [5] [6] ... [20] [다음 >>] 구조   │
│    - 페이지당 노출 개수(10/20/50개) 동적 셀렉터 내장         │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│ 2. DB 헬스체크 & Failover 감지 엔진 최적화                   │
│    - SELECT 1 쿼리 타임아웃(2초) 및 실제 쓰기 가능 여부 점검 │
│    - 메인 DB ↔ 보조 DB 활성 상태 실시간 배지 UI 시각화     │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│ 3. 슬랙(Slack) 장애 텔레메트리 상세화                        │
│    - 서버 호스트, 에러 메시지, 영향받은 라우터 및 타임스탬프 │
│    - 리치 블록 키트(Block Kit) 포맷 알림 전송               │
└─────────────────────────────────────────────────────────────┘
```

### 2.1. `admin_common.js` 기반 표준 페이징 모듈화
각각 흩어져 있던 페이징 로직을 하나의 전역 모듈(`admin_common.js`)로 통합했습니다.
* **동적 페이지 네비게이션**: 대용량 데이터 탐색에 최적화된 생략 부호(`...`) 처리와 직관적인 이전/다음 구조를 적용했습니다.
* **유연한 뷰어 설정**: 관리자가 직접 페이지당 노출 개수(10/20/50개)를 동적으로 변경할 수 있도록 셀렉터 컴포넌트를 내장했습니다.
* 이를 통해 하위 어드민 페이지(성분, 번역, 로그 등)에서는 단 1줄의 함수 호출(`renderStandardPagination`)만으로 일관된 UI/UX를 제공할 수 있게 되었습니다.

### 2.2. 부하 없는 무중단 DB 헬스 프로브
기존의 무거운 헬스체크 방식을 들어내고, DB 커넥션 풀에 불필요한 과부하를 주지 않는 **경량 쿼리 타임아웃(2초 내 `SELECT 1`) 메커니즘**을 도입했습니다.
* 단순히 살아있는지만 보는 것이 아니라, 실제 읽기/쓰기 권한 및 Failover 상태를 실시간으로 감지합니다.
* 어드민 상단 대시보드에 현재 활성화된 Primary/Secondary DB 상태를 실시간 배지 UI로 시각화하여 운영자가 시스템 상태를 직관적으로 인지할 수 있도록 개선했습니다.

### 2.3. Slack Block Kit 기반 텔레메트리 강화
장애 발생 시 단순히 "에러 발생"을 외치던 슬랙 알람을 개편했습니다. 
* 발생 시각, 영향받은 서버 호스트, 에러 스택트레이스, 그리고 정확한 라우터 정보를 담은 **Rich Block Kit** 포맷으로 전송되도록 변경하여, 개발자가 슬랙 메시지만 보고도 즉각적으로 원인을 유추할 수 있게 되었습니다.

## 3. 결과 및 맺음말 (Results & Takeaways)

이번 아키텍처 개선을 통해 얻은 성과는 명확합니다.

1. **코드베이스 경량화**: 어드민 프론트엔드 전반에 걸쳐 중복되던 스파게티 코드 **1,000라인 이상을 제거**하여 유지보수성을 대폭 향상시켰습니다.
2. **MTTD(Mean Time to Detect) 80% 단축**: 명확해진 슬랙 알람 텔레메트리와 실시간 DB 헬스 프로브 덕분에, 잠재적 장애 징후를 감지하고 원인을 파악하는 시간이 극적으로 단축되었습니다.

### 💡 엔지니어링 교훈 (Takeaways)
> *"기술 부채는 미룰수록 이자가 불어난다. 핵심 비즈니스 로직 외의 '운영 도구(Admin)' 품질은 결국 전체 시스템의 신뢰도와 개발자 경험(DX)을 결정하는 핵심 지표다."*

PickSafe는 앞으로도 빠르고 안정적인 서비스 제공을 위해, 내부 시스템의 보이지 않는 곳까지 치밀하게 다듬어 나가는 엔지니어링 문화를 이어갈 것입니다. 읽어주셔서 감사합니다!
