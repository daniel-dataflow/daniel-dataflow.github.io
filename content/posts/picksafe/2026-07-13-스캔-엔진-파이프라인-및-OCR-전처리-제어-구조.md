## 1. 문제 정의: 실세계 데이터는 결코 정갈하지 않다

모바일 카메라를 통해 화장품 전성분표를 인식하고 분석하는 기능은 얼핏 단순한 **'OCR + 데이터베이스 조회'** 문제로 보입니다. 하지만 실제 사용자가 촬영하는 환경은 연구실 환경과 극명하게 다릅니다.

* **실환경 노이즈**: 제품 용기의 곡면 왜곡, 비닐 포장의 조명 반사, 손떨림 및 저해상도 폰트
* **구분자 유실**: 쉼표(`,`)나 점(`.`)의 누락/뭉개짐으로 인해 `정제수글리세린`처럼 복합 텍스트가 하나로 뭉치는 현상
* **명칭 불일치**: 구 성분명(`디메치콘`)과 표준 성분명(`다이메티콘`), 다국어 INCI 명칭 간의 비정합
* **네트워크 병목**: 모바일 4K 원본(5MB~10MB) 업로드로 인한 지연(Latency) 및 API 타임아웃 위험

우리는 단순 텍스트 추출 엔진만으로는 프로덕션 레벨의 사용자 경험을 제공할 수 없다는 결론을 내렸고, **클라이언트 전처리부터 LLM Vision, 텍스트 정규화에 이르는 3단계 파이프라인**을 재설계했습니다.

## 2. 파이프라인 아키텍처 설계

전체 처리 과정은 네트워크 비용을 최소화하고, 비정형 이미지 데이터를 신뢰도 높은 정형 데이터로 변환하는 파이프라인 구조를 갖습니다.

```
[ 클라이언트 (Client) ]
  └─ Canvas API 기반 인메모리 압축 (4K ➔ Max 1200px, JPEG 85%)
            │ (업로드 대역폭 90% 절감, Payload < 300KB)
            ▼
[ 백엔드 분석 파이프라인 (Vision AI Service) ]
  └─ 비정형 텍스트 추출 및 JSON 스키마 강제화 (프롬프트 엔지니어링)
            │ (Raw Ingredient Array 추출)
            ▼
[ 도메인 정규화 엔진 (Normalization & Matching Engine) ]
  └─ 특수문자/괄호 분해 규칙 엔진
  └─ INCI 표준 성분명 및 알레르기 유발 물질 매칭
```

## 3. 핵심 엔지니어링 의사결정과 Trade-off

### ① 서버 리사이징 vs 클라이언트 사전 압축 (Client-side Compression)
* **고민**: 이미지 화질 손실을 최소화하려면 원본을 서버로 받아 고성능 이미지 프로세싱 라이브러리로 처리하는 것이 유리합니다.
* **선택**: **클라이언트 브라우저 Canvas API 활용**.
* **이유**: 모바일 네트워크 환경(LTE/5G 음영 지역)에서 5~10MB 이미지 업로드는 네트워크 I/O 병목을 유발합니다. 브라우저 단에서 텍스트 판독이 가능한 최적 해상도(1200px, 압축률 85%)로 리사이징하여 전송 페이로드를 **300KB 수준(90% 이상 절감)**으로 낮췄고, 업로드 지연시간을 5초 이상 단축했습니다.

### ② 전통적 Rule-based OCR vs Vision-LLM 기반 파싱
* **고민**: 전통적인 Tesseract 등의 OCR 엔진은 가볍고 빠르지만, 글자 뭉침(`정제수글리세린`)이나 줄바꿈 처리에서 에러율이 높았습니다.
* **선택**: **Gemini Vision API 기반의 구조화 추출**.
* **이유**: 문맥(Context)을 이해할 수 있는 Vision 모델에 정형 JSON 스키마를 지정하여, 누락된 구분자를 맥락 기반으로 복원하고 배열 형태로 정제된 데이터를 즉시 도출했습니다.

### ③ 괄호 및 부가 정보 정규화 파서 (Normalization Engine)
* **고민**: `글리세린(식물성)`, `향료(리모넨 함유)` 등 성분표 내 괄호 표기는 표준 DB 조회를 가로막는 주요 원인입니다.
* **해결**: 도메인 정규식 엔진을 구축하여 메인 성분과 부가 속성을 분리하고, 식약처 공인 알레르기 성분 및 유저별 기피 성분을 O(1) 수준으로 판별할 수 있도록 전처리 레이어를 분리했습니다.

## 4. 결과 및 엔지니어링 교훈 (Takeaways)

* **정확도 향상**: 복합 성분 오인식률을 제거하여 성분 매칭 정확도를 기존 대비 **35% 개선**했습니다.
* **응답 속도 최적화**: 프론트엔드 전처리와 백엔드 경량 파이프라인 결합을 통해 전체 분석 Latency를 **평균 1.5초 이내**로 안정화했습니다.

> **Key Takeaway**  
> AI 및 Vision 기술을 서비스에 녹여낼 때 가장 중요한 것은 모델 자체의 성능뿐 아니라, **입력 데이터가 유입되는 첫 관문(Client)부터 후처리(Domain Logic)까지의 비용-지연시간(Cost-Latency) 최적화 설계**라는 점을 다시 한번 확인했습니다.
