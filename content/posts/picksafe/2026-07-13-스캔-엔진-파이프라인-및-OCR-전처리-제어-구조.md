모바일 환경에서 카메라 기반 서비스는 유저에게 뛰어난 편의성을 제공하지만, 개발팀에게는 '제어 불가능한 야생의 데이터'라는 거대한 도전을 안겨줍니다. 

실제 소비자가 화장품 성분표를 촬영하는 환경은 정갈하게 스캔된 문서와 거리가 깁니다. 곡면 용기의 왜곡, 조명 반사, 초점 흔들림, 저해상도 폰트까지 온갖 실환경 노이즈가 섞여 들어오기 때문입니다.

이번 글에서는 **'PickSafe'** 서비스의 스캔 파이프라인을 구축하며 마주했던 기술적 병목(네트워크 지연, OCR 인식 오류, 텍스트 분할 실패)을 어떤 아키텍처적 트레이드오프(Trade-off)를 거쳐 해결했는지, 그리고 이를 통해 얻은 엔지니어링 교훈을 공유합니다.

---

## 1. 문제 정의: 야생의 데이터와 물리적 한계

초기 단순 텍스트 추출 방식에서는 세 가지 치명적인 문제가 발견되었습니다.

### 1) 대용량 원본 이미지로 인한 네트워크 병목
최신 스마트폰의 원본 사진 해상도는 4K를 훌륭히 넘어섭니다. 평균 5MB~10MB에 달하는 원본 이미지를 그대로 백엔드로 전송하면서 **네트워크 지연 시간(Latency)이 5초 이상 발생**했고, 모바일 3G/LTE 환경에서는 업로드 타임아웃과 API 비용 급증이라는 상용 서비스로서의 결함으로 이어졌습니다.

### 2) 문맥 파괴 및 텍스트 뭉개짐 (Segmentation Failure)
성분표 텍스트 간 쉼표(`,`)나 점(`.`)이 반사광이나 저해상도로 인해 훼손되면, OCR 엔진은 `정제수글리세린`처럼 복수의 성분을 단일 텍스트로 인식했습니다. 이로 인해 데이터베이스 내 표준 성분명과의 매칭 실패율이 치솟았습니다.

### 3) 표기 변형과 도메인 특수성
성분명 뒤에 붙는 부가 설명(예: `글리세린(식물성)`, `향료(리모넨 함유)`)이나 법적/통상 명칭과 표준 INCI 영문명의 혼용(예: `디메치콘` vs `다이메티콘`)은 단순 텍스트 검색만으로는 해결할 수 없는 정교한 정규화를 요구했습니다.

## 2. 해결 방안 및 기술적 설계 (Architecture & Trade-offs)

개발팀은 문제 해결을 위해 **Client-side 전처리 ➔ Vision LLM 백엔드 파이프라인 ➔ 결정론적(Deterministic) 정규화 엔진**으로 이어지는 3단계 파이프라인을 설계했습니다.

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Client-Side 이미지 전처리 (Canvas API)                   │
│    - 인메모리 리사이징 (Max 1200px) & Quality 85% JPEG 압축     │
│    - 결과: 네트워크 대역폭 90% 절감 (5MB ➔ 300KB)            │
└─────────────────────────────────────────────────────────────┘
                              │ Dynamic Multipart Payload
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. Backend Scan Pipeline (Vision API + JSON Prompt)         │
│    - 비전 기반 한글/영문 성분 영역 정밀 추론 및 Context 파악 │
│    - JSON Schema 강제를 통한 구조화된 파싱 (Structured Output) │
└─────────────────────────────────────────────────────────────┘
                              │ Structured Array
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. Normalization & Matching Engine                          │
│    - 괄호/특수문자 제거 정규식 알고리즘                         │
│    - INCI 표준 명칭 및 식약처 26대 공인 알레르기/기피성분 매칭 │
└─────────────────────────────────────────────────────────────┘
```

### [Trade-off 1] 서버 측 이미지 처리 vs 클라이언트 엣지 압축

* **고민**: 서버(Node.js/Python)에서 OpenCV나 Sharp 등의 라이브러리로 이미지를 리사이징하면 일관된 품질 제어가 가능하지만, **서버로 이미지를 보내는 과정 자체의 네트워크 지연**은 해결할 수 없었습니다.
* **선택**: **클라이언트 브라우저 단에서 Canvas API를 활용한 사전 압축** 방식을 선택했습니다.
* **구현 방안**: 
  * 이미지의 최대 해상도를 1200px로 제한하고 JPEG Quality 85%로 인메모리 압축을 진행했습니다. 
  * OCR 엔진이 문자 픽셀의 에지(Edge)를 식별할 수 있는 최소한의 가시성을 유지하면서, 업로드 용량을 **5MB에서 300KB 수준으로 90% 이상 절감**시켰습니다.

### [Trade-off 2] 전통적 OCR(Tesseract) vs Vision LLM 파이프라인

* **고민**: 전통적인 OCR은 비용이 저렴하지만 곡면 텍스트나 노이즈가 낀 성분표에서 텍스트 뭉개짐 현상을 극복하기 힘들었습니다.
* **선택**: 대형 비전 모델(Vision LLM) 기반의 파이프라인을 채택하고 **JSON 정형화 프롬프트 엔지니어링**을 도입했습니다.
* **구현 방안**: 
  * 단순 텍스트 출력이 아닌, 성분명을 배열 형태(`string[]`)로 반환하도록 Schema 규칙을 명시적으로 제어했습니다. 
  * 모델이 문맥 파악을 통해 누락된 쉼표 위치를 추론하도록 유도함으로써 복합 성분 분리 실패율을 극적으로 낮췄습니다.

### [Trade-off 3] 퍼지 매칭(Fuzzy Matching) vs 결정론적 정규화 규칙 Engine

* **고민**: 유사도 기반의 퍼지 매칭은 철자가 조금 틀린 텍스트도 잡아내지만, 화학 성분명 특성상 단 한 글자 차이로 완전히 다른 성분(알레르기 유발 물질 유무 등)으로 변질될 위험이 있었습니다.
* **선택**: 100% 예측 가능한 **정규식 기반 괄호/특수문자 분리 파이프라인 + 도메인 사전 데이터베이스 1:1 매칭** 방식을 결합했습니다.
* **구현 방안**: 
  * `글리세린(식물성)`과 같은 부가 표기는 정규식을 통해 핵심 성분(`글리세린`)과 수식어(`식물성`)로 안전하게 분리 추출했습니다. 
  * 이후 한글 음차 및 INCI 영문 표준명 데이터베이스와 매칭하여, 식약처 공인 26대 알레르기 물질 및 사용자 지정 기피 성분을 정확하게 플래깅하도록 보장했습니다.

## 3. 결과 및 엔지니어링 성과

이러한 파이프라인 구조 변경으로 구축한 서비스는 모바일 환경에서 괄목할 만한 성능 향상을 기록했습니다.

1. **처리 속도(Latency) 대폭 개선**
   * 클라이언트 단 사전 압축 도입을 통해 업로드 데이터 크기가 **90% 절감 (5MB ➔ 300KB)** 되었습니다.
   * 그 결과 전체 모바일 스캔 분석 응답 시간이 기존 대비 **5초 이상 단축되어 평균 1.5초 이내**로 안정화되었습니다.

2. **인식 정확도(Accuracy) 향상**
   * Vision LLM의 Context 추론 및 결정론적 정규화 파이프라인을 거치면서, 뭉개진 성분표 인식 정확도가 기존 대비 **35% 향상**되었습니다.

3. **인프라 비용 효율화**
   * 무분별한 고화질 원본 이미지가 백엔드로 유입되는 것을 차단하여 네트워크 대역폭 비용과 백엔드 메모리 부하를 동시에 줄였습니다.

## 4. Takeaway: 시니어 개발자로서 얻은 인사이트

1. **"최적화의 위치가 성능을 결정한다"**
   * 백엔드 서버를 아무리 증설해도 클라이언트에서 전송하는 데이터의 크기가 크면 네트워크 계층의 병목을 피할 수 없습니다. 엣지(클라이언트 브라우저) 자원을 적극적으로 활용하여 컴퓨팅과 대역폭 부담을 분산시키는 것이 전체 시스템 성능 향상의 핵심이었습니다.

2. **"확률론적 모델과 결정론적 검증의 결합"**
   * LLM/Vision 모델과 같은 인공지능 기술은 노이즈 제거와 문맥 파악(확률론적 처리)에 매우 훌륭한 도구입니다. 하지만 사용자 건강에 영향을 미치는 알레르기 성분 판정은 반드시 예측 가능하고 검증 가능한 규칙(결정론적 처리)을 통해 필터링해야 시스템 전체의 신뢰성을 확보할 수 있음을 배웠습니다.
