안녕하세요. PickSafe 백엔드/프론트엔드 엔지니어링 팀입니다. 

서비스를 글로벌 클라우드 인프라(Render, Neon DB 등)에 배포하고 운영하다 보면, 한 번쯤 마주치게 되는 고질적인 문제가 있습니다. 바로 **'타임존(TimeZone) 불일치'** 문제입니다. 

이번 포스팅에서는 서버 기본 설정인 UTC와 비즈니스 요구사항인 KST(한국 표준시) 사이의 간극을 메우기 위해 어떤 기술적 고민을 거쳤고, 어떻게 시스템 전반의 시간 표준화와 어드민 UI 일원화를 달성했는지 그 과정을 공유해 드립니다.

---

## 1. Problem: 마이페이지에 '어제 스캔'으로 뜨던 이유 (문제 정의)

초기 아키텍처를 구축할 당시, 클라우드 DB 및 호스팅 서버의 기본 시스템 타임존은 **UTC(협정 세계시, +00:00)**로 설정되어 있었습니다. 이로 인해 서비스 운영 중 다음과 같은 치명적인 UX 저하 및 운영 이슈가 발생했습니다.

1. **사용자 경험(UX) 혼선**: 사용자가 오후 2시(14:00 KST)에 정상적으로 서비스를 이용했음에도, 데이터베이스에는 05:00 UTC로 적재되었습니다. 이를 그대로 노출하거나 단순 변환할 때 날짜 경계선에서 오차가 발생해 마이페이지와 로그에 "어제 스캔함"과 같은 혼란스러운 문구가 노출되었습니다.
2. **배치 스케줄러 실행 시점 불일치**: 핵심 비즈니스 로직 중 하나인 '식약처 성분 일일 수집 배치'가 KST 자정이 아닌 **UTC 자정(한국 시간 오전 9시)**에 구동되었습니다. 트래픽이 집중되는 주간 시간에 대량 수집 배치가 돌면서 불필요한 서버 부하를 유발했습니다.
3. **어드민 파편화**: 어드민 페이지 내 각 모듈(대시보드, 성분 수집, 방문자 통계 등)마다 시간 포맷(ISO, YYYY-MM-DD, 상대 시간 등)과 아이콘 스타일이 제각각이어서 관리자의 피로도가 높았습니다.

---

## 2. Trade-off & Architecture: 왜 이렇게 해결했는가?

타임존 문제를 해결하기 위해 크게 두 가지 대안을 저울질했습니다.

* **대안 A: DB 자체의 타임존을 KST(+09:00)로 변경**
  * *장점*: 애플리케이션 코드단에서 별도의 변환 로직을 신경 쓸 필요가 줄어듦.
  * *단점*: 글로벌 클라우드 Managed DB 서비스들의 기본 권장 사항은 UTC이며, 향후 글로벌 확장이나 타임존 변경 시 DB 레벨의 마이그레이션 리스크가 큼.
* **대안 B: DB는 UTC 표준 유지 + 애플리케이션/UI 단에서 KST 일괄 변환 (선택)**
  * *장점*: DB의 무결성(UTC 표준 저장)을 지키면서, 비즈니스 로직과 클라이언트 응답 단에서 명확하게 KST(`+09:00`)를 보장할 수 있음. 인프라 종속성을 낮출 수 있음.
  * *단점*: 백엔드 직렬화 과정과 프론트엔드 렌더링 시점에 휴먼 에러가 발생하지 않도록 엄격한 컨벤션과 헬퍼 함수 강제가 필요함.

우리는 시스템의 확장성과 데이터 무결성을 위해 **대안 B**를 채택했습니다.

## 3. Implementation: 기술적 구현 방식

### 3.1. 백엔드 KST 타임존 변환 헬퍼 표준화
FastAPI 기반의 백엔드 전역에서 타임존 처리를 일원화하기 위해, 고정된 KST 오프셋 상수를 도입했습니다.

```python
from datetime import datetime, timezone, timedelta

# KST 타임존 상수 정의 (UTC +9)
_KST = timezone(timedelta(hours=9))
```

* **DB 적재**: 데이터 생성 시점은 `func.now()` 또는 `server_default=func.now()`를 활용해 UTC 기준으로 안전하게 적재합니다.
* **API 응답**: 클라이언트에 데이터를 내려주거나 로그를 출력할 때, `.astimezone(_KST).strftime('%Y-%m-%d %H:%M:%S')` 패턴을 강제하여 항상 일관된 한국 표준시 문자열을 반환하도록 했습니다. 이를 통해 배치 스케줄러 역시 KST 자정 기준에 맞춰 정확하게 동작하도록 정합성을 확보했습니다.

### 3.2. 어드민 디자인 시스템 및 시간/UI 일원화
백엔드의 타임존 표준화와 더불어, 내부 어드민의 파편화된 UI를 대폭 리팩토링했습니다.

* **직관적인 상대 시간 포맷**: "오늘 14:30" 또는 "08.28 14:30"과 같이 관리자가 직관적으로 인지할 수 있는 KST 기반 상대/절대 혼합 시간 포맷을 프론트엔드에 적용했습니다.
* **컴포넌트 및 아이콘 시스템 통일**: 대시보드, 성분 수집, 번역 관리, 방문자 통계, 1:1 문의 등 산재해 있던 관리 모듈의 아이콘 세트와 카드 컴포넌트를 디자인 시스템 기준으로 일원화했습니다. 또한 CAS 번호 자동 보강 작업 내역 및 오류 관리 목록 테이블의 UI를 정돈하여 운영 효율성을 극대화했습니다.

---

## 4. Takeaway (엔지니어링 교훈)

1. **시간 데이터는 '저장'과 '표현'을 분리하라**: DB는 언제나 UTC라는 전역 표준으로 안전하게 지키고, 사용자에게 보여지는 시점(Presentation Layer)에서만 명확하게 타임존을 변환하는 원칙이 대규모 서비스 확장 관점에서 훨씬 유리하다는 것을 다시 한번 확인했습니다.
2. **사소한 UX 파편화가 운영 생산성을 좌우한다**: 백엔드 로직 수정뿐만 아니라 어드민 UI의 시간 포맷과 컴포넌트를 일원화한 작업은, 관리자의 인지 부하를 줄이고 장애 대응 속도를 높이는 데 직접적으로 기여했습니다.

PickSafe 팀은 앞으로도 개발자 경험(DX)과 사용자 경험(UX) 모두를 놓치지 않는 단단한 아키텍처를 만들어 나갑니다. 감사합니다.
