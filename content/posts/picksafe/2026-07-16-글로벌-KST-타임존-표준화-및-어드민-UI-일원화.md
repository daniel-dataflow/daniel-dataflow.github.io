서비스가 글로벌 클라우드 인프라 위에서 성장함에 따라, 전 세계 어디서나 직관적이고 일관된 사용자 경험(UX)을 제공하는 것은 핵심 과제 중 하나입니다. 이번 포스팅에서는 **클라우드 기본 설정인 UTC와 비즈니스 요구사항인 KST(한국 표준시) 사이의 간극을 어떻게 극복했는지**, 그리고 파편화된 어드민 UI를 어떻게 일원화했는지에 대한 기술적 의사결정 과정을 공유하고자 합니다.

---

## 1. Problem: 글로벌 클라우드 환경에서의 '시간 왜곡' 현상

우리는 클라우드 호스팅 서비스와 매니지드 데이터베이스(Neon DB)를 활용해 인프라를 구축했습니다. 초기 구축 단계에서 간과하기 쉬운 점 중 하나는 서버 시스템의 기본 타임존이 **UTC(+00:00)**로 고정되어 있다는 점입니다.

이로 인해 서비스 운영 전반에 걸쳐 다음과 같은 치명적인 문제들이 발생했습니다.

1. **사용자 경험(UX) 저하**: 사용자가 KST 기준 오후 2시에 서비스를 이용했음에도, 마이페이지와 시스템 로그에는 UTC 기준인 오전 5시로 기록되었습니다. 이로 인해 "어제 날짜로 스캔 기록이 남거나", 사용자가 시간대를 혼동하는 현상이 빈번했습니다.
2. **배치 스케줄러의 논리적 오류**: 식약처 성분 데이터를 일괄 수집하는 배치 스케줄러가 KST 자정이 아닌, **UTC 기준 자정(한국 시간 오전 9시)**에 동작하고 있었습니다. 트래픽이 몰리는 피크 타임에 데이터 수집 부하가 겹치는 비효율이 발생했습니다.
3. **어드민 인터페이스의 파편화**: 어드민 페이지마다 날짜 표기 방식(ISO 8601, 커스텀 문자열, 상대 시간 등)과 아이콘 세트가 제각각이어서 관리자의 피로도가 높았습니다.

---

## 2. Trade-off & Solution: 왜 애플리케이션 계층에서 KST 변환을 강제했는가?

시간 데이터를 다룰 때 아키텍트가 마주하는 고전적인 딜레마가 있습니다. *"DB 저장 시점부터 로컬 타임존(KST)으로 저장할 것인가, 아니면 UTC로 저장하고 응답 시점에 변환할 것인가?"*

### 대안 비교
* **A안: DB 자체의 타임존을 KST로 설정**
  * *장점*: 쿼리 작성 시 별도의 변환 로직이 불필요함.
  * *단점*: 글로벌 확장성 저하, 추후 타임존 변경 시 마이그레이션 지옥, 클라우드 DB 매니지드 서비스의 기본 정책과 충돌 가능성.
* **B안: DB는 UTC(Single Source of Truth)로 유지하고, 애플리케이션 계층(API/ORM) 및 프론트엔드에서 KST 변환 표준화**
  * *장점*: 인프라 독립성 유지, 글로벌 타임존 확장성 확보, 데이터 정합성 보장.
  * *단점*: 개발 단계에서 변환 로직을 누락할 휴먼 에러 가능성 존재.

### 최종 선택: B안 + 전역 헬퍼 표준화
우리는 인프라의 유연성을 포기할 수 없었기에 **"DB는 UTC 저장, 응답은 KST 강제"** 원칙을 세웠습니다. 휴먼 에러를 방지하기 위해 백엔드 전역에서 공통으로 사용하는 KST 타임존 상수를 정의하고 직렬화 단계를 일원화했습니다.

```python
# 백엔드 전역 KST 타임존 헬퍼 표준화 (개념 코드)
from datetime import datetime, timezone, timedelta

_KST = timezone(timedelta(hours=9))

def to_kst_format(utc_dt: datetime) -> str:
    if not utc_dt:
        return ""
    # UTC로 저장된 시점에 tzinfo를 부여하고 KST로 변환
    return utc_dt.replace(tzinfo=timezone.utc).astimezone(_KST).strftime('%Y-%m-%d %H:%M:%S')
```

- **DB 적재**: `func.now()`를 활용해 순수한 UTC 기준 시각을 안전하게 적재합니다.
- **API 응답**: 클라이언트에게 데이터를 전달하기 직전, 표준화된 헬퍼를 거쳐 KST 기준의 직관적인 문자열 혹은 상대 시간(`오늘 14:30`, `08.28 14:30`)으로 변환합니다.

### 어드민 UI 디자인 시스템 및 컴포넌트 일원화
백엔드 타임존 정합성 확보와 동시에, 어드민 대시보드(성분 수집, 번역 관리, 방문자 통계, 1:1 문의 등)의 UI 컴포넌트를 리팩토링했습니다. 
* 파편화되어 있던 아이콘 세트를 통합 디자인 시스템 기준으로 교체
* CAS 번호 자동 보강 및 오류 관리 목록 테이블의 레이아웃을 통일하여 관리자의 가독성과 업무 처리 속도 극대화

## 3. Takeaway: 엔지니어링 교훈

1. **타임존은 초기 설계가 전부다**: 사소해 보이는 타임존 설정 문제를 방치하면 나중에 데이터 디버깅 시 엄청난 인력 낭비로 이어집니다. 인프라는 UTC 표준을 따르되, 비즈니스 로직과 UI는 타겟 유저(KST)에 철저히 맞추는 구조적 분리가 정답입니다.
2. **컨벤션은 코드로 강제해야 한다**: "개발자가 알아서 변환해서 쓰겠지"라는 믿음 대신, 공통 헬퍼와 직렬화 파이프라인을 구축해 개발자가 고민하지 않고도 올바른 타임존 데이터를 다룰 수 있는 환경을 만드는 것이 시니어의 역할입니다.

이번 개선을 통해 사용자 및 관리자 화면 전반에서 **KST 시간 표기 100% 일치**를 달성했으며, 배치 스케줄러의 부하 분산까지 성공적으로 마무리할 수 있었습니다. 

앞으로도 PickSafe는 견고한 아키텍처를 바탕으로 안정적인 서비스를 제공하겠습니다. 감사합니다.
