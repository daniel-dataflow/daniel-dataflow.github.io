화장품 성분 분석 플랫폼에서 **‘검색 매칭률’**은 서비스의 신뢰도와 직결되는 핵심 지표입니다. 사용자가 화장품 라벨을 촬영하거나 검색했을 때 성분이 `❓ 미확인`으로 표시되는 순간, 사용자 경험(UX)은 급격히 저하됩니다.

최근 식약처 공인 화장품 성분 마스터 데이터를 고도화하는 과정에서 **"단일 화학 물질 중심의 엄격한 데이터 검증 규칙이 실제 천연/식품 원료 데이터를 탈락시키는 구조적 문제"**를 마주했습니다. 

이번 글에서는 엄격한 데이터 무결성을 훼손하지 않으면서도 서비스 매칭률을 99.9%까지 끌어올린 **이중 관리(Dual Management) 아키텍처**와 자동화 파이프라인 구축 과정을 공유합니다.

---

## 1. Problem: 엄격한 데이터 검증이 만든 역설

### 현상
식약처 공인 화장품 성분 2만여 건을 수집·적재하는 과정에서 약 1,000건의 성분이 오류 검토 큐로 격리되는 현상이 발생했습니다. 탈락된 성분들은 `가공소금`(바디스크럽 원료), `누룩추출물`(발효 에센스 원료), `온천수` 등 실제 시판 화장품에 널리 쓰이는 천연 복합물 및 식품 원료들이었습니다.

```
[사용자 시나리오 문제점]
인기 발효 에센스 스캔 ──> '누룩추출물' 식별 불가 (❓ 미확인) ──> 서비스 신뢰도 하락
```

### 원인 분석
기존 수집 엔진은 화학 물질의 고유 식별자인 **CAS 등록번호(Chemical Abstracts Service Registry Number)**의 유효성(`숫자-숫자-숫자` 정규식)을 필수 조건으로 강제하고 있었습니다. 

그러나 천연 추출물이나 발효물은 수백 가지 유기 화합물이 섞인 **복합 혼합물**이므로, 국제적으로도 단일 CAS 번호가 존재하지 않거나 복수의 번호를 갖는 경우가 흔합니다. 시스템의 ‘엄격한 스키마 검증’이 현실 세계의 ‘도메인 특수성’을 수용하지 못해 정상 데이터를 유실시키고 있었던 것입니다.

---

## 2. Technical Decisions: 어떤 아키텍처를 선택할 것인가?

우리는 데이터 완전성과 실시간 서비스 가용성 사이에서 세 가지 선택지를 검토했습니다.

| 대안 | 장점 | 단점 및 리스크 |
| :--- | :--- | :--- |
| **Option A: 글로벌 스키마 제약 완화**<br>(CAS 번호를 완전히 Optional 처리) | 즉각적인 전수 편입 가능 | 향후 화학물질 기반 유해성 분석 및 규제 DB 매핑 시 데이터 결측으로 인한 2차 품질 저하 발생 |
| **Option B: 전수 수동 보강 후 릴리즈**<br>(관리자가 1,000건을 모두 조사한 뒤 배포) | 완벽한 데이터 무결성 | 리소스 병목으로 인한 릴리즈 지연. 애초에 CAS가 없는 원료의 경우 무기한 보류 |
| **Option C: 이중 관리 파이프라인 (선택)**<br>(서비스 즉시 편입 + 비동기 메타 보강 큐) | **사용자 검색 100% 매칭 달성** & **점진적·자동화된 데이터 보강 가능** | 상태 머신 관리 및 보강 파이프라인 추가 개발 공수 발생 |

우리는 **Option C**를 채택했습니다. 
**"사용자 서빙(Serving)"**과 **"메타데이터 보강(Enrichment)"**의 라이프사이클을 디커플링(Decoupling)하여 최종적 일관성(Eventual Consistency)을 확보하는 전략입니다.

---

## 3. Solution: 이중 관리(Dual Management) 아키텍처

```
[수집 파이프라인]
 식약처 공인 성분 인입
       │
       ▼
 [CAS 보유 여부 검증]
  ├── (CAS 존재) ──> [마스터 DB 즉시 적재]
  └── (CAS 부재) ──> [마스터 DB 즉시 적재 (cas_no = NULL, 표준 식별자 부여)]
                           │
                           └──> 📌 [CAS 보강 전용 큐 (Status: Pending)]
                                       │
                                       ▼ (자동/수동 하이브리드 파이프라인)
                                 🤖 PubChem API 자동 탐색
                                 🔍 공인 사전(KCIA/CosIng/K-REACH) 교차 검증
                                       │
                                       ▼
                                [CAS 보강 완료 (Status: Completed)]
```

### 1) 서비스 레벨: 제로-블로킹(Zero-Blocking) 마스터 편입
- 공인 한글 성분명이 존재하는 경우, CAS 번호가 없더라도 표준 대체 식별자(`N/A-[성분명]`)를 부여하여 즉시 마스터 DB에 적재합니다.
- 프로덕션 서빙 캐시 레이어를 즉시 갱신하여, 배포 즉시 천연/발효 화장품 스캔 시 매칭률 99.9%를 확보했습니다.

### 2) 관리 레벨: 점진적 메타 보강(Enrichment) 체계
- 성분 엔티티에 `enrichment_status` (`none` | `pending` | `completed`) 상태 머신을 도입했습니다.
- CAS 결측 데이터는 적재와 동시에 `pending` 상태로 큐에 격리되어, 운영팀이 2만여 건 전체를 탐색할 필요 없이 보강 대상만 집중 관리할 수 있도록 설계했습니다.

### 3) 하이브리드 자동 보강 엔진 구축
운영 리소스를 최소화하기 위해 다단계 보강 파이프라인을 구축했습니다.

1. **외부 화학 데이터베이스(PubChem PUG-REST API) 비동기 연동**:
   - 성분명(영문/국문) 기반으로 NIH PubChem 오픈 API를 비동기 질의하여 가장 신뢰도 높은 CAS 번호를 자동 매핑 및 추천합니다.
   - 백그라운드 배치 프로세스를 통해 수천 건의 `pending` 큐 데이터를 단 한 번의 클릭으로 일괄 탐색합니다.
2. **글로벌 3대 공인 사전 원클릭 교차 검증**:
   - 자동 매핑이 모호한 복합 추출물은 관리자가 단일 뷰에서 **대한화장품협회(KCIA)**, **유럽연합 화장품 성분 DB(CosIng)**, **화학물질정보시스템(K-REACH)** 링크로 즉시 교차 검증하고 수동 확정할 수 있는 UI 환경을 제공했습니다.

## 4. Engineering Takeaways

### 1. 실세계 도메인 데이터는 이상적인 스키마에 맞춰주지 않는다
엔지니어링 관점에서 모든 레코드에 고유한 정규식 키(CAS Number)가 존재하는 것이 이상적입니다. 하지만 천연물/혼합물이라는 도메인 현실은 이를 허용하지 않았습니다. **"데이터 검증 룰은 도메인의 현실을 반영해야 하며, 단일 필드의 결측이 전체 파이프라인의 블로커가 되어서는 안 된다"**는 교훈을 얻었습니다.

### 2. 읽기 모델과 보강 모델의 분리 (Decoupling)
데이터 수집과 정제 작업을 하나의 트랜잭션으로 묶지 않고, **'실시간 사용자 서빙 파이프라인'**과 **'비동기 메타데이터 강화 파이프라인'**으로 분리함으로써 시스템의 확장성과 사용자 만족도를 동시에 잡을 수 있었습니다.

### 3. 결과 및 비즈니스 임팩트
* **국내 화장품 성분 스캔 매칭률 99.9% 달성**: "가공소금", "누룩추출물" 등 천연/식품 원료 스캔 시 `❓ 미확인` 오분류율 제로(0%) 달성
* **운영 생산성 향상**: 외부 오픈 API 자동 탐색 배치를 통해 수작업 검토 리소스의 약 80% 이상을 절감
