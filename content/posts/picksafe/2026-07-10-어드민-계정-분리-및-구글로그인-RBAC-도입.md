안녕하세요, PickSafe 개발팀입니다. 

서비스가 성장함에 따라 사용자 관리뿐만 아니라 운영 효율화를 위한 백오피스(어드민) 시스템의 중요성도 함께 커지기 마련입니다. 최근 PickSafe는 기존에 혼용되던 사용자/관리자 권한 체계를 전면 개편하고, **구글 소셜 로그인 단일화, 테이블 격리, 그리고 페이지 단위 역할 기반 접근 제어(RBAC)**를 도입했습니다.

이번 포스팅에서는 어드민 시스템을 왜, 어떤 방식으로 설계하고 개선했는지 기술적 고민과 트레이드오프(Trade-off), 그리고 실무에서 얻은 인사이트를 공유하고자 합니다.

---

## 1. 기존 시스템의 문제점 (Problem)

초기 프로토타입 단계에서는 빠른 개발을 위해 일반 사용자 테이블(`users`) 내에 `role='admin'` 컬럼을 두거나, 특정 이메일을 관리자로 지정하는 방식을 사용했습니다. 하지만 서비스 규모가 확장되면서 다음과 같은 치명적인 한계와 보안 리스크가 드러났습니다.

1. **세션 혼용 및 쿠키 충돌**
   * 일반 로그인과 어드민 로그인이 동일한 `access_token` 쿠키를 공유했습니다. 관리자 권한으로 로그인한 상태에서 일반 사용자 페이지로 이동할 경우 상태가 꼬이거나, 반대로 세션 관리가 엄격하지 못해 보안적 결함이 발생할 수 있었습니다.
2. **보안 취약성 (하드코딩된 패스워드)**
   * 로컬 DB 시딩 과정에서 추측하기 쉬운 고정 패스워드(`admin7777!`) 형태의 계정이 생성되어 있어, 잠재적인 침입 경로를 제공하고 있었습니다.
3. **세부 권한 제어(RBAC)의 부재**
   * 콘텐츠 담당자, 고객 지원 담당자 등 각 역할별로 필요한 대시보드 페이지만 노출해야 했으나, 모든 어드민이 전체 시스템의 원장 정보와 모니터링 수치에 무제한 접근할 수 있는 구조였습니다.

---

## 2. 기술적 고민과 아키텍처 대안 (Trade-offs)

이 문제를 해결하기 위해 백엔드(FastAPI)와 프론트엔드 전반에 걸쳐 대대적인 아키텍처 리팩토링을 단행했습니다.

### ① 데이터베이스 및 세션 쿠키 물리적 격리
* **대안 A:** 기존 `users` 테이블에 플래그를 추가하고 하나의 토큰으로 관리
  * *장점:* 구현이 단순함.
  * *단점:* 일반 유저와 어드민의 스키마 요구사항(소셜 연동 방식, 상태 값 등)이 다르고, 세션 오염 문제를 근본적으로 해결할 수 없음.
* **최종 선택 (대안 B): `admins` 테이블 및 `admin_access_token` 쿠키 분리**
  * 일반 사용자는 기존 `access_token`을 유지하고, 관리자는 전용 `admin_access_token` 쿠키에 관리자 식별자(UUID)를 담아 전송하도록 브라우저 세션 수준에서 완전히 격리했습니다. 이로써 두 세션이 독립적으로 공존할 수 있게 되었습니다.

### ② 패스워드 로그인 폐지 및 구글 OAuth 단일화
* 자체 패스워드 로그인 폼을 완전히 제거하고, **구글 소셜 OAuth 로그인**으로 신원 증명을 일원화했습니다.
* 단, 로컬 개발 환경의 편의를 위해 `.env` 기반의 `SUPER_ADMIN` 정보를 활용한 **Mock 간이 로그인**을 병행 도입했습니다. 단, 운영 환경(`settings.ENV == "prod"`)에서는 해당 엔드포인트 진입 시 즉각 `403 Forbidden`을 반환하도록 이중 안전장치를 두었습니다.
* 또한, 구글 로그인 시 타 계정으로의 전환이 원활하도록 인증 요청 파라미터에 `prompt=select_account` 옵션을 추가해 UX 마찰을 줄였습니다.

### ③ 유연한 RBAC (Role-Based Access Control) 설계
* 하드코딩된 권한 체크 대신, 파이썬 코드 상에 `ADMIN_TABS` 상수를 정의하고, 최고관리자(`super_admin`)가 어드민 관리 화면에서 각 관리자별로 허용된 탭 목록을 체크하여 매핑할 수 있도록 구현했습니다.
* 백엔드 라우터 API 레벨에서는 데코레이터 의존성(`verify_admin("tab_id")`)을 통해 각 요청마다 접근 권한을 엄격히 검증합니다.

## 3. 실무 고도화 및 세부 엔지니어링 포인트

아키텍처 설계 외에도 실제 서비스를 운영하며 마주할 수 있는 디테일한 부분들을 함께 개선했습니다.

* **HttpOnly 쿠키 기반 로그아웃:** 자바스크립트에서 접근할 수 없는 보안성을 고려하여, 서버 측 `GET /admin/logout` 엔드포인트를 통해 `delete_cookie`를 수행함으로써 세션 잔존 문제를 깔끔하게 해결했습니다.
* **어드민 세션 수명 차별화:** 일반 구글 로그인 어드민 세션은 보안 강화를 위해 **2시간**의 만료 규격(`max_age=7200`)을 적용한 반면, 로컬 테스트용 Mock 로그인은 개발 편의를 위해 만료 제약 없는 장기 세션을 부여하는 이중 정책을 채택했습니다.
* **모바일 UX 및 이미지 압축 최적화:** 어드민 대시보드 내 모바일 기기 활용 시 강제 카메라 촬영(`capture="environment"`) 제약을 풀고 갤러리 선택을 허용했으며, 업로드 전 HTML5 Canvas를 이용해 이미지를 최대 1200px 및 85% 퀄리티로 브라우저 단에서 선제 압축(200~300KB 수준)하여 네트워크 지연을 방지했습니다.

## 4. 파급 효과 및 맺음말 (Takeaways)

이번 어드민 시스템 개편을 통해 얻은 성과는 명확합니다.

1. **보안성 강화:** 하드코딩된 패스워드 기반 계정이 완전히 소멸하고, 구글 OAuth 및 철저한 쿠키 격리를 통해 외부 침입 벡터를 원천 차단했습니다.
2. **운영 효율성 및 유연성:** `ADMIN_TABS` 기반의 동적 RBAC 구조를 도입함으로써, 향후 새로운 백오피스 메뉴가 추가되더라도 UI 체크박스와 백엔드 보안 데코레이터가 유기적으로 연동될 수 있는 확장성을 확보했습니다.

보안과 확장성은 어드민 시스템을 구축할 때 가장 먼저 타협하기 쉬운 영역이지만, 서비스가 성장할수록 발목을 잡는 부채가 되기 쉽습니다. 이번 리팩토링은 PickSafe가 더 안전하고 탄탄한 백오피스 인프라 위에서 비즈니스에 집중할 수 있는 튼튼한 토대가 되었습니다. 

앞으로도 PickSafe 개발팀은 더 나은 아키텍처와 엔지니어링 경험을 공유해 나가겠습니다. 감사합니다!
