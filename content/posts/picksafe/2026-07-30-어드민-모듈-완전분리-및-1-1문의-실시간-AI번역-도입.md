안녕하세요, PickSafe 개발팀입니다. 
서비스의 글로벌 유저가 빠르게 늘어남에 따라, 성분 매칭 제보나 앱 버그 신고 등 **1:1 해외 고객 문의** 또한 폭발적으로 증가했습니다. 

이번 포스팅에서는 언어 장벽으로 인한 응답 지연 문제를 해결하기 위해 **FastAPI 어드민 모듈을 도메인별로 완전히 분리**하고, LLM을 활용한 **실시간 양방향 다국어 AI 번역 엔진**을 도입한 아키텍처적 고민과 의사결정 과정을 공유합니다.

---

## 1. 문제 정의 (Context & Problem)

글로벌 유입 초기, 우리 팀은 운영 효율성 저하라는 두 가지 큰 기술적 병목에 부딪혔습니다.

### ① 휴먼 에러를 유발하는 수동 번역 프로세스
* **현상:** 관리자가 영어, 일본어, 중국어 등 다양한 언어로 된 문의를 처리하기 위해 외부 번역기를 수동으로 오가며 복사/붙여넣기를 반복했습니다.
* **문제점:** 관리자가 작성한 한국어 답변을 다시 고객의 모국어로 번역해 전달하는 과정에서 톤앤매너가 깨지거나 오역이 발생했고, 결과적으로 **평균 응답 시간(Response Time)이 15분 이상**으로 치솟았습니다.

### ② 비대해진 모놀리식 어드민 코드베이스 (`God File` 안티패턴)
* **현상:** 초기 MVP 개발 속도에 집중한 나머지, 인증·유저 관리·문의하기 등 모든 어드민 로직이 단일 파일(`admin.py`)과 거대한 템플릿 구조에 집중되었습니다.
* **문제점:** 단일 파일의 라우터 코드가 비대해지면서 코드의 가독성이 급격히 떨어졌고, 작은 기능 수정에도 사이드 이펙트(Side Effect)를 걱정해야 하는 유지보수 지옥에 빠졌습니다.

---

## 2. 기술적 고민과 아키텍처 대안 (Trade-offs)

문제를 해결하기 위해 크게 **1) 어드민 구조 개선**과 **2) AI 번역 기능 연동**이라는 두 가지 트랙으로 아키텍처 설계를 진행했습니다.

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 어드민 아키텍처 도메인별 완전 모듈 분할                  │
│    - app/routers/admin/ (translations, inquiries, users 등)  │
│    - 프론트엔드 static/js/admin/ 및 templates/admin/ 완전 분리│
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│ 2. 1:1 고객문의 실시간 양방향 다국어 AI 번역 엔진           │
│    - [수신] 외국어 원문 ↔ 한국어 즉시 토글 번역               │
│    - [발신] 한국어 답변 작성 ➔ 고객 언어 자동 감지 및 변환  │
│    - 자주 쓰는 답변 템플릿(Quick Replies 3종) 원클릭 삽입   │
└─────────────────────────────────────────────────────────────┘
```

### 대안 1: 어드민 모듈의 도메인별 분할 (Decoupled Admin Modules)
* **기존 방식:** 단일 `admin.py` 라우터와 템플릿 유지.
* **선택한 방식:** FastAPI의 `APIRouter`를 도메인 단위(`translations.py`, `inquiries.py`, `users.py`, `settings.py` 등)로 세분화하고, 프론트엔드 자산(`static/js/admin/`, `templates/admin/`) 역시 도메인별 디렉토리로 완전 분리했습니다.
* **Trade-off:** 초기 파일 디렉토리 구조 설정과 라우터 등록에 소요되는 세팅 비용이 발생했으나, 특정 도메인 로직 수정 시 다른 도메인에 영향을 주지 않는 **격리성(Isolation)**을 확보하여 장기적인 생산성을 크게 높였습니다.

### 대안 2: LLM 기반 실시간 양방향 번역 파이프라인 구축
* **기존 방식:** 외부 서드파티 번역 API 직접 호출 또는 수동 번역.
* **선택한 방식:** Gemini Pro 기반 번역 서비스를 어드민 대시보드에 직접 임베딩.
  * **수신(Inbound):** 고객이 접수한 원문의 언어를 자동 감지하여, 대시보드 내에서 `🌐 한국어로 번역 보기` 토글 기능 제공.
  * **발신(Outbound):** 관리자가 한국어로 편하게 타이핑한 뒤 `🌐 고객 언어로 답변 변환`을 누르면, 고객 지원에 적합한 정중한 톤앤매너로 자동 변환.
  * **부가 기능:** CS 효율을 높이기 위해 자주 쓰는 답변 템플릿(Quick Replies 3종) 원클릭 삽입 기능 추가.
* **하드코딩 방지:** 다국어 사전 시더 스크립트(`bin/seed_multilingual_db.py`)를 독립화하여, 하드코딩 없이 6개 국어 사전 DB를 유연하게 동기화할 수 있는 파이프라인을 구축했습니다.

## 3. 결과 및 성과 (Results & Takeaways)

이번 아키텍처 리팩토링과 AI 기능 도입을 통해 다음과 같은 정량적/정성적 성과를 거둘 수 있었습니다.

1. **응대 시간 80% 이상 단축:** 
   * 평균 15분이 소요되던 1:1 고객 문의 처리 시간이 **3분 이내**로 대폭 단축되었습니다. 수동 복사/붙여넣기가 사라지면서 운영 리소스가 극적으로 절감되었습니다.
2. **코드 유지보수성 및 확장성 확보:**
   * 비대했던 모놀리스 어드민 코드를 도메인별로 깔끔하게 분리함으로써, 향후 CS 어드민에 새로운 기능(예: 자동 분류, 통계 대시보드 등)을 붙일 때의 기술 부채를 원천 차단했습니다.

### 💡 엔지니어링 교훈 (Takeaways)
> *"빠른 성장에 밀려 방치했던 'God File(비대한 단일 파일)'은 결국 기술 부채가 되어 프로덕트의 발목을 잡습니다. 서비스 확장 국면에서는 비즈니스 로직 추가뿐만 아니라, **모듈을 적시에 도메인별로 분리하고 AI와 같은 최신 기술을 워크플로우에 자연스럽게 녹여내는 아키텍처적 결단**이 개발 생산성과 유저 경험 모두를 지키는 핵심 열쇠임을 다시 한번 깨달았습니다."*
