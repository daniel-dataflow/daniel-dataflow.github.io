### 🔹 \[이주형\] - \[팀원/Data Science\]

💡 **Keep (유지할 것)**

*   **안정적인 브랜치 관리와 파이프라인 통합:** Airflow의 단독 동작 환경을 성공적으로 검증하고, 팀원들의 브랜치 작업물들을 브랜치로 무사히 병합(Merge)하며 협업 및 형상 관리 프로세스를 안정적으로 유지
*   **크롤링 효율성 및 수집력 강화:** 무한 스크롤(Infinite Scroll) 로직을 도입하여 전체 상품 데이터를 끝까지 누락 없이 수집하는 기반을 마련하고, 이미 저장된 파일은 건너뛰는(Skip/이어하기) 기능을 추가해 불필요한 재작업 시간과 리소스 낭비 방지

🔍 **Problem (문제점)**

*   **예상치 못한 노이즈 데이터 유입:** 실제 데이터 파이프라인을 가동하는 과정에서 1KB 크기의 더미(Dummy) 이미지나 비정상적인 파일들이 섞여 들어오면서, 이후 이어지는 모델 추론 단계(YOLO, VLM 등)에서 불필요한 컴퓨팅 자원을 소모하거나 에러를 유발하는 이슈 발생

✨ **Try (시도할 것)**

*   **파이프라인 초기 방어 로직(Defense Logic) 구축:** 비정상적으로 작은 용량의 이미지나 손상된 파일을 파이프라인 앞단에서 즉각 감지하고 필터링(Filtering)하여 후속 작업의 안정성을 보장하는 예외 처리 로직 적용
*   **End-to-End 연동 테스트 및 모니터링 고도화:** 크롤링부터 Spark 분산 처리, 네이버 API, YOLO 객체 인식, VLM 텍스트 추출, 이미지 임베딩, 그리고 최종 ElasticSearch 동기화까지 이어지는 전체 파이프라인 흐름에서 데이터 유실이나 병목이 없는지 각 연결 구간 집중 점검

### 🔹 \[정수아\] - \[팀원/Data Science\]

**💡 Keep (유지할 것)**

*   **검색단 객체탐지 모델 백엔드 연동**
    
    : 프론트엔드에서만 적용되어 있던 YOLO 기반 객체 탐지 결과를 백엔드 임베딩 모델과 연동하여 검색 파이프라인에 반영
    
*   **카테고리 자동 선택 검색 기능 구현**
    
    : 검색 정확도가 낮은 문제를 해결하기 위해, YOLO 객체 탐지 결과를 활용하여 카테고리가 자동 선택되도록 검색 로직 개선
    
*   **텍스트 검색 Rewrite 로직 구현**
    
    : Qwen 모델을 활용하여 텍스트 검색 단계에서 Query Rewrite 적용 후 임베딩을 생성하는 방식으로 검색 품질 개선 노력
    
*   **검색 로직 모델 연동 점검**
    
    : 검색 파이프라인 내 모델 연동 상태 및 동작 흐름 점검, 실제 서비스 환경에서 정상 동작 여부 확인
    

**🔍 Problem (문제점)**

*   **Rewrite 모델 선정 및 적용 범위 결정의 어려움**
    
    : 프로젝트 환경에 적합한 LLM 모델 선정과 Rewrite 적용 케이스 정의 과정에서 시행착오 발생
    
*   **검색 평가 지표 설계의 어려움**
    
    : 검색 서비스 품질을 평가하기 위한 지표 선정 및 평가 방식 설계 과정에서 적절한 기준 정의에 어려움 존재
    

**✨ Try (시도할 것)**

*   **검색 서비스 평가 지표 마련**
    
    : 검색 품질을 정량적 혹은 정성적으로 평가할 수 있는 지표 설계 및 평가 기준 수립
    
*   **프로젝트 마무리 문서 작업과 발표 자료**
